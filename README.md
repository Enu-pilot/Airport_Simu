# SkyPort

PCブラウザで動作する空港デザイン・運営シミュレーションゲーム。

プレイヤーは滑走路・誘導路・駐機場・ターミナル・各種設備を建設し、航空機の発着、旅客・手荷物の流れ、地上支援、航空会社との契約を管理して、空港の処理能力と収益を高める。
施設や道路の配置は見た目だけでなく、航空機・旅客・手荷物の流れに実際に影響する。

> 本ゲームは娯楽目的の簡略化モデルであり、実際の航空管制・航空安全基準への適合を保証するものではない。

## 現在の状態

**Phase 12** — 滑走路を任意の真方位・実長（m）で置ける「自由形」を追加（滑走路ツールのオプション。既定は従来の 8 方向）。実寸の舗装・肩・着陸帯・RESA による判定、
磁気偏角つきの滑走路番号（L/C/R）、平行間隔の警告、交差する滑走路（従属運用）、2D/3D の描画。従来形の舗装は実寸の幅で表示。
設計・参考値は [docs/23](docs/23_runway_design.md)、検証は [docs/26](docs/26_validation_rules.md)、移行・互換性は [docs/27](docs/27_migration_and_compatibility.md)。
参考値はゲーム内の判定であり、実際の安全基準への適合を保証しない。未実装・既知の制限は [docs/10](docs/10_open_issues.md) の M。

**Phase 7〜10** — 具体的な機種・派生型（777-300 と 777-300ER など、メーカー資料で照合した値と出典つき）を航空会社の保有機材・便に割り当て、
機種ごとに座席・手荷物・地上作業・必要な滑走路長・スポットの適合性が変わる。天候・障害（滑走路閉鎖・ゲート故障・車両故障・欠勤・需要急増など）と対応操作。
機種別・航空会社別などの運営分析、ボトルネックの根拠、混雑マップ、シナリオ比較。2D/3D 表示の切り替え（3D の機体は手続き生成）。
プロジェクトの保存・復元（運航中の状態を含む）、機種データの固定と最新カタログとの差分、旧形式の移行。
Phase 1〜6 の建設エディタ、運航、旅客、地上支援・手荷物、運航計画・経営、空港アクセス・拡張はそのまま使える。
ルールは docs/11〜21（下表）。いずれもゲーム用の簡略化モデルで、金額はゲーム内通貨 cr（実在の料金・費用とは無関係）。
未実装の機能・既知の制限は [docs/10](docs/10_open_issues.md) の K（自動最適化は未実装、3D の専用機体モデルはなし など）。

## 使い方

```bash
npm install
npm run dev        # 開発サーバー（http://localhost:5173）
npm run build      # 型チェック + 本番ビルド（dist/）
npm test           # 単体テスト（Vitest）
npm run test:e2e   # ブラウザテスト（Playwright）
npm run lint       # ESLint（レイヤー境界ルールを含む）
```

| 操作 | 内容 |
|------|------|
| 左クリック / ドラッグ | 選択 / 移動（選択ツール）、配置（各建設ツール） |
| 右ドラッグ・中ドラッグ・Space+ドラッグ | パン |
| ホイール | ズーム（カーソル位置を中心） |
| 誘導路・道路 | クリックで頂点追加、ダブルクリック・Enter・右クリックで確定 |
| R / Ctrl+D / Delete | 回転 / 複製 / 削除 |
| Ctrl+Z / Ctrl+Shift+Z・Ctrl+Y | 元に戻す / やり直し |
| 矢印キー | 選択中の施設を1タイル移動（Shift で10） |

上部の「3D表示へ」で 3D ビューに切り替え（ドラッグで回転、右ドラッグでパン、ホイールでズーム。運航は止まらない）。

### 保存・バックアップ

- 作業中の空港・会社はブラウザに自動保存される。
- 上部の「メニュー」から JSON 保存/読み込み、「経営 → プロジェクト・保存」から **保存 / 名前を付けて保存 / 開く / 削除**。運航中に保存すると運航状態も含まれ、開くと一時停止で再開する。
- 保存先はこのブラウザの localStorage（端末・ブラウザごと、約 5 MB まで）。**バックアップや別の端末へは「JSON に書き出し」**、戻すときは「JSON を読み込み」。
  以前の「書き出し」で作ったレイアウトファイルも読み込める。読み込みは検証してから適用し、問題があれば開いている内容は変えない。

運航モード: 機体をクリックで状態・経路・運航履歴を表示 / Space 一時停止 / 1〜5 時間倍率（実時間〜×600）/ 左パネルで滑走路の運用方向・モード変更と便の追加。
1 日のループ（Phase 12B-2）: 0:00 の締めで自動的に一時停止して「1日の振り返り」（収支・定時率と遅延理由・旅客と満足度・障害と対応・前日比・航空会社の評価・明日の見通し）を表示し、「次の日へ」または「建設モードに戻る」で続ける（設定で無効化可）。便別の問題一覧では到着・出発別の原因、実績遅延と評価対象遅延、旅客・手荷物への影響、走行・停止・地上作業・バス待ちを確認でき、便を展開すると機体状態・作業・障害の時系列が表示される。航空会社の評価理由は締め時に使った当日スコアカード・EMA・満足度変化を保存して示し、翌日の計画は別欄に分ける。過去の旧形式レビューで記録がない値は推測しない。「1日スキップ」は残りの 1 日を画面を止めて一気に進める（進捗バー・中止・重大な障害で自動停止。結果は画面で進めた場合と同じ）。締めのたびに自動保存し、日ごとの履歴（直近 7 日＋週ごと最大 8 件、IndexedDB）から「その日の朝」に戻せる。

リモートスポットのバス搭乗・独立ゲート（Phase 12B-3a Part A）: ゲートの「搭乗方式」をバスにし、GSE 基地に「ランプバス」を置くと、リモートスポットごとにバス搭乗の使用・使用しない・接続するバスゲートを設定でき、出発旅客は指定ターミナルで搭乗券を確認してバスでスポットへ、到着旅客は対応する降機口へ運ばれる（運行・不足・故障と救援・費用・分析・アラート・運航表の BUS の札）。計画・旅客生成・実運航は共通の選択規則を使い、運用中で搭乗口と降機口が同じターミナルにあるゲートから最寄りを選ぶ。指定先が利用不能なら別ターミナルへ流さず、検証・運航記録に原因を出す。設定画面は接続先ターミナル・搭乗/降機可否・ランプバスの状態を表示する。ゲートの「接続先ターミナル」で、ターミナルに隣接しない独立ゲートを徒歩の連絡通路でつなげる。運航中はスポット・誘導路を個別に使用停止でき、手動閉鎖と障害・整備の閉鎖理由を独立して管理する。評価用遅延は実績時刻を変えず、記録された外部遅延秒数と折返し余裕を共通計算で反映する。詳細は [docs/29](docs/29_remote_stands_and_bus_boarding.md)。

航空会社別のホームスポット: 運航日ごとに、航空会社が利用したスポット群をホーム候補として記録する。同社の次便・折り返し便は空き、機材適合、閉鎖、経路条件を満たすホームを優先し、足りないときは近接した空きスポットを同社の追加ホームとして登録する。他社が使用中のスポットは既存の占有予約で排他し、他社のホームは未割当の候補より後に選ぶ。閉鎖やサイズ不適合による代替は運航イベントに理由と履歴を記録し、障害時に追加した代替ホームは復旧後も優先して割当の振動を抑える。日付変更でホーム候補をリセットする。データと版の扱いは [docs/32](docs/32_airline_stand_homes.md)。

都市と旅客需要（Phase 12B-3b の一部）: 新規ゲーム設定またはルール設定で地方都市・中核都市・大都市を選ぶと、人口・都心距離・道路/鉄道品質からアクセス所要時間と旅客需要上限を計算し、便計画と日次の都市人口成長に反映する。駅ごとに各停・快速・特急を設定でき、都市鉄道品質に応じて利用可否、時間、運賃、運営費へ反映する。都市設定時は騒音ポイントを日報・住民満足度に反映し、22:00〜06:00の離着陸を計画から除き、遅延便も運航待機させる。騒音は実測dBではなく機種サイズとエンジン数によるゲーム内指標。設定のない既存セーブは従来の需要式・アクセス所要時間・運航ルールのまま。イベントと都市鉄道投資は未実装。

複数ターミナルの旅客処理: 出発旅客は搭乗ゲート、到着旅客は到着ゲートの接続先ターミナルへ割り当てられ、チェックイン・保安検査・搭乗口、到着通路・手荷物受取所・出口を同じターミナル内で利用する。独立ゲートとバスゲートの接続先も反映する。運航計画はチェックイン・保安検査能力をターミナル別に比較し、運航画面のターミナルカードは館内人数・設定能力・平均待ちをターミナル別に表示する。構造上の経路不成立と運航中の到達不能・長時間滞留は集約アラートに表示し、解消履歴を運航画面で確認できる。ターミナル間移動は未実装。旅客動線の検証と能力の前提は [docs/12](docs/12_passenger_rules.md)・[docs/14](docs/14_management_rules.md)・[docs/18](docs/18_analytics.md)。

動線・処理能力の分析: 運航中の常設アラートは旅客動線に加えて、滑走路・誘導路・スポット・ゲート間の構造的不整合も集約する。日次振り返りは終了便の実記録から遅延原因、影響便、記録時刻、走行停止・作業待ち・バス待ちの根拠と対応案を示す。計画画面はスポット内訳・ターミナル別窓口能力を表示する。現行モデルに時間レートや日次スナップショットがない誘導路・プッシュバック・バスの時間能力、施設別ピーク、日次の車両別稼働は数値を推定せず「算出条件不足」とする。航空機の実経路は機体選択時にマップ上で表示される。

ロードマップの現状: 12B-3a Part B まで実装済み。12B-3b は都市需要・成長・駅別列車種別・騒音/夜間制限を一部実装し、イベント・都市鉄道投資は未完了。12B-4 は季節近似の昼夜表現、2D/3D追従、機体詳細案内、プロジェクトに保存される日次運航記録まで実装し、機種固有の操縦席視野・塗装別記録などが未完了。地下レイヤ、Phase 13〜16 は未実装または設計基盤のみで、本書は完了を主張しない。個別項目と依存関係は [docs/09](docs/09_roadmap.md) を参照。

画面構成: 上部の主要ナビゲーションを「建設」「経営」「運行」に分け、ゲーム全体の新規作成・モード/難易度・保存/読み込みは「メニュー」にまとめる。経営画面は運航計画・契約・空港能力・アクセス・財務・分析/履歴・拡張計画など既存パネルを再利用する。運航中に経営や建設確認へ移動してもシミュレーションは止まらず、建設画面は読み取り専用になる。構造編集には運航終了が必要。建設と経営から相互に移動できる。

運航モードの画面（Phase 12B-1）: 左右の常設カード（本日の KPI・滑走路・天候/障害・工事・ターミナル・地上支援・アクセス・航空会社の評価・イベント）、マップ右上の案内板風の運航表（出発/到着の切り替え・折りたたみ・行クリックで機体選択・⋯ から遅延/スポット変更/優先）、左上のアラート（クリックで移動・修理など）、上部から開く各詳細パネル。下部には選択中の機体・施設の詳細。

空港能力ダッシュボード: 経営画面の「空港能力」は運航計画から時間帯別の滑走路・旅客・駐機需要を算出し、チェックイン/保安検査の設定処理能力、運用時間を反映した理論日次値、既存地上支援の同時折り返し上限を表示する。滑走路 30 回/時は計画用の基準値。誘導路、ゲート、プッシュバック、ランプバスの時間レートなど現行モデルで算出できない能力は未算出とする。契約・増便の仮想チェックは複製した会社状態と決定的な計画生成を使い、現行セーブや運航を変更しない。詳細と前提は [docs/33](docs/33_capacity_dashboard.md) を参照。
