# 12. ターミナル・旅客流動仕様（Phase 3 実装）

> ゲーム用の簡略化モデルです。実際の空港の旅客処理基準・保安検査の手順を再現するものではありません。数値は仮の値です。

実装: `src/core/terminal/`（内部モデル・経路探索）、`src/core/sim/passengers.ts`（旅客の計算）。

## 1. ターミナル内部の簡易マップ

- ターミナル（建物）に **階数**（1〜3）を持たせ、各階に **エリア**（矩形）を配置する。エリアはターミナルの敷地内・階数の範囲内に置き、同じ階で重ねない。
- 同じ階で辺を共有するエリア同士がつながる（入口・出口・施設間の接続）。エスカレーター・エレベーターは、上下の階で重なるエリアとつながり、所要時間（既定 30 秒 / 60 秒）がかかる。
- 歩行距離は「中心 → 境界の中点 → 相手の中心」の長さ（1タイル = 25m）、歩行速度 1.3 m/s。

| エリア | 区域 | 主なプロパティ |
|--------|------|---------------|
| 入口 / 出口 | 一般 | — |
| チェックイン | 一般 | カウンター数、1人あたり処理時間（既定 50 秒） |
| 保安検査場 | 出発（一般との境界） | レーン数、1人あたり処理時間（既定 15 秒） |
| 出発ロビー / 待合スペース | 出発 | 座席数 |
| トイレ | 出発（変更可） | 設備数（1グループ 3 分） |
| 到着通路 / 手荷物受取所 | 到着 | ベルト数 |
| 通路・ホール / エスカレーター / エレベーター | 変更可 | 上下移動の所要時間 |

### 区域の規則

- 一般区域 → 出発区域へは **保安検査場に入るときだけ** 移動できる（保安検査を通らずに出発区域へ入れない）。保安検査前の旅客が並んでいる位置は一般区域側とみなし、迂回するときは一般区域へ戻る。
- 到着区域 → 一般区域へは **手荷物受取所から出る / 出口に入る** ときだけ移動できる。出発区域と到着区域は行き来できない。
- ゲートは、隣接するターミナルタイルを含む出発区域のエリア（搭乗口）と到着区域のエリア（降機口）につながる。

建設モードの検証で、入口・出口・チェックイン・保安検査・手荷物受取所の欠如、保安検査場の接続不備、ゲートへ到達できない・到着旅客が出口へ出られない配置を警告する。

## 2. 旅客の単位

- 旅客は **1〜5 人のグループ** 単位で計算する（業務計算）。描画はグループの代表点を表示するだけで、計算には影響しない。
- 便ごとの搭乗人数・乗り遅れ・降機・退出人数は、グループの状態の合計と常に一致させる（テストで毎ティック検査）。

## 3. 出発旅客

| 項目 | 仕様 |
|------|------|
| 旅客数 | 座席数 × 搭乗率（65〜90%、シード付き乱数）。出発予定の3時間前に生成 |
| 空港到着 | 出発予定の 150〜45 分前（三角分布、最頻 90 分前）に入口へ |
| 手荷物 | 1人 50% の確率で預ける |
| 流れ | 入口 → チェックイン（手荷物ありは必須、なしは 30%）→ 保安検査 → トイレ（30%）→ 待合 → 搭乗口 → 搭乗 |
| 施設の選択 | 歩行時間 + 待ち時間の見込みが最小の施設（閉鎖中・窓口 0 は除く） |
| 搭乗開始 | 機体がスポットで地上作業中、到着旅客の降機が完了、かつ出発予定の 20/30/40 分前（S/M/L） |
| 搭乗締切 | 出発予定の 10 分前（搭乗開始から最低 15 分は確保）。締切時に搭乗口の列が残っていれば処理してから締め切る |
| 搭乗 | ゲートごとに1列、1人 3 秒（ボーディングブリッジ）/ 5 秒 |
| 出発への影響 | **航空機は搭乗締切まではプッシュバックしない**（遅れれば遅延理由「搭乗手続き」） |

## 4. 到着旅客

| 項目 | 仕様 |
|------|------|
| 降機 | ブロックイン後、20 人/分（ブリッジ）/ 12 人/分で降機口に現れる |
| 流れ | 降機口（到着通路）→ 手荷物受取所（手荷物ありのみ）→ 出口 → 退出 |
| 手荷物 | 降機口から近い受取所に割り当て、ブロックイン 10〜15 分後から受取可能。ベルト数を超える便は、ベルトが空くまで待つ（1便 20 分占有） |

## 5. 施設の処理能力と待ち行列

- 各施設は窓口数（カウンター・レーン・設備）と1人あたりの処理時間を持つ FIFO の待ち行列。**同時に処理できるのは窓口数のグループまで**（超えた旅客は列で待つ）。
- 処理時間 = 人数 × 1人あたり処理時間 × (0.8〜1.2)。
- エリアの滞在人数が目安（1タイル 40 人）を超えると歩行速度が落ちる（最低 30%）。

## 6. 異常時の扱い

| 状況 | 旅客の状態 | 締切時の記録 |
|------|-----------|-------------|
| 施設が閉鎖・窓口 0 で、同種の別施設に行ける | 迂回して並び直す | — |
| 別施設がない | **施設閉鎖で待機**（30 秒ごとに再確認、再開すれば進む） | 乗り遅れ（施設閉鎖で未処理） |
| ゲートへの経路がない / ゲートに搭乗口がない | **到達不能**（搭乗済みにはしない） | 乗り遅れ（ゲートに到達できず） |
| 締切までにゲートの列に入れない | — | 乗り遅れ（締切に間に合わず） |
| スポットにゲートがない（バスゲートがない空港） | 待合で待機 | 乗り遅れ（ゲートなし） |
| スポットにゲートがない（バスゲートがある空港） | バスゲートで搭乗券を確認 → ランプバスで運ぶ（docs/29） | バスが来ない: 乗り遅れ（ランプバスが来ず） |
| 便が欠航 | 欠航 | — |

## 7. 未実装・簡略化

- 国内線・国際線の区別（出入国審査・税関）は未実装。将来は国際線に「出国審査」「入国審査」「税関」のエリアと、各 1人 30〜60 秒の処理を追加する想定。
- 乗り継ぎ旅客、店舗・満足度は未実装。リモートスポットのバス搭乗は Phase 12B-3a で実装済み（[docs/29](29_remote_stands_and_bus_boarding.md)。バスゲートがない空港は従来どおり）。
- 複数ターミナル: 便の出発旅客は搭乗ゲートの所属ターミナル、到着旅客は到着ゲートの所属ターミナルに割り当てる。チェックイン・保安検査・待合・搭乗口、到着通路・手荷物受取所・出口はそのターミナル内だけから選ぶ。ターミナル間の移動は無い。
- 出発ゲートが無い便は、単一ターミナルなら従来互換でそのターミナルを使い、複数ターミナルではターミナルを推測せず未割当てとして記録し、到達不能・ゲートなしで処理する。ゲートはあるが入口・工程がつながらない場合は到達不能として扱い、別ターミナルの施設へ迂回しない。到着ゲート未割当て・降機口なしは到達不能。
- 独立ゲート・バスゲートは `GateAccess.terminalId` が示す接続先を便のターミナルとする。バスゲートの選択は既存の負荷・スポット距離・ID の順で決定する。複数の入口は、旅客の次の必須工程まで開いた経路があるものに絞ってからシード付きで選ぶ。接続入口がない場合、閉鎖中は再開を待ち、構造的に到達不能なら到達不能として記録する。
- 運航計画のチェックイン・保安検査能力はターミナル別に需要と比較し、全体表示の能力は各ターミナルの合計とする。運航カードはターミナル別の館内人数、チェックイン・保安検査能力、平均待ち時間を表示する。
- 構造検証は施設の存在に加えて、利用可能な入口 → チェックイン → 保安検査の経路、ゲート別の保安検査 → 搭乗口経路、到着ゲート → 手荷物受取所 → 出口経路を確認する。運航中は到達不能、ターミナル割当て不一致、長時間の施設・工程待ちを集約してアラート表示し、現在の問題と解消履歴を確認できる。
- 複数の入口がある場合でも、出発グループを接続していない入口へ割り当てない。動的な施設閉鎖は構造検証と分け、旅客が実際に待機・経路探索できない状態を運航アラートに集約する。
- 搭乗口の変更後、まだ空港施設内に入っていない旅客は新しいゲートのターミナルへ割り当て直す。同じターミナル内の変更は再経路探索する。施設内に入った後に別ターミナルへ変更された旅客は、未実装のターミナル間移動を仮定せず、到達不能として通知する。
- 運航中に歩行中の次区間が閉鎖された場合はその場から再経路探索する。異常な滞留は待機・工程の種類ごとに監視し、通常の混雑は動線不成立にしない。施設待ち15分、処理待ち20分、歩行中の無進捗は区間長から求める通常所要時間の2倍 + 5分（最低10分）を警告しきい値とする。
- 座席数は表示用で、座席不足による影響はまだ無い。
