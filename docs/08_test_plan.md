# 08. テスト計画

## 1. 方針

- シミュレーションコア（`src/core`）は DOM 非依存のため、**大半のテストを Node 上の Vitest で実行**する。
- 「仕様書に書いた不変条件・状態遷移」を、テストの主要な観点とする。
- ランダム性はシード固定で再現し、失敗時はシードとコマンドログを出力して再現できるようにする。
- UI・描画のテストは最小限（E2E のスモーク + 主要フロー）とし、ロジックを UI に置かないことでテスト対象を core に集める。

## 2. テストの種類

| 種類 | 対象 | ツール | 実行タイミング |
|------|------|--------|---------------|
| 単体 | core の関数・モジュール | Vitest | 常時（PR ごと） |
| プロパティ | 不変条件（ランダム操作列） | Vitest + fast-check | PR ごと（回数少）/ 夜間（回数多） |
| 統合（シナリオ） | 複数システムを通したゲームプレイ | Vitest（ヘッドレスで N 日実行） | PR ごと |
| 回帰（ゴールデン） | シード + 初期状態 + コマンドログ → 結果 | Vitest | PR ごと |
| セーブ互換 | 旧スキーマのセーブ読込 | Vitest | PR ごと |
| 性能 | ティック処理時間・派生データ再構築 | Vitest bench | PR ごと（閾値超過で警告）|
| E2E | ブラウザでの起動・建設・運航・セーブ | Playwright | main マージ時・夜間 |
| 目視/プレイテスト | バランス・操作感 | 手動 + ヘッドレスCLIのKPI | フェーズ完了時 |

## 3. 単体テストの観点（モジュール別）

| モジュール | 主なテストケース |
|-----------|-----------------|
| rng | 同一シードで同一列、ストリーム間の独立性、状態のシリアライズ往復 |
| model/ids | 発行の単調増加、ロード後も重複しない |
| map/placement | 地形不可・重なり・クリアランス違反・資金不足の拒否、正常配置 |
| airside/graph | 直線・L字・T字・十字の誘導路で期待どおりのノード/エッジ、幅区分による `maxSize`、一方通行で逆エッジがない、斜め角切り防止、建設中タイルの除外、滑走路接続部にホールディングポイント |
| airside/pathfinding | 最短経路、サイズ制約で迂回、到達不能で null、一方通行遵守、同コスト時の決定的タイブレーク、滑走路横断ペナルティ |
| airside/reservation | 予約の排他、前方予約・後方解放、交差点の一括予約、滑走路ノードは占有なしで予約不可 |
| airside/deadlock | 対向2機・4機環状の閉路検出、優先度に従った解消 |
| ops/runway | 間隔表どおりの許可、mixed での離着陸選択、飢餓防止、横断許可、モード別の拒否 |
| ops/standAllocator | サイズ適合、時間窓重複の拒否、遅延時の再割り当て、手動割り当て検証、決定的なタイブレーク |
| ops/aircraftFsm | 全正常遷移、不正遷移の拒否、例外遷移（経路なし・スポットなし） |
| ops/flightFsm | 生成→確定→運航→完了、遅延伝播、欠航条件 |
| ops/turnaround | 依存関係順、クルー不足時の待ち、区分係数 |
| pax/network | 歩行リンクの距離算出、非接続施設の警告 |
| pax/queue | FIFO、窓口数・配置人数による処理速度、容量超過時の上流待機 |
| pax/stages | 出発・到着の全段階、オンラインチェックインのスキップ、乗り遅れ |
| baggage | 仕分け容量、積み残し、受取所割り当て |
| economy | 料金計算（丸め含む）、駐機料の無料時間と切り上げ、搭乗率式、満足度更新、契約更新判定、日次締め順序、ledger と cash の一致 |
| save | シリアライズ往復で同値、マイグレーション、派生データが保存されないこと |

## 4. 不変条件テスト

[04_operations_passenger_spec.md](04_operations_passenger_spec.md) §11 の不変条件（R1–R3, S1–S4, T1–T3, P1, B1, F1, ID1）を `core/invariants` に関数として実装し、以下で使う。

1. **全統合テストで毎ティック実行**（違反で即失敗し、ティック・シード・違反内容を出力）。
2. **プロパティテスト**: fast-check で「ランダムなマップ（テンプレートの組合せ）+ ランダムな便スケジュール + ランダムなプレイヤー操作（建設・撤去・料金変更・手動割り当て）」を生成し、数日分実行して不変条件が破れないことを確認。失敗時は fast-check の縮小（shrink）で最小再現ケースを得る。
3. 開発ビルドの実行時チェック。

## 5. 統合（シナリオ）テスト

`tests/fixtures/maps/` にテスト用マップ（JSON）を用意し、ヘッドレスで実行して結果を検証する。

| シナリオ | 内容 | 期待結果 |
|----------|------|---------|
| SC-01 最小空港 | 滑走路1・誘導路1本・スポット1・ゲート1、M級1日2往復 | 全便 completed、旅客・手荷物の保存、収支が手計算と一致 |
| SC-02 スポット不足 | スポット1に対し同時刻2便 | 2便目が待機/遅延（noStand）、二重割り当てなし |
| SC-03 未接続誘導路 | スポットが滑走路と非接続 | 検証警告、そのスポットに割り当てなし、航空機が進入しない |
| SC-04 サイズ制約 | narrow 誘導路のみの経路に L 級 | L 級は迂回または割り当て対象外 |
| SC-05 滑走路混雑 | 1時間に50便の要求 | 滑走路の同時占有なし、間隔表を守る、遅延が発生 |
| SC-06 対向デッドロック | 1本の誘導路で到着・出発が対向 | デッドロック検出・解消、全便最終的に完了 |
| SC-07 保安検査不足 | 保安レーン1、ピーク旅客多 | 待ち時間増、満足度低下、乗り遅れ発生 |
| SC-08 運用中の撤去 | 機体が使用中のスポットを撤去 | 撤去予約、使用終了後に撤去、整合性維持 |
| SC-09 遅延伝播 | 到着便 +60分 | 折り返し出発便の estimated が更新、スポット再調整 |
| SC-10 日次締め・契約 | 30日実行 | 評価・満足度・契約更新が仕様どおり |
| SC-11 セーブ/ロード途中再開 | 途中でセーブ→ロードして続行 | セーブなしで連続実行した場合と同一の最終状態ハッシュ |

## 6. 回帰テスト（ゴールデン）

- 入力: `{ 初期マップ, シード, コマンドログ }`、N 日実行。
- 出力: 最終状態の **正規化ハッシュ**（ID順にソートした JSON の SHA-256）と主要 KPI（旅客数・OTP・純利益）。
- 期待値ファイル `tests/regression/golden/*.json` と比較。
- 仕様変更で結果が変わる場合は `npm run test:update-golden` で更新し、**差分（KPIの変化）をPRに記載** する運用とする。
- バランス値の変更はゴールデンを変えるため、ゴールデンは「固定バランス値（テスト用 `balance.test.json`）」で実行し、ロジックの回帰とバランス調整を分離する。

## 7. E2E テスト（Playwright）

| ID | フロー |
|----|--------|
| E2E-01 | 起動 → 新規ゲーム → メイン画面表示（コンソールエラーなし） |
| E2E-02 | 滑走路・誘導路・スポット・ターミナルを配置 → 開港チェックリストが全て緑 |
| E2E-03 | 契約承認 → 速度8x → 1日経過 → 運航表に completed 便がある |
| E2E-04 | セーブ → リロード → ロード → 状態が復元 |
| E2E-05 | スクリーンショット比較（主要画面、許容差あり、夜間のみ） |

テスト用にフィクスチャのセーブデータを URL パラメータ（`?fixture=sc01`、開発ビルドのみ）で読み込めるようにする。

## 8. 性能テスト

- ベンチマークシナリオ: 目標規模（滑走路2・スポット30・同時40機・旅客グループ2,000）のフィクスチャで1日分を実行。
- 指標: 平均/95パーセンタイルのティック処理時間、派生データ再構築時間、メモリ。
- 閾値（[07](07_architecture.md) §8）を超えたら CI で警告。

## 9. 品質ゲート（各フェーズ完了条件に共通）

- lint / typecheck / 全テストが成功
- core の行カバレッジ 80% 以上（ops・airside・economy は 90% 目標）
- 不変条件違反ゼロ（全シナリオ・プロパティテスト）
- 新規の状態・遷移を追加した場合、仕様書（04）を同じPRで更新

## 10. 不具合再現の手順

1. ゲーム内メニュー「不具合報告用データを書き出す」で `{セーブ, シード, 直近のコマンドログ}` をファイル出力（開発ビルド）。
2. `tools/run-scenario.ts --replay file.json` で Node 上で再現。
3. 再現ケースを `tests/regression/` に追加してから修正する。

## 11. Phase 2 で追加したテスト（運航シミュレーション）

| ファイル | 内容 |
|---------|------|
| `tests/unit/sim/pathfinding.test.ts` | 接続されたエッジだけの経路、到達不能で null、機体区分による制限、予約区間の迂回、一方通行 |
| `tests/unit/sim/simulation.test.ts` | 到着から駐機まで、駐機から離陸まで、スポットの競合、連続到着の間隔、着陸中の離陸禁止、閉鎖滑走路でのダイバート、到達不能経路、滑走路横断、1日分の運航と決定性、一時停止・再開・時間倍率・処理落ち |
