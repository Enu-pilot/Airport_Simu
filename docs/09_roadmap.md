# 09. フェーズ別ロードマップ

各フェーズは「動くもの」で終わるように区切る。フェーズ完了ごとに成果を報告し、承認を得てから次へ進む。
全フェーズ共通の品質ゲートは [08_test_plan.md](08_test_plan.md) §9。

## 初期版（MVP = v0.1）

### Phase 0: 要件定義・技術設計 ← **現在**

- 成果物: `docs/` 一式（本書を含む11文書）
- 完了条件: 初期版/後続機能、データ構造、航空機状態遷移、旅客動線、経営モデル、技術構成、テスト方法の明文化。**承認待ち。**

### Phase 1: 基盤（プロジェクト・コア骨格・マップ・建設）

- Vite + TypeScript + React + PixiJS + Vitest + ESLint の雛形、CI（lint/typecheck/test/build）
- モジュール境界ルール、`Math.random`/`Date.now` の core 内禁止ルール
- core: `GameState`、ID発行、シード付き RNG（ストリーム）、固定ティックループ、コマンド検証/適用、イベントログ
- map: 地形、建設レイヤー（配置系 Structure / ペイント系）、占有、配置検証、工期、撤去
- render: 地形・施設の描画、カメラ（パン/ズーム）、建設ゴースト
- ui: トップバー（時刻・速度・資金）、建設ツールバー
- save: シリアライズ往復（IndexedDB 保存は簡易）
- **完了条件**: ブラウザで滑走路・誘導路・エプロン・スポット・建物を配置/撤去でき、時間が進み、セーブ/ロードできる。ヘッドレスでコアが動く。

### Phase 2: エアサイド（グラフ・経路・地上走行・滑走路）

- エアサイドグラフ生成と検証警告、デバッグオーバーレイ
- A* 経路探索（サイズ・一方通行・横断）とキャッシュ
- 区間予約、交差点ルール、デッドロック検出・解消
- 滑走路コントローラ（進入キュー、占有、間隔表、mixed 運用、横断）
- 航空機状態機械（到着〜離陸の移動部分。ターンアラウンドは固定時間のスタブ）
- デバッグ用の「テスト機を出現させる」コマンド
- **完了条件**: 手で作った誘導路網で、複数機が着陸→スポット→（固定時間）→離陸を衝突・二重占有なしに繰り返す。SC-03〜SC-06 合格。

### Phase 3: 運航（便・スポット割り当て・ターンアラウンド）

- 機種データ、便の状態機械、スケジュール生成（契約はダミーデータ）
- 遅延の発生・伝播、欠航
- スポット割り当て（貪欲法・再割り当て・手動割り当て）
- ターンアラウンド作業の依存関係、GSE クルー、地上支援基地・燃料施設
- 運航表パネル、航空機詳細パネル
- **完了条件**: スケジュールどおりに便が回り、遅延・スポット不足・GSE 不足が仕様どおりに発生・記録される。SC-01（旅客抜き）、SC-02、SC-08、SC-09 合格。

### Phase 4: 旅客・手荷物

- ターミナル区域（制限/非制限）、処理施設、ランドサイド処理ネットワーク
- 旅客グループの生成と出発・到着行程、施設待ち行列、乗り遅れ
- 手荷物フロー（預け→仕分け→積載、荷降ろし→受取所）
- 道路・カーブサイド
- 旅客満足度、混雑オーバーレイ
- **完了条件**: 旅客と手荷物が施設を流れ、配置変更で待ち時間・歩行距離が変わることを確認できる。SC-01（完全版）、SC-07 合格。

### Phase 5: 経営

- ledger、料金設定と課金、建設費・維持費・人件費、日次締め
- 職員配置
- 航空会社・契約提案・搭乗率・航空会社満足度・契約更新
- 空港評価、KPI 集計、開港条件
- 財務・契約・職員・KPI パネル
- **完了条件**: フリープレイで「建設 → 開港 → 契約 → 運航 → 収支確認 → 改善」のループが成立。SC-10 合格。

### Phase 6: UI 仕上げ・ゲーム体験

- オーバーレイ一式（混雑・経路・スポット・稼働率）、スポットガント
- 通知とクリックでのジャンプ、開港チェックリスト
- セーブスロット・オートセーブ・ファイル入出力、設定画面
- 新規ゲーム設定（モード・シード・資金）、簡易チュートリアル（S優先度）
- i18n 整備、アクセシビリティ（パターン併用・UI拡大率）
- **完了条件**: 初見のプレイヤーが説明なしで最小空港を開港できる（社内プレイテスト）。E2E-01〜04 合格。

### Phase 7: バランス・性能・リリース

- ヘッドレスCLIによるバランス調整（数十日分の自動実行で KPI を確認）
- 性能目標の達成（必要に応じてコアの Web Worker 化、描画最適化）
- 回帰ゴールデンの整備、E2E 夜間実行
- 静的ホスティングへのデプロイ
- **完了条件**: 非機能要件 NF-01〜NF-03 を満たし、v0.1 として公開。
