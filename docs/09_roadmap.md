# 09. フェーズ別ロードマップ

各フェーズは「動くもの」で終わるように区切る。フェーズ完了ごとに成果を報告し、承認を得てから次へ進む。
全フェーズ共通の品質ゲートは [08_test_plan.md](08_test_plan.md) §9。

## 初期版（MVP = v0.1）

### Phase 0: 要件定義・技術設計 ✅

- 成果物: `docs/` 一式（本書を含む11文書）

### Phase 1: 2D空港マップ・建設エディタ ✅

当初案（基盤 + 建設）から、建設エディタに焦点を絞って実施した。ゲーム内時刻・ティックループ・コマンドログは Phase 2 の冒頭に移す。

- Vite + TypeScript + React + PixiJS + Zustand + Vitest + Playwright + ESLint（レイヤー境界ルール、core 内の `Math.random`/`Date.now` 禁止）
- core: レイアウトのデータモデル、安定ID、シード付き乱数と敷地生成、編集操作、Undo/Redo、JSON 入出力
- 論理エアサイドネットワークの導出（誘導路・滑走路・スポット接続、機体区分・一方通行・建設状態による通行条件）
- 配置エラー・接続エラーの検出と運用可否の判定
- 2Dマップ（グリッド・ズーム・パン・建設不可エリア・論理ネットワーク・エラー表示）、建設ツール、施設一覧、プロパティパネル、問題一覧
- 初期サンプル空港の生成
- **完了条件**: 施設の座標・形状・接続関係が一貫して保持され、配置・回転・移動・削除・座標変換・Undo/Redo・重複・誘導路接続・滑走路属性・孤立施設検出のテストが通る。

### Phase 2: 航空機運航・地上移動シミュレーション ✅

ルールの詳細は [11_operations_rules.md](11_operations_rules.md)。

- ゲーム内時刻・固定ティック（1ゲーム秒）・時間倍率・一時停止、描画との分離（処理落ち時はティックを捨てる）
- 機種（S/M/L の3機種）、到着・出発便の生成（シード付き）、手動の便追加
- 航空機の状態遷移（到着予定〜出発完了、空中待機・着陸復行・ダイバート・欠航）と運航履歴
- 滑走路の選択・運用方向とモード、占有（1機）と進入予約（1機）による排他、間隔表、横断、飢餓防止
- 誘導路の経路探索（ダイクストラ、区分・一方通行・建設状態）、全区間の一括予約と通過後の解放、迂回
- スポットの割り当て（1スポット1機）
- 運航モードの UI（時計・倍率、運航表、機体詳細と運航履歴、イベントログ、滑走路の状態、予約の表示）
- **完了条件**: 航空機が到着→駐機→出発完了でき、状態と占有情報が整合する（毎ティックの不変条件チェック付きテスト）。

コマンドログによるリプレイは、運航状態の保存（Phase 6）と合わせて実装する。

### Phase 3: ターミナル・旅客流動 ✅

ルールの詳細は [12_passenger_rules.md](12_passenger_rules.md)。ターミナル内部（階・エリア・上下移動）、旅客グループの発生・経路探索・移動、施設の待ち行列、搭乗締切、到着旅客と手荷物受取、施設閉鎖、混雑の可視化。

### Phase 3（旧案）: 運航（便・スポット割り当て・ターンアラウンド）→ Phase 4 に統合

- 機種データ、便の状態機械、スケジュール生成（契約はダミーデータ）
- 遅延の発生・伝播、欠航
- スポット割り当て（貪欲法・再割り当て・手動割り当て）
- ターンアラウンド作業の依存関係、GSE クルー、地上支援基地・燃料施設
- 運航表パネル、航空機詳細パネル
- **完了条件**: スケジュールどおりに便が回り、遅延・スポット不足・GSE 不足が仕様どおりに発生・記録される。SC-01（旅客抜き）、SC-02、SC-08、SC-09 合格。

### Phase 4: 旅客・手荷物

- ターミナル区域（制限/非制限）、処理施設、ランドサイド処理ネットワーク
- 旅客グループの生成と出発・到着行程、施設待ち行列、乗り遅れ
- 手荷物フロー（預け→仕分け→積載、荷降ろし→受取所）
- 道路・カーブサイド
- 旅客満足度、混雑オーバーレイ
- **完了条件**: 旅客と手荷物が施設を流れ、配置変更で待ち時間・歩行距離が変わることを確認できる。SC-01（完全版）、SC-07 合格。

### Phase 5: 経営

- ledger、料金設定と課金、建設費・維持費・人件費、日次締め
- 職員配置
- 航空会社・契約提案・搭乗率・航空会社満足度・契約更新
- 空港評価、KPI 集計、開港条件
- 財務・契約・職員・KPI パネル
- **完了条件**: フリープレイで「建設 → 開港 → 契約 → 運航 → 収支確認 → 改善」のループが成立。SC-10 合格。

### Phase 6: UI 仕上げ・ゲーム体験

- オーバーレイ一式（混雑・経路・スポット・稼働率）、スポットガント
- 通知とクリックでのジャンプ、開港チェックリスト
- セーブスロット・オートセーブ・ファイル入出力、設定画面
- 新規ゲーム設定（モード・シード・資金）、簡易チュートリアル（S優先度）
- i18n 整備、アクセシビリティ（パターン併用・UI拡大率）
- **完了条件**: 初見のプレイヤーが説明なしで最小空港を開港できる（社内プレイテスト）。E2E-01〜04 合格。

### Phase 7: バランス・性能・リリース

- ヘッドレスCLIによるバランス調整（数十日分の自動実行で KPI を確認）
- 性能目標の達成（必要に応じてコアの Web Worker 化、描画最適化）
- 回帰ゴールデンの整備、E2E 夜間実行
- 静的ホスティングへのデプロイ
- **完了条件**: 非機能要件 NF-01〜NF-03 を満たし、v0.1 として公開。
