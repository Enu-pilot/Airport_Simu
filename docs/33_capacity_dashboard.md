# 空港能力ダッシュボード

## 1. 画面とデータの流れ

経営ページの「空港能力」から、運航計画 `planDayWithDemand` と計画分析 `analyzeDayPlan` を再利用して表示する。施設の設定値は `AirportLayout` と `SimContext` から読み、空港の保存形式は変更しない。

契約・増便の仮想チェックでは `CompanyState` を複製し、試算用の一時契約を追加して計画・分析を再実行する。元の会社、レイアウト、セーブスロット、運航状態は変更しない。

## 2. 表示する算出値

| 指標 | 算出方法 | 単位・注意 |
|---|---|---|
| 滑走路 | 運用中滑走路数 × 計画基準値 `RUNWAY_HOURLY_CAPACITY` | 回/時。現行の 30 回/時は計画警告に使うゲーム値で、滑走路の構成・風・従属運用を解いた実性能ではない |
| スポット | 運用中かつ誘導路接続済みの個数。需要は計画割当における到着から出発までの同時駐機ピーク | 箇所と機数。直結/リモート別に施設一覧へ表示。1スポットは同時に1機 |
| チェックイン | 運用ターミナルのカウンター数 × 3600 ÷ 施設別処理秒数 | 人/時。計画上の出発旅客の 65% を需要とする既存計画モデル |
| 保安検査 | 運用ターミナルのレーン数 × 3600 ÷ 施設別処理秒数 | 人/時。計画出発旅客を需要として使う |
| ターミナル | 各ターミナルで `min(保安検査, チェックイン能力 / 0.65)` を算出し合算 | 人/時。接続先を割り当てられない旅客を含めない |
| 折り返し | 既存 `turnaroundCapacity` による人員・車両制約の最小上限と、計画中の最大同時機数 | 機。同じ要員・設備を工程ごとに加算せず、既存の共有リソース算出を使う。燃料施設・整備士・トーイングカーのいずれかがなければ 0。給油の制約は 給油車 × 2 ＋ ハイドラント接続スポット数。ランプバスは式に入れない |
| 日次理論値 | 時間能力 × 会社の開場から閉場までの時間 | 回/日・人/日。24時間換算ではない。ピーク偏在・日中の閉鎖等は含まない |
| スポットの回転数 | 運用中スポット数 ÷ 計画の平均占有時間（降機〜出発＋スポット間隔 `STAND_GAP_SEC`）× 2（到着・出発） | 回/時。計画に便がなければ未算出 |
| 空港全体の離発着能力 | 滑走路能力・スポットの回転数・折り返し能力 × 2 ÷ 平均の折り返し時間（到着〜出発）の最小。制約になっている要素（滑走路 / スポット / 折り返し）も表示 | 回/時。誘導路は能力が未算出のため含めない。計画に便がなければスポット・折り返しは未算出 |
| 空港アクセス（合計・1 時間 / 1 日） | 使える手段（`analyzeAccess`）の時間あたり能力の合計。1 日は運用時間を掛けた理論値 | 人/時・人/日。使える手段に能力が算出できないもの（自家用車・送迎・徒歩は常に能力なし）が 1 つでもあれば「未算出」で、根拠欄にその手段を示す。需要・実績は未算出 |

運航中の閉鎖（`LiveClosures`: 閉鎖中の滑走路・スポット）を渡すと、滑走路数・スポット数・施設一覧に反映し、根拠欄に「運航中の閉鎖を反映」と示す。

80% 以上は注意、100% 超は能力不足。需要がない項目は0%、容量モデル自体がない項目は「未算出」とする。

## 3. 施設別内訳

- 滑走路ごとは運用状態と計画用基準能力を表示するが、滑走路ごとの便割当需要は未算出。
- 誘導路ごとは運用状態を表示する。ネットワーク経路探索は利用可能性を扱うが、通過時間と占有競合を時間能力に変換する式がないため、回/時は未算出。
- スポットごとは直結/リモート、運用状態、計画同時駐機数を表示する。
- ターミナルごとは同じターミナル内に割り当てた出発旅客、チェックイン/保安検査能力、工程ボトルネックを表示する。施設別カウンター/レーン能力は設定数・秒/人から算出する。
- 搭乗ゲートごとの処理率はモデル化されていない。接続ターミナルと運用状態は表示する。
- 空港アクセスの施設として、一般車の出入口（出入口数 × 道路容量）、車寄せ、駐車場（台数）、バス乗り場（便/時 × 1 便の定員）、タクシー乗り場（乗車枠 × 人/時）の容量を表示する。アクセス手段として使われていない施設の容量は未算出。需要・実績はいずれも未算出。
- ターミナル間通路・動く歩道は、明示容量が未設定のとき運航で使う既定の容量（`terminalLinkCapacityPerHour`）を容量として表示し、根拠欄にその旨を示す。需要は未算出。
- 地上支援拠点は配置人数・車両台数を表示する。車両・人員の施設別稼働率はシミュレーションログから算出する別分析が必要なため未算出とし、既存の折り返し能力上限へ二重加算しない。

ランプバスは台数・1台当たりの定員を根拠情報として表示するが、往復時間はスポット・バスゲート間の経路、乗降人数、運行中の配車競合によって変化する。運転要員・経路時間を一体で算出するモデルが未実装のため、人/時は未算出とする。

### 誘導路の行（フェーズ 2）

- 従来の地上走行（`taxiMode` が欠落）: 誘導路の時間当たり能力は**未算出**のまま（`capacity: null`・`uncomputed`）。
- 区間ごとの地上走行（`taxiMode: 'block'`。[docs/41](41_capacity_expansion_plan.md) §1）: 運用中の誘導路の行に、含む区間の最小の通行能力（回/時、M 機）を出す。式は `min(進入可能機数 × 3600 ÷ 通過時間, 3600 × 地上走行速度 ÷ 必要長 90 m)`（`taxiBlocks.ts` の `taxiwayCapacityPerHour`。通過時間 = 区間の長さ ÷ 地上走行速度、速度は M 機の代表の型の値）。**実装済み**（`tests/unit/taxiwayCapacity.test.ts`）。「空港全体の離発着能力」には含めない（未検証のため）。
- 飽和させた運航の実績との比（目標 0.8〜1.2、plan 2-08）は**未計測**。計測した値は docs/41 の実装の記録に書く。
- `city.nightOps` があるときだけ、運用時間（1 日の理論値の係数）の終わりを最終出発時刻で切る（R17）。`nightOps` がなければ従来の営業時間のまま。

## 4. 契約・増便の仮想チェック

選んだ航空会社・就航先・保有機種・日便数・時間帯を当日有効の一時契約として追加し、現行計画と追加後の計画を比較する。新たに発生した計画上のエラーは受け入れ不可、警告は条件付き、追加警告がない場合は受け入れ可能とする。選択機種が空港で運航できない場合は受け入れ不可とする。

現在の能力上限が低いままでも追加便がその上限を超えない場合があり、必ずしも全ての既存不足を修正するとは限らない。またこのチェックは長時間の運航を試行するものではなく、計画の割当・施設能力警告に基づく。誘導路時間能力、プッシュバック時間能力、バス時間能力、時刻別のサービス業務時間は現在のシミュレーションに存在しない。

## 5. ページ構成

メイン画面の上部ナビゲーションは「建設」「経営」「運行」。経営ページは需要・計画、能力、契約・航空会社、アクセス、財務、分析・履歴、拡張、配置チェック、機種カタログ、シナリオ、保存・プロジェクト、目標を既存パネルから構成する。

「メニュー」は必要時に開き、新規ゲーム、サンドボックス、空の敷地/サンプル、難易度・ルール、JSON保存/読込、保存データ管理への移動をまとめる。トップレベルのページ切替は `editorStore.mode` を変更しない。運航中に建設画面へ移動した場合は編集を無効にし、動作中シミュレーションを継続する。運航モードのマップ・運航表・常設カードは運行ページ内に維持する。
