# 11. 運航ルール仕様（Phase 2 実装）

> **本書のルールはゲーム用に簡略化したものです。** 実際の航空管制方式・離着陸間隔・後方乱気流区分・空港運用基準を再現したり、
> それらに適合したりすることを主張するものではありません。数値はゲームとしての分かりやすさを優先した仮の値です。

実装: `src/core/sim/`（定数は `rules.ts`、機種は `aircraftTypes.ts`）。[04_operations_passenger_spec.md](04_operations_passenger_spec.md) の運航部分のうち、Phase 2 で実装した内容と、Phase 0 案からの変更点をまとめる。

## 1. 時間モデル

| 項目 | 仕様 |
|------|------|
| ティック | 1ティック = 1ゲーム秒（固定）。すべての移動・判定はこの刻みで行う |
| 時間倍率 | 一時停止 / 実時間 / ×15 / ×60 / ×240 / ×600（実時間1秒あたりのゲーム秒数） |
| 描画との分離 | 描画フレームごとに「実経過時間 × 倍率」をティック数に換算し、固定刻みのティックを必要回数実行する（`core/sim/clock.ts`）。描画はティック間を線形補間して表示するだけで、状態は変えない |
| 処理落ち | 1フレームのティック数に上限（120）を設け、超えた分は捨てる。ゲーム内時間が遅れるだけで、刻み幅が大きくなることはない（機体がワープせず、倍率で衝突判定が変わらない）。1フレームの実時間は 0.25 秒で頭打ちにする（タブ復帰時の暴走防止） |
| 開始時刻 | 1日目 06:00 |
| 決定性 | 同じレイアウト・同じシードからは、フレームの刻み方や一時停止の有無にかかわらず同じ結果になる（テストで確認） |

## 3. 航空機の状態

```
scheduled ─→ inbound ⇄ holding ─→ approach ─→ landing ─→ vacating ─→ taxiIn ─→ docking ─→ parked
 (到着予定)  (到着処理中)(空中待機) (最終進入)  (着陸)    (滑走路離脱)(到着走行)(スポット進入)(駐機中)
                │  ↑        │                                                          │
                │  └ 着陸復行 ┘                                                          ↓
                ↓                                                                   turnaround (出発準備中)
           diverted                                                                     ↓
       (運航不能:ダイバート)                                                   readyForPushback (出発待機)
                                                                                 │        ↓
                                                                    cannotOperate   pushback (プッシュバック)
                                                                   (運航不能:欠航)       ↓
   departed ←── takeoff ←── lineUp ←── holdShort ←── taxiOut (出発走行) ←────────────┘
  (出発完了)   (離陸滑走)  (滑走路進入) (離陸待ち)
```

| 要求された状態 | 実装上の状態 | 入る条件 / 出る条件 |
|---------------|-------------|-------------------|
| 到着予定 | `scheduled` | 便の生成時 / 着陸予定の15分前に空域へ |
| 到着処理中 | `inbound` | スポット・滑走路・経路を確保中 / 進入許可で `approach` |
| 遅延（空中） | `holding` | 進入できない（理由は §8）/ 許可が出れば `approach`、45分でダイバート |
| 滑走路への進入・着陸 | `approach` → `landing` | 進入許可（滑走路の進入予約）→ 90秒後に滑走路端。空いていれば接地して占有 |
| 滑走路からの離脱 | `vacating` | 離脱ノード到達 / 離脱誘導路上の停止位置を機体長分越えたら滑走路を解放 |
| 誘導路上を移動中 | `taxiIn` | スポットへ走行 |
| 駐機スポットへの進入 | `docking` | スポット接続エッジに入った / スポット中心で停止（ブロックイン） |
| 駐機中 | `parked` | ブロックイン後60秒 |
| 出発準備中 | `turnaround` → `readyForPushback` | 折り返し作業（Phase 4、[13](13_ground_handling_rules.md)）がすべて完了したら準備完了。その後、出発予定時刻・搭乗締切・トーイングカーの到着・走行経路の確保を待つ |
| プッシュバック中 | `pushback` | 出発経路を全区間予約できたら後退開始 → エンジン始動60秒 → スポット解放 |
| 誘導路上を出発移動中 | `taxiOut` | 滑走路手前の停止位置まで |
| 離陸待ち | `holdShort` | 停止位置で停止。出発キュー（到着順）に並ぶ |
| 離陸処理中 | `lineUp` → `takeoff` | 離陸許可（滑走路を占有）→ 滑走路へ進入・整列15秒 → 離陸滑走 |
| 出発完了 | `departed` | 浮揚速度に達したら滑走路を解放 |
| 運航不能 | `diverted` / `cannotOperate` | 空中待機の上限（45分）でダイバート / 出発経路が60分得られなければ欠航 |

すべての状態変化は機体ごとの運航履歴（時刻・状態・理由）とイベントログに記録する。

## 4. 便の生成

- 運航開始時に当日（06:30〜22:00）、以後は毎日 23:00 に翌日分を生成する。1日の往復数の既定値は `min(60, 運用中スポット数 × 3)`。
- 各便は「到着便 + 同じ機体の折り返し出発便」の組。出発予定 = 到着予定 + 折り返し時間 + 20分。
- 機種は、空港で運航可能な区分（使用可能な滑走路と、接続済みのスポットがある区分）から重み付きで選ぶ（S:M:L = 3:6:1.5）。
- 25% の確率で出発地からの遅れ（3〜40分）を付ける。
- 乱数はシード付き（`core/rng.ts`）。手動で「到着便を追加」もできる。

## 5. 駐機スポットの割り当て

- 到着機が空域に入った時点で割り当てる。条件: 運用中・接続済み・区分が合う・**他の機体に割り当てられていない**・使用可能な滑走路との間を往復できる経路がある。
- 優先順: サイズの無駄が少ない → ゲート付き → ID 順。
- 割り当ては `standAssignments`（スポット → 機体）だけが正で、1スポットに1機しか持てない。プッシュバックしてエンジン始動を終えた時点で解除する。
- 空きがなければ 30 秒ごとに再試行し、その間は空中待機（理由: 空きスポットなし）。
- **Phase 0 案からの簡略化**: 時間窓による先行予約（ガント方式）は未実装。到着時点で空いているスポットだけを割り当てる。

## 6. 滑走路

### 6.1 運用方向とモード

- 滑走路ごとに運用方向（例: 09 方向 / 27 方向）とモード（離着陸 / 着陸専用 / 離陸専用 / 閉鎖）を運航中に変更できる。離着陸とも同じ方向を使う。
- 機体区分は滑走路の `maxSize`（長さと舗装幅、[03](03_data_model.md) §5）以下であること。

### 6.2 排他制御

| 資源 | 内容 |
|------|------|
| 占有（occupant） | 滑走路を物理的に使う機体。**同時に1機だけ**（着陸滑走〜離脱 / 整列〜浮揚 / 横断）。データ構造上2機目を持てない |
| 進入予約（booking） | 最終進入中の到着機。**同時に1機だけ** |

- **着陸**: 進入許可は「予約が空いている」「先行機との間隔が取れる」「出発の飢餓防止に当たらない」場合のみ。滑走路端に着いた時点で占有がまだ残っていれば**着陸復行**（空中待機に戻り4分後に再試行）。したがって使用中の滑走路に次の機体が無条件で進入することはない。
- **離陸**: 占有なし、かつ進入中の到着機が 90 秒以上先、かつ先行の離陸との間隔が取れる場合に許可。
- **横断**: 占有なし、かつ進入中の到着機が 60 秒以上先の場合に許可。横断機の尾部が反対側の停止位置を越えたら解放。
- **飢餓防止**: 離陸待ちが 10 分を超えたら、新しい進入許可を止めて出発を通す。

### 6.3 間隔（秒、簡略化）

| 先行 \ 後続 | S | M | L |
|------------|----|----|----|
| S | 60 | 60 | 60 |
| M | 90 | 75 | 75 |
| L | 120 | 120 | 90 |

到着→到着（接地時刻同士）、出発→出発（滑走開始同士）に適用。出発→到着は滑走開始から 45 秒以上、到着→出発は到着機が滑走路を離脱していれば可。

### 6.4 離脱・進入位置の選び方

- 着陸: 接地点から「着陸に必要な減速距離」以上先にある、誘導路が接続した滑走路ノードのうち、スポットまでの経路を確保できるもの（近いものを優先）。接地速度から離脱速度 15 m/s まで、そのノードでちょうど減速し切る一定減速度で走る。
- 離陸: 残り距離が「離陸滑走距離 + 100m」以上ある入口のうち、走行時間と滑走路全長からの距離（全長に近いほど優先）、出発待ち機数の合計が最小のもの。

## 7. 誘導路での移動と順序制御

### 7.1 経路探索

- 論理エアサイドネットワーク（[03](03_data_model.md) §5）上の多始点・多終点ダイクストラ（`core/sim/pathfinding.ts`）。
- 通れるのはネットワークのエッジのみ。機体区分・一方通行・建設状態（運用中のみ）を守る。地上走行では滑走路の上を走らない（横断はノード経由で可、コスト +120 秒）。
- 経路が見つからない場合、機体は**移動せず**その場（空中 / スポット）で待機する。瞬間移動はしない。

### 7.2 区間予約

- ノードとエッジ（誘導路区間）は1機ずつしか予約できない。
- 到着機は**進入許可の時点で**、離脱ノードからスポット入口までの全区間を予約する（予約できなければ進入しない = 着陸後に滑走路上で立ち往生しない）。出発機は**プッシュバック開始時に**スポット入口から離陸位置までの全区間を予約する。
- 予約できない場合は、他機の予約区間を避けた迂回路を探し、それも無ければ待機（理由: 経路上に他機）して 5 秒ごとに再試行する。
- 通過済みの区間は、機体の尾部（機体長）がノードを越えた時点でそのノードと手前のエッジを解放する。
- 走行中の機体は、自分が予約している区間の中しか進めないため、交差点での交差・同一区間の対向・追突は起こらない。経路を一括で確保してから動くため、互いの予約を待ち合うデッドロックも起こらない（Phase 0 案のデッドロック検出・解消は不要になった）。
- 地上で動いている機体同士が 20m 未満に近づいたら「競合」として記録する（予約制御が正しければ常に 0 件）。

### 7.3 停止位置と速度

| 項目 | 値 |
|------|----|
| 滑走路手前の停止位置 | 滑走路中心線から 87.5m（接続エッジ長の 60% を上限） |
| 加速 / 減速 | 0.6 / 1.2 m/s²（停止位置までの制動距離を毎ティック考慮。停止位置は越えない） |
| 曲がり角（45度以上） | 5 m/s |
| スポット進入 | 2 m/s、プッシュバック 1.5 m/s、滑走路への整列 4 m/s |

### 7.4 区間ごとに進む地上走行（フェーズ 2。`layout.taxiMode === 'block'` のときだけ。選択式・既定は §7.2 の従来方式）

仕様: [41](41_capacity_expansion_plan.md) §1、実装計画: [design/impl_phase2_plan.md](design/impl_phase2_plan.md) §1〜§2。数値はゲーム内の値。

- 誘導路を、交差点・行き止まり・滑走路ノード・スポット入口・条件の変わり目で区切り、さらに `taxiBlockTiles`（既定 10 タイル = 250 m、範囲 4〜40）ごとに等分した**区間**に分ける（`core/sim/taxiBlocks.ts` `buildTaxiBlocks`。配置から決まる派生データで保存しない）。
- 区間の進入可能機数 = 使える長さ（長さ − 出口側の停止距離）を、機体の大きさ別の必要長（S 70 / M 90 / L 120 m、混在は合計）で割った値（最小 1。誘導路ごとの上限 `blockMaxAircraft` 1〜10 で小さくできる）。
- 機体は次に止まれる区間までの交差点と枠をまとめて確保できたときだけ進み、前の機体との間隔 40 m を保って追従する。滑走路手前には列を作る。デッドロックは、向きの確保（経路全体）・行き止まりの規則・到着の離脱の保証で避け、残る環は検出して解消する。
- 待機理由（§8）: 前の区間が満杯 / 対向機の通過待ち / 滑走路手前の待機列。
- 状態は `SimState.taxiBlocks`（保存形式 4。[21](21_save_format.md)）。不変条件 B1〜B6 は §9 を参照。
- 状態: 設定・保存・表示・能力の行は**実装済み**（B 側）。走行・デッドロック回避・到着のコア（`src/core/sim`）の完了状況と測定値は [41](41_capacity_expansion_plan.md) の実装の記録（CP2）を参照。

## 8. 待機・遅延・運航不能

| 待機理由 | 主な原因 | 遅延理由として記録 |
|---------|---------|-----------------|
| 空きスポットなし | スポット不足 | スポット不足 |
| 使用できる滑走路なし / 経路なし | 閉鎖・区分不適合・未接続 | 経路なし |
| 経路上に他機 / 滑走路横断待ち | 誘導路の混雑 | 誘導路の混雑 |
| 先行機との間隔待ち / 滑走路使用中 / 出発優先 / 着陸復行 | 滑走路の混雑 | 滑走路の混雑 |
| 前の区間が満杯 / 対向機の通過待ち（区間ごとの走行のみ） | 誘導路の混雑 | 誘導路の混雑 |
| 滑走路手前の待機列（区間ごとの走行のみ） | 滑走路の混雑 | 滑走路の混雑 |

- 遅延: 到着便は着陸時刻、出発便はブロックアウト（プッシュバック開始）時刻を予定と比べる。到着の遅れは折り返しの出発予定（予想）に伝播する。
- 運航不能: 空中待機 45 分でダイバート（到着便はダイバート、出発便は欠航）。出発経路が 60 分得られなければ欠航。いずれもスポット・予約・滑走路を解放する。

## 9. 整合性の保証

テストでは毎ティック `checkInvariants`（`core/sim/invariants.ts`）を実行し、違反があれば失敗させる。

| ID | 内容 |
|----|------|
| S1/S3/S4 | 1スポット1機、区分の適合、割り当て表と機体側の参照の一致 |
| R1–R3 | 着陸・整列・離陸中の機体は滑走路を占有している。占有・進入予約と機体状態の一致 |
| T0–T2 | 予約者が有効な機体であること、走行中の機体は現在のエッジと次のノードを予約していること、経路が接続したエッジだけでできていること |
| C1 | 地上で動いている機体同士の距離 ≥ 20m |
| M1 | 1ティックの移動量が最高速度以内（瞬間移動の禁止） |

## 10. 前提と制約（ゲーム用の簡略化）

- 空域は扱わない。進入は「90 秒の最終進入」、待機は「待機旋回」として抽象化し、表示上の距離も縮めている。
- 間隔は3区分の簡易表で、風・視程・滑走路の状態は考慮しない。
- 地上走行は既定では経路の全区間を一括予約するため、実際より保守的（同じ区間を続けて走る追従走行はしない）。区間ごとに進む方式（§7.4、選択式）では追従と列を扱う。
- 機体は誘導路の中心線上を点として動き、翼端の間隔は誘導路の幅区分で近似する。
- プッシュバックはスポット接続エッジを後退するだけで、牽引車は表現しない。
- 地上作業（降機・給油・搭乗など）は折り返し時間で一括して扱う。
