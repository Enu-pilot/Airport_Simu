# 05. 経営計算仕様

## 1. 原則

- 通貨は架空の「円」相当（表示 `¥`）。内部は **整数（1円単位）** で保持し、浮動小数で金額を累積しない。
- 率の計算は「整数 × 率 → `Math.round`（四捨五入、0.5は偶数丸めではなく切り上げで統一）」とし、丸め関数は `core/economy/money.ts` の1か所に集約する。
- すべての収支は `LedgerEntry` として記録し、`cash` を直接加減算する処理は ledger 経由以外に存在させない（不変条件 F1）。
- 本書の数値はすべて **初期バランス値** であり、`data/balance.json` に外出しして調整可能とする。コードに定数を埋め込まない。

## 2. 収支の発生タイミング

| 区分 | 発生タイミング |
|------|---------------|
| 建設費 | 建設コマンド適用時（全額前払い） |

| 駐車場収入 | 車両の出庫時（S優先度） |
| 維持費・光熱費 | 日次締め（00:00） |
| 人件費 | 日次締め |
| 融資利息 | 日次締め |

## 4. 収入

### 4.1 空港使用料（プレイヤーが設定）

| 料金 | 既定値 | 設定範囲 | 計算 |
|------|--------|----------|------|
| 着陸料 | ¥1,500 / t（MTOW） | ¥500〜¥4,000 | `round(MTOW_t × 単価 × (1 - 契約割引))` |
| 旅客施設使用料（出発） | ¥1,000 / 人 | ¥0〜¥3,000 | `搭乗人数 × 単価 × (1 - 契約割引)` |
| 旅客施設使用料（到着） | ¥500 / 人 | ¥0〜¥1,500 | `降機人数 × 単価 × (1 - 契約割引)` |
| 駐機料 | S ¥1,000 / M ¥2,000 / L ¥4,000 per 時間 | ×0.5〜×2.0 | 最初の2時間無料。超過分を15分単位で切り上げ |
| ボーディングブリッジ使用料 | ¥10,000 / 回 | ¥0〜¥30,000 | ブリッジ付きゲート使用時 |

料金は需要（§6）と航空会社満足度（§7）に影響する。**基準料金**（上表の既定値）に対する比 `feeRatio` を各計算で用いる。

### 4.2 店舗収入

- 旅客グループが `dwell` 中に店舗へ立ち寄る確率 = `min(1, 店舗数 / (制限区域旅客数 / 50))` × 0.7。
- 1人あたり売上 = `¥1,500 × 滞留時間係数`（滞留30分で1.0、90分で1.6、上限1.8）× 満足度係数（満足度/70、0.5〜1.2）。
- 空港収入 = 売上 × テナント料率 20%。

### 4.3 駐車場収入（S優先度）

- 出発旅客の自家用車利用率 30%（1台あたり1.5人）。駐車料 ¥1,500/日。満車時は利用不可・満足度 -5。

### 5.2 その他費用

- 維持費（§3）を日次で計上。
- 融資（S優先度）: 上限 = 総資産評価額の50%。日利 0.02%（年約7.3%）、日次で元利均等返済。

## 6. 需要モデル

### 6.1 航空会社の契約提案

毎週（ゲーム内7日ごと）および空港評価が上がった時に、提案を生成する（`airline` 乱数ストリーム）。

- 提案数 = `1 + floor(評価星 × 0.8)` 件（最大5件）。
- 機材サイズ: 空港が受け入れ可能な最大区分以下からランダム（評価が低いと大型機は出ない: L は星3以上）。
- 週便数: 7〜21（毎日1〜3便）。希望時間帯: 朝・昼・夕のピーク帯に偏る分布。
- 提示条件: 航空会社タイプにより料金割引要求（LCC: 20〜40%、フルサービス: 0〜15%、リージョナル: 10〜25%）。
- 受け入れ判定前に UI で「この契約で増える1日あたり便数・推定旅客数・推定収入・ピーク時の施設負荷」を表示する（§8 の予測式を使用）。

### 6.2 搭乗率（便ごと）

```
loadFactor = clamp( baseLF(airlineType)
                    × feeFactor
                    × ratingFactor
                    × seasonality(day)        // 後続。初期版は 1.0
                    × (1 + noise(±0.08)),
                    0.30, 1.00 )

baseLF:       lcc 0.85 / fullService 0.78 / regional 0.70
feeFactor:    1 - 0.25 × (paxFeeRatio - 1)      // 旅客施設使用料が基準の2倍で-25%
ratingFactor: 0.80 + 0.08 × 評価星              // 星0で0.8、星5で1.2
paxBooked = round(seats × loadFactor)
bagsBooked = round(paxBooked × bagRate)         // bagRate: lcc 0.4 / full 0.9 / regional 0.6
```

### 6.3 空港評価（0〜5星、日次更新、過去7日の移動平均）

```
score (0..100) = 0.30 × OTPスコア
               + 0.30 × 旅客満足度平均
               + 0.25 × 航空会社満足度平均
               + 0.15 × 施設充足スコア（消防・必須施設・待合席/ピーク旅客 比 等）
stars = floor(score / 20 × 2) / 2   // 0.5刻み
OTPスコア = 定時率(%)（15分以内の発着）
```

## 7. 航空会社満足度と契約更新

各航空会社の満足度（0〜100、初期 60）を日次で更新。

| 要因 | 影響（日次） |
|------|-------------|
| 空港起因の遅延（`runwayQueue`, `taxiCongestion`, `noStand`, `gseShortage`, `baggage`） | 遅延便1便ごとに -1（30分超は -2） |
| 平均地上走行時間が品質要求を超過 | -1 |
| ボーディングブリッジ利用率（フルサービスのみ） | 80%以上で +0.5 |
| 手荷物ミスハンドリング | 10個ごとに -1 |
| 料金比 `feeRatio` | `-(feeRatio - 1) × 価格感度 × 2` |
| 目標達成日（全便が定時） | +1 |

契約満了時（初期契約期間 90日）:

| 満足度 | 結果 |
|--------|------|
| ≥ 75 | 便数 +25% で更新提案 |
| 50〜74 | 同条件で更新 |
| 30〜49 | 便数 -25% で更新提案（拒否で終了） |
| < 30 | 撤退（契約終了） |

満足度 < 15 が14日継続した場合は期間中でも撤退。

## 8. 予測・投資判断支援

- **ピーク時処理能力**: 施設ごとに `能力(人/時) = 稼働窓口数 × 3600 / 1人あたり処理時間`。
- **ピーク時需要**: 今後7日の便スケジュールから、旅客到着分布（[04](04_operations_passenger_spec.md) §9.3）を畳み込んだ時間帯別の予測旅客数。
- **稼働率** = 需要 / 能力。85% 超を黄色、100% 超を赤で UI 表示。
- **滑走路能力の目安**: `3600 / 平均運用間隔`（mixed で約 30〜40回/時）。スケジュール上のピーク時運用回数と比較。
- **スポット充足**: 時間帯別の必要スポット数（区分別）と保有数。
- **投資回収の目安**: 契約提案の受け入れ画面で、推定日次純益と必要追加投資を併記（後続で「この施設を追加すると何が改善するか」の比較機能）。

## 9. 日次締め処理（00:00）の順序

決定性のため、以下の順で固定する。

1. 維持費・光熱費の計上
2. 人件費の計上
3. 融資利息・返済
4. 当日 ledger を統計（`stats.daily[day]`）へ集計し、ledger をクリア
5. 旅客満足度・OTP・航空会社満足度の日次集計
6. 空港評価の更新
7. 契約の満了・撤退判定
8. 契約提案の生成（週次の日のみ）
9. 便の生成（ローリング7日）と `scheduled` への昇格
10. 破産判定（cash < 0 が30日継続）
11. 不変条件チェック（本番ビルドでもここで実行）
