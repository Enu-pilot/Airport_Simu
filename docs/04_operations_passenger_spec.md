# 04. 運航・旅客・手荷物処理仕様

> 本仕様はゲーム向けの簡略化モデルであり、実際の航空管制方式・安全基準を再現・保証するものではない。
>
> **Phase 2 で実装した運航ルール（状態、滑走路の排他、誘導路の予約、時間モデル）は [11_operations_rules.md](11_operations_rules.md) を正とする。**
> 本書 §1〜§8 の運航部分は Phase 0 時点の設計案で、主な変更点は「スポットは時間窓予約ではなく到着時の割り当て」「誘導路は前方の逐次予約ではなく全区間の一括予約（デッドロック検出は不要）」。

## 1. 航空機サイズ区分と機種（初期版）

| 機種ID | 区分 | 座席 | MTOW(t) | 必要滑走路 | 地上走行速度 | 最小折り返し | 着陸時滑走路占有 | 離陸時滑走路占有 |
|--------|------|------|---------|-----------|-------------|-------------|-----------------|-----------------|
| `regional70` | S | 70 | 40 | 48タイル | 8 m/s | 30分 | 50秒 | 40秒 |
| `narrow180` | M | 180 | 75 | 80タイル | 8 m/s | 45分 | 60秒 | 50秒 |
| `wide300` | L | 300 | 250 | 112タイル | 7 m/s | 90分 | 70秒 | 60秒 |

- 旋回・エプロン上では速度上限 5 m/s、スポット進入・プッシュバックは 2 m/s。
- 区分の包含関係: L のスポット・誘導路は S/M も使える。逆は不可。
- 後続で XL（400席級）、貨物機を追加。

## 2. 便（Flight）の状態遷移

```
                ┌──────────── cancel ─────────────┐
                │                                  ▼
 planned ──► scheduled ──► active ──► completed   cancelled
   (契約で生成)  (T-24hで確定)   │
                 │             └─► diverted（到着便のみ、S優先度）
                 └─ delayed は status ではなく estimated > scheduled のフラグとして表現
```

| 状態 | 意味 | 遷移条件 |
|------|------|----------|
| `planned` | 契約から生成された将来便 | 契約承認時に今後7日分を生成（毎日ローリング） |
| `scheduled` | 確定。スポット割り当て対象 | 予定時刻の24時間前 |
| `active` | 運航中（到着便: 進入〜ブロックイン、出発便: 搭乗開始〜離陸） | 到着便: 機体が進入キューに入った時点 / 出発便: 搭乗開始時点 |
| `completed` | 完了 | 到着便: ブロックイン（スポット停止）/ 出発便: 離陸 |
| `cancelled` | 欠航 | 機材不具合、遅延が閾値（到着便 +4h）超過、契約終了、スポット割り当て不能が出発 -1h まで継続 |
| `diverted` | 他空港へ | 進入待ちが上限（45分）を超過（S優先度） |

**遅延**: `estimated - scheduled > 15分` で「遅延」とし、`delayCauses` に原因（`inboundLate`, `runwayQueue`, `taxiCongestion`, `noStand`, `turnaround`, `boarding`, `baggage`, `gseShortage`）を記録する。到着便の遅延は折り返し出発便の `estimated` に伝播する（`max(出発予定, 到着実績 + 最小折り返し)`）。

## 3. 航空機の状態遷移

```
                          [到着側]
 (spawn) ──► inbound ──► approach ──► landing ──► vacating ──► taxiIn ──► docking
               │  ▲         │                                     │
               │  └ hold ◄──┘ (滑走路未許可・間隔不足)               │
               │                                                    ▼
               └──► diverted (despawn)                          atStand
                                                                     │
                          [地上支援]                                  ▼
                                                                turnaround
                                                                     │ 全作業完了 & 出発時刻到達
                          [出発側]                                    ▼
 (despawn) ◄── departed ◄── takeoff ◄── lineUp ◄── holdShort ◄── taxiOut ◄── pushback ◄── readyForPushback
```

| 状態 | 内容 | 入る条件 | 出る条件 | 占有するリソース |
|------|------|----------|----------|-----------------|
| `inbound` | 空域に出現（着陸予定の15分前） | 到着便の `estimated - 15min` | 5分前に `approach` | なし |
| `hold` | 空中待機 | 進入許可が出ない | 許可が出たら `approach` | 進入キュー上の順番 |
| `approach` | 最終進入（抽象。90秒） | 滑走路コントローラが進入許可（§5） | 閾値到達で `landing` | **滑走路予約**（着陸用） |
| `landing` | 着陸滑走 | 進入完了 | 占有時間経過後、離脱ノードへ | **滑走路占有** |
| `vacating` | 滑走路から誘導路へ離脱 | 離脱経路の最初の誘導路ノードを予約済み | ホールディングポイント通過で滑走路解放 | 滑走路占有 → 解放 |
| `taxiIn` | スポットへ走行 | スポット割り当て済み、経路あり | `standEntry` ノード到達 | 誘導路ノード予約（前方） |
| `docking` | スポット進入 | — | 停止完了（ブロックイン） | スポット（occupied） |
| `atStand` | 停止・エンジン停止 | ブロックイン | 即時 `turnaround` | スポット |
| `turnaround` | 地上支援作業中（§7） | — | 全作業完了 | スポット・GSEクルー・ゲート |
| `readyForPushback` | 出発待ち | 作業完了 | 出発予定時刻到達 & 地上走行許可 & プッシュバック経路予約 | スポット |
| `pushback` | 後退 | プッシュバックエッジ予約 | 誘導路ノードで停止 → スポット解放 | スポット → 解放、誘導路ノード |
| `taxiOut` | 滑走路へ走行 | — | ホールディングポイント到達 | 誘導路ノード予約 |
| `holdShort` | 滑走路手前で停止 | — | 離陸許可（§5） | ホールディングポイントノード |
| `lineUp` | 滑走路進入・整列 | 離陸許可（滑走路占有取得） | 整列完了 | **滑走路占有** |
| `takeoff` | 離陸滑走 | — | 占有時間経過 | **滑走路占有** |
| `departed` | 離陸後 | — | 滑走路解放、60秒後 despawn | なし |

### 3.1 例外遷移

- **経路なし**: `taxiIn` / `taxiOut` で経路探索に失敗した場合、現在ノードで停止し `holdReason = 'noRoute'` を設定、30秒ごとに再探索。プレイヤーに警告通知。
- **スポット割り当て失敗**（到着時に空きなし）: 着陸前に判明した場合は `hold` を継続（ダイバート判定へ）。着陸後に割り当てが失われた場合（撤去等は §8 で禁止するため通常発生しない）は、最寄りの誘導路で待機ノードに停止。
- **欠航**: 地上の機体の出発便が欠航した場合、機体はスポットに残り、次の運航（翌日の同契約便）まで駐機料が発生。

## 4. 誘導路ネットワークと地上走行

### 4.1 経路探索

- アルゴリズム: A*（ヒューリスティック = ユークリッド距離 / 最高速度）。コスト = 走行時間（長さ / 速度上限）+ 旋回ペナルティ + 滑走路横断ペナルティ（120秒）。
- 制約: `edge.maxSize >= aircraft.size`、一方通行、滑走路横断エッジは横断許可が必要。
- 決定性: 同コストのタイブレークはノードIDの辞書順。
- キャッシュ: `(structureVersion, from, to, size)` をキーに経路をキャッシュ。建設変更で無効化。

### 4.2 区間予約（衝突回避）

各航空機は経路上の **前方ノードを予約しながら** 進む。

1. 前進するには、次のノードを予約できなければならない。予約できなければその手前で停止（`holdReason = 'traffic'`）。
2. 予約は前方 `lookahead`（既定: 停止距離 + 2ノード）分を確保しようとする。
3. 通過済みノードの予約は機体後端が抜けた時点（機体長に応じたノード数）で解放。
4. 滑走路ノード・滑走路横断エッジは **滑走路占有を取得してからでないと予約できない**。
5. 交差点（3本以上のエッジが接続するノード）は、その先の出口ノードまで一括予約できる場合のみ進入する（交差点内停止の防止）。

### 4.3 デッドロック対策

- 毎ティックではなく10ティックごとに **待ちグラフ**（機体A → Aが待っているノードを予約している機体B）を構築し、閉路を検出。
- 閉路検出時: 閉路内で最も優先度の低い機体（優先度: 着陸直後の滑走路離脱中 > 到着走行 > 出発走行、同順位はID順）の前方予約を解放し、代替経路を再探索する。代替経路がない場合は、その機体を一時待避ノード（最寄りの分岐の空きノード）へ誘導。
- 30分以上解消しない場合は、プレイヤーに「誘導路が詰まっています」通知（一方通行化・待避場所の追加を促す）。
- 予防: 経路探索のコストに **対向交通ペナルティ**（同一エッジを逆方向に使用予定の機体がいる場合 +60秒）を加える。

## 5. 滑走路運用

### 5.1 不変条件

- **R1**: 任意の時刻において、1本の滑走路の `occupancy` は高々1機。
- **R2**: 滑走路ノード・横断エッジの予約を持つ機体は、その滑走路の `occupancy.aircraftId` と一致する。
- **R3**: `approach` 中の機体は、その滑走路の着陸予約を持つ（進入中に他機が占有を取得しない）。

### 5.2 滑走路コントローラ（毎ティック評価）

各滑走路に対し、以下の順で判断する。

1. 占有中なら何もしない（占有終了処理は占有機体側の状態遷移で行う）。
2. **次の着陸候補**: 進入キュー先頭の機体。着陸予約時刻（approach 開始 + 90秒）までに、以下を満たすか予測する。
   - 先行運用との最小間隔: 先行機の区分と後続機の区分による間隔表（下表）。
3. **離陸候補**: `holdShort` の機体のうち先着順（同時刻はID順）。
4. 決定ルール（`mixed` モード）:
   - 着陸予定機が **離陸1回分の所要時間（整列 + 離陸占有 + 間隔）より先** に閾値に来ないなら、離陸を許可する。
   - それ以外は着陸を優先し、離陸機は待機。
   - 離陸待機が 10分を超えた機体が出た場合、進入許可を一時的に1回保留し離陸を通す（飢餓防止）。
5. 横断要求（`runwayCrossing`）: 滑走路が空いており、次の着陸までに横断時間（30秒）+ 余裕 30秒がある場合に許可。

**運用間隔表（秒、簡略化）**

| 先行 \ 後続 | S | M | L |
|------------|----|----|----|
| S | 60 | 60 | 60 |
| M | 90 | 75 | 75 |
| L | 120 | 120 | 90 |

※到着→到着、離陸→離陸の間隔。到着→離陸は「先行機の滑走路離脱」で可、離陸→到着は「離陸機の離陸滑走開始 + 45秒」。

### 5.3 滑走路の選択

- 複数滑走路がある場合、到着便は「スポットまでの予想走行時間 + 現在の進入キュー長」で滑走路を選ぶ（スポット確定後に決定）。
- プレイヤーは滑走路ごとに `mixed / arrivalsOnly / departuresOnly / closed` を設定できる。
- 滑走路が対応できない機体区分は割り当てない。

## 6. 駐機スポットの割り当て

### 6.1 不変条件

- **S1**: 1つのスポットに対し、時間窓が重なる `StandBooking`（`planned` または `occupied`）は存在しない。
- **S2**: `occupied` のブッキングは1スポットにつき高々1つ。
- **S3**: スポットの `size` は機体区分以上。
- **S4**: `aircraft.standId` と `StandAllocation` 上の `occupied` ブッキングが一致する。

これらは `StandAllocator` モジュールのみが更新できる（他モジュールは要求APIを呼ぶ）。

### 6.2 割り当てアルゴリズム（初期版: 貪欲法）

1. トリガー: 便が `scheduled` になった時、遅延で時間窓が変わった時、スポットが追加/閉鎖された時。
2. 時間窓: `[到着 estimated - 10分, 出発 estimated + 10分]`（前後バッファ）。
3. 候補スポットを以下でソートし、最初に S1/S3 を満たすものに割り当てる。
   1. サイズが過大でない（L スポットへの S 機は減点）
   2. ゲートあり（ボーディングブリッジ付き優先、航空会社の希望）
   3. 滑走路からの走行距離が短い
   4. スポットID順（決定性のためのタイブレーク）
4. 遅延で時間窓が既存ブッキングと衝突した場合: 後続ブッキングを別スポットへ再割り当てを試み、不可なら遅延便側を再割り当て、それも不可なら「スポット待ち」（到着便は空中待機、`delayCauses: noStand`）。
5. プレイヤーの手動割り当ては S1〜S3 を満たす場合のみ受け付ける（コマンド検証で拒否）。

## 7. 地上支援（ターンアラウンド）

### 7.1 作業と依存関係

```
 ブロックイン
   ├─► 降機(deboard) ──► 清掃(clean) ──┐
   │                  └► ケータリング(cater) ┤
   ├─► 荷降ろし(unload) ──► 荷積み(load) ─┤
   └─► 給油(fuel) ※降機中の給油可 ────────┤
                                         ▼
                              搭乗(board) ※清掃・ケータリング・給油の完了後
                                         ▼
                                出発準備完了(readyForPushback)
```

| 作業 | 所要時間（M級の基準値） | 必要リソース | 備考 |
|------|----------------------|--------------|------|
| deboard | 人数 / 降機レート（ブリッジ 25人/分、タラップ 15人/分） | ゲート | 旅客グループを到着動線へ流す |
| unload | 12分 | 手荷物クルー1 | 到着手荷物バッチを受取所へ |
| clean | 15分 | 清掃クルー1 | |
| cater | 12分 | ケータリングクルー1 | |
| fuel | 燃料量 / 給油レート（M級 15分） | 燃料クルー1、燃料施設 | |
| load | 12分 + 未着手荷物待ち | 手荷物クルー1 | 出発手荷物の `madeUp` を待つ |
| board | 搭乗開始は出発 -30分（M級）。人数 / 搭乗レート | ゲート | ゲート到着済みグループのみ搭乗可 |

- S/L 級は時間に係数（S: 0.7、L: 1.6）。
- 作業開始には GSE クルーの到着が必要。到着時間 = 地上支援基地からスポットまでの距離 / 車両速度（10 m/s、エアサイドの道路は初期版では直線距離で近似）。
- クルー数は地上支援基地ごとに職員配置で決まる。不足時は作業待ち（`delayCauses: gseShortage`）。

### 7.2 出発の判定

- 出発予定時刻（`estimated`）に `readyForPushback` であればプッシュバック要求。
- 搭乗締切（出発 -10分）に間に合わなかった旅客グループは **乗り遅れ**（満足度大幅低下、旅客は退出）。初期版では便を待たせない。
- 積み込めなかった手荷物は `missed`（ミスハンドリング、航空会社満足度低下）。

## 8. 運用中の建設変更

- 航空機の予約・占有中のノードを含むタイル、ブッキングのあるスポットは即時撤去できない → `pendingDemolition` にし、新規予約・割り当てを停止、解放後に撤去。
- 新規建設の完成は **ティック境界** で反映し、派生データを再構築したうえで、走行中の機体は次のノードで経路を再探索する（予約済み区間は維持）。
- 既存経路が無効化される変更（撤去予約）は、その区間を予約していない機体のみ再探索。

## 9. 旅客の扱い

### 9.1 旅客グループ

- 便ごとに旅客を **旅客グループ**（既定 1グループ最大10人）に分割する。
- グループは1つの単位として施設を移動・待機・処理される。描画では人数分のドットとして表示する。
- 理由: 個人エージェント（1日数万人）は経路探索と描画のコストが高い。グループ化で処理量を1/10程度にしつつ、待ち行列・混雑の手触りを保つ。

### 9.2 ランドサイド処理ネットワーク（派生データ）

ターミナル内は歩行タイル単位の経路探索ではなく、**処理ノードと歩行リンクのネットワーク** として扱う。

```
 [カーブサイド] ─walk─► [チェックイン群] ─walk─► [保安検査] ─walk─► [制限区域ハブ]
                                                                    ├─walk─► [店舗] (任意滞留)
                                                                    └─walk─► [ゲートi 待合]
 [ゲートj] ─walk─► [手荷物受取所k] ─walk─► [カーブサイド/駐車場]
```

- 各リンクの歩行距離は、ターミナル内の歩行可能タイル上での BFS 最短距離から算出（建設変更時に再計算）。
- 歩行速度 1.2 m/s（25m/タイル → 約21秒/タイル）。
- 施設同士が歩行可能タイルで接続されていない場合、リンクは存在せず、検証警告を出す。

### 9.3 出発旅客の行程（PaxStage）

| 段階 | 内容 | 遷移 |
|------|------|------|
| `toAirport` | 空港へ移動中（画面外） | 到着時刻分布に従い `atCurb` |
| `atCurb` | カーブサイド到着 | カーブサイド容量に空きがあれば降車 → `walking` |
| `walking` | 次の施設へ歩行 | 距離/速度の時間経過後に次の段階 |
| `queueCheckIn` | チェックイン待ち | 手荷物なし・オンラインチェックイン（既定 40%）はスキップ |
| `checkIn` | 手続き中 | 処理時間後、手荷物を `BagBatch` として仕分けへ |
| `queueSecurity` | 保安検査待ち | |
| `security` | 検査中 | |
| `dwell` | 制限区域で滞留（店舗利用） | 搭乗開始時刻 -10分 またはランダムな滞留時間後 |
| `atGate` | ゲート待合 | 搭乗開始で `boarding` |
| `boarding` | 搭乗中 | 完了で `onBoard`（機体に属する） |
| `onBoard` | 搭乗済み | 離陸で消滅（統計に計上） |
| `missed` | 乗り遅れ | 退出して消滅 |

**到着時刻分布（出発時刻からの逆算）**: 三角分布（最早 -150分、最頻 -90分、最遅 -40分）。LCC は全体に遅め、国際線（後続）は早め。

### 9.4 到着旅客の行程

`deplaning` → `walking` → (`waitBaggage` → 自分の便の手荷物が受取所に届くまで) → `walking` → `toCurb` → 消滅。
手荷物なしの旅客（既定 50%）は受取所をスキップ。

### 9.5 施設処理モデル

各処理施設は **多窓口待ち行列** とする。

- 窓口数 = `min(servers, staffed)`。
- 1グループの処理時間 = `人数 × 1人あたり処理時間`（基準値に ±20% の乱数、`service` ストリーム）。

| 施設 | 1人あたり基準処理時間 |
|------|---------------------|
| チェックイン（手荷物あり） | 90秒 |
| 自動チェックイン機 | 40秒 |
| 保安検査（1レーン） | 20秒 |
| 搭乗 | ブリッジ 2.4秒 / タラップ 4秒 |

- 待ち行列は FIFO。容量（人数）を超えると上流で待機（行列があふれてカーブサイドまで詰まる表現）。
- 待ち時間はグループごとに累積し、満足度・KPIに反映。

### 9.6 旅客満足度（グループ単位、0〜100）

初期値 70。以下で増減し、空港評価の入力となる。

| 要因 | 変化 |
|------|------|
| 待ち時間（累計） | 10分超過分につき -1/分（チェックイン・保安検査） |
| 歩行距離 | 600m 超過分につき -2/100m |
| 待合席不足（立ち） | -5 |
| 店舗利用可能 | +3 |
| 遅延 | 30分ごとに -5 |
| 乗り遅れ | -50 |
| 手荷物待ち | 15分超過分につき -1/分 |

## 10. 手荷物処理

### 10.1 出発手荷物

```
 チェックイン ─► checkedIn ─► (コンベア) ─► sorting ─► madeUp ─► toAircraft ─► loaded
                                         仕分け場の処理容量/分     カート輸送       load作業
```

- 仕分け場: 処理容量（初期 30個/分）。超過分は待機。仕分け場がない/接続されていない場合、チェックインで手荷物受付不可（開港条件）。
- `madeUp` になった手荷物は、該当便の `load` 作業中に積み込まれる。出発時に未積載なら `missed`。

### 10.2 到着手荷物

`unloading`（unload 作業）→ `toClaim`（カート輸送 5分 + 距離）→ `onBelt`（受取所に表示）→ 到着旅客グループの受取で `collected`。

受取所の割り当ては、ゲートから最も近い空きターンテーブル（同時2便まで）。

## 11. 不変条件の一覧（テストと実行時チェックの対象）

| ID | 内容 |
