# 02. ゲーム仕様書

## 1. コアゲームループ

```
 ┌─────────────────────────────────────────────────────────────┐
 │ 1. 建設   滑走路・誘導路・スポット・ターミナル・設備を配置   │
 │ 2. 開港   必須施設チェック（管制塔・滑走路・スポット等）     │
 │ 3. 契約   航空会社の提案から路線・便数を契約 → 便スケジュール │
 │ 4. 運航   到着 → 着陸 → 地上走行 → 駐機 → 地上支援          │
 │           旅客・手荷物処理 → 出発準備 → プッシュバック        │
 │           → 地上走行 → 離陸                                   │
 │ 5. 評価   運航実績（OTP・待ち時間）と収支を確認               │
 │ 6. 改善   ボトルネックを特定し、建設・配置・料金・人員を変更  │
 └──────────────────────────── 1へ ────────────────────────────┘
```

短期ループ（数分）: 混雑や遅延に気付いて人員・割り当てを調整する。
中期ループ（ゲーム内1日〜1週間）: 収支を見て施設を増設する。
長期ループ（ゲーム内数か月）: 空港評価を上げ、大型機・多便数の航空会社を誘致する。

## 2. 時間

| 項目 | 仕様 |
|------|------|
| ゲーム内時刻 | 整数秒（`SimTime`、ゲーム開始 = 0）。日付は `day = floor(t / 86400)` |
| ティック | 1ティック = 1ゲーム秒（固定） |
| 速度 1x | 1実秒 = 1ゲーム分（60ティック/実秒） |
| 速度 2x/4x/8x | 120 / 240 / 480 ティック/実秒 |
| 一時停止 | ティック停止。建設・設定変更は可能 |
| 日次締め | 毎日 00:00 に収支確定・需要更新・契約評価 |

> 1x で1日 = 24実分。初期版は「1日の運航を見届けられる」テンポを重視する。数値は調整項目。

## 3. マップ

| 項目 | 仕様 |
|------|------|
| 座標系 | 整数タイル座標 `(x, y)`、原点左上、x右・y下 |
| タイル寸法 | 1タイル = 25m × 25m（ゲーム上の換算値。速度計算に使用） |
| 初期敷地 | 160 × 112 タイル（4.0km × 2.8km）。外周に購入可能区画 |
| 地形 | `grass`（建設可）, `water`（建設不可、埋立は後続）, `forest`（伐採費用で建設可）, `blocked`（不可） |
| 標高 | 初期版は全域平坦（標高0）。データ上は `elevation` フィールドを予約 |
| 表示 | トップダウン2D（後続で斜め見下ろし表現を検討） |

## 4. 施設一覧（初期版）

サイズはタイル数。費用・維持費は [05_economy_spec.md](05_economy_spec.md) の表を正とする。

### 4.1 エアサイド

| 施設 | 配置方法 | 論理的な役割 |
|------|----------|-------------|
| 滑走路 | 始点〜終点をクリック/ドラッグ（8方向）。幅3タイル固定。長さ（S:≥1.2km, M:≥2.0km, L:≥2.8km）と舗装幅（30/45/60m）の小さい方で対応機種が決まる | 離着陸リソース。両端に進入方向を持つ |
| 誘導路 | 頂点をクリックして折れ線で描く（8方向スナップ）。交差・T字・滑走路横断で自動的に交差点/滑走路入口ノードができる。幅区分 S/M/L、一方通行可 | エアサイドグラフのノード・エッジ |
| ホールディングポイント | 誘導路が滑走路に接する箇所に自動生成（手動で無効化可） | 滑走路占有の境界 |
| 高速離脱誘導路 | 滑走路に斜めに接続（S優先度） | 着陸後の滑走路占有時間を短縮 |
| エプロン | タイルをペイント | スポットを置ける舗装面。走行可能 |
| 駐機スポット | エプロン上に配置。サイズ S(3×3) / M(3×4) / L(5×5)。入口（機首の反対側）が誘導路上にあると接続 | 1機のみ駐機可。プッシュバック方向を持つ |
| 管制塔 | 2×2。滑走路全体を視認できる位置（初期版は距離条件のみ） | 必須施設。レベルで同時処理可能な離着陸数が上がる（後続） |
| 地上支援基地 | 3×3。エプロンまたは誘導路に隣接 | GSEクルーの待機所。スポットまでの距離が作業開始遅延になる |
| 燃料施設 | 3×3 | 給油作業の前提。燃料車の補給拠点 |
| 消防施設 | 3×3（S優先度） | 運航規模に応じた必須条件 |

### 4.2 ターミナル・ランドサイド

| 施設 | 配置方法 | 論理的な役割 |
|------|----------|-------------|
| ターミナル建屋 | 矩形ゾーンを指定（壁・床） | 内部を **非制限区域** と **制限区域** に区分する |
| 保安検査場 | 建屋内、区域境界に配置。1レーン=1×3 | 非制限 → 制限の唯一の通路 |
| チェックインカウンター | 建屋内非制限区域。1台=1×2 | 搭乗手続き + 手荷物預け |
| 自動チェックイン機 | 1×1（S優先度） | 手荷物なし旅客向け、処理が速い |
| 搭乗ゲート | 建屋外壁に配置し、スポット1つ以上と紐付け。ボーディングブリッジ有無を選択 | 搭乗・降機の接点 |
| 待合エリア | ゲート付近に席を配置 | 席数が混雑度に影響 |
| 店舗・飲食 | 制限区域/非制限区域 | 滞留旅客から収入 |
| 手荷物受取所 | 建屋内非制限区域。ターンテーブル 2×5 | 到着手荷物の受取 |
| 手荷物仕分け場 | 建屋に隣接する作業区画 3×4 | 預け手荷物を便別に仕分け（コンベア容量） |
| トイレ | 1×2 | 満足度に影響（S優先度） |
| 道路 | 誘導路と同じ折れ線描画。一般道路 / サービス道路、一方通行可 | 旅客の空港アクセスと車両動線 |
| カーブサイド | ターミナル正面の道路に接して配置 | 旅客の乗降場所。容量超過で到着遅延 |
| 駐車場 | 矩形（S優先度） | 駐車場収入。容量不足で満足度低下 |

## 5. 建設ルール

1. **工期**: 施設は「建設中」状態を経て完成する（例: 誘導路1タイル 2時間、滑走路 3日）。建設中は論理モデルに含めない。
2. **重なり**: 同一タイルに複数の構造物を置けない（ただし誘導路タイル上の標識・照明等は後続でサブレイヤーとする）。
3. **接続性検証**: 配置直後に論理モデルを再構築し、以下を警告として表示する。
   - どの滑走路にも到達できないスポット
   - どのゲートにも紐付かないスポット（リモートスポットとしてバス搭乗可にするのは後続）
   - 保安検査場のない制限区域
   - カーブサイドから到達できないチェックイン
4. **運用中の変更**: 航空機が占有・予約中のタイル/スポットは撤去不可。撤去を予約すると新規割り当て停止 → 空き次第撤去。
5. **クリアランス**: 滑走路の両側1タイルは建物不可（誘導路のみ可）。スポット間は機体サイズに応じた間隔を自動チェック。
6. **撤去**: 建設費の一部（25%）を返金。

## 6. 開港条件

以下を満たすと「開港」でき、航空会社の提案が届くようになる。

- 滑走路 1本以上（完成済み）
- 管制塔 1つ
- 滑走路からエアサイドグラフで到達可能なスポット 1つ以上
- そのスポットに紐付くゲートと、カーブサイド → チェックイン → 保安検査 → ゲートの旅客動線
- 地上支援基地 1つ、燃料施設 1つ

## 7. 航空会社と便

- 航空会社は架空。各社に「タイプ」（LCC / フルサービス / リージョナル）があり、希望機材サイズ・料金感度・品質要求が異なる。
- 開港後、空港評価と施設条件に応じて **契約提案** が届く: `{航空会社, 就航先, 機材サイズ, 週あたり便数, 希望時間帯, 提示料金条件}`。
- 承認すると便スケジュールが生成される。到着便と出発便はペア（同一機材の折り返し）を基本とする。
- 品質条件（OTP、苦情率）を満たさないと契約更新時に便数削減・撤退。

## 8. 空港評価

0〜100 の数値（画面は小数 1 桁で「評価 xx.x」と表示する。星は使わない）。以下の加重平均（詳細は [05](05_economy_spec.md)）。

- 定時運航率（OTP）
- 旅客満足度（待ち時間・歩行距離・混雑・設備）
- 航空会社満足度（ターンアラウンド遅延・スポット割り当て・料金）
- 安全・必須施設充足度

評価は需要・契約提案の質・料金の受容度に影響する。

## 9. モード

| モード | 初期版 | 内容 |
|--------|--------|------|
| サンドボックス | ○ | 初期資金設定可、資金無制限オプション、イベントON/OFF |
| フリープレイ | ○ | 通常の資金制約。破産（資金がマイナスで30日継続）でゲームオーバー |
| キャリア | 後続 | 目標（例: 年間旅客100万人）達成型シナリオ |

## 10. ランダムイベント（初期版）

すべてシード付き乱数で発生し、再現可能。

| イベント | 影響 |
|----------|------|
| 便の出発地遅延 | 到着予定時刻の後ろ倒し（分布で決定） |
| 機材不具合 | ターンアラウンド延長、まれに欠航 |
| 旅客数の変動 | 搭乗率の日次揺らぎ |
| 手荷物の積み残し | 手荷物処理遅延時に確率で発生 |

天候・設備故障・ストライキは後続フェーズ。
