# 40. 出発時刻の制限と最終便の遅れ抑制（仕様案・未実装）

- 状態: **未実装**。本書は要求と判定基準を定める仕様案で、実装方式は指定しない。数値はすべてゲーム内の値で、実在の空港の運用時間・騒音規制を表さない。
- 関連: [docs/31](31_city_models.md)「騒音・夜間制限」（実装済みの離着陸制限）、[docs/11](11_operations_rules.md)（運航ルール）、[docs/36](36_daily_review_and_flight_analysis.md)（遅延の評価）、[docs/39](39_comprehensive_test_audit_and_handover.md) §11（現状の検証結果）。

## 1. 目的

都市設定があるとき、22:00〜06:00 は離着陸できない（docs/31）。しかし現在は「滑走路を使う時刻」だけを制限しているため、夜の最終便が少し遅れると離陸が翌朝 06:00 まで持ち越される。本機能は、**離着陸時刻の制限に加えて出発時刻（スポットを離れる予定時刻）にも制限を設け、最終便に遅れを吸収する余裕を持たせる**ことで、持ち越しを減らす。

## 2. 現状（2026-11-16 の検証結果。docs/39 §11）

| 項目 | 現状 |
|---|---|
| 計画 | 都市設定があると営業時間を 06:00〜22:00 に制限。出発の予定は 06:15〜21:50 に入る（最終出発から制限開始まで 10 分） |
| 到着が遅れて夜間にかかる | 上空で 06:00 まで待つ（実測 約 7.7 時間。待機時間の上限なし） |
| 出発が遅れて離陸が夜間にかかる | 定刻どおりスポットを離れて滑走路の手前まで進み、そこで 06:00 まで待つ（実測 約 7.9 時間。旅客は搭乗したまま）。後ろの出発機は経路を確保できずスポットで一晩待つ |
| 発生頻度 | 到着の遅れ（最大 40 分）だけで最終便が 22:00 を越え得る。3 日間の試験運航で 1 日あたり 0〜3 便 |
| 遅延の指標 | 出発の遅延はスポットを離れた時刻で測るため、滑走路手前で 8 時間待った便も遅延 0 分・定時運航率 100% と記録される（実際の離陸の遅れ 510 分に対し記録は 32〜48 分の例） |
| 手動の便 | 夜間の予定でも追加でき、06:00 まで待つ |

## 3. 用語

| 用語 | 意味 |
|---|---|
| 離着陸制限 | 滑走路を使える時間帯の制限（既存。22:00〜06:00 は不可） |
| 出発時刻制限 | **新設**。出発予定時刻（スポットを離れる時刻）を置ける最も遅い時刻（最終出発時刻） |
| 余裕時間 | 最終出発時刻から離着陸制限の開始までの時間 |
| 持ち越し | 当日中に離陸・着陸できず、翌朝の制限解除まで待つこと |

## 4. 要求

### 4.1 設定

- R1: 都市設定のある会社は「最終出発時刻」を持つ。初期値は「離着陸制限の開始 − 余裕時間」。余裕時間の初期値の案は 45 分（最終出発 21:15）。**値は要決定**（§8）。
- R2: プレイヤーは最終出発時刻を変更できる。範囲の案: 離着陸制限の開始の 15 分前〜120 分前。余裕を大きくするほど夜の便数が減り、小さくするほど持ち越しの危険が増える、という経営判断にする。
- R3: 最終到着時刻は「最終出発時刻 − その機種の折り返し時間 − 計画上の余裕」から導く（別に入力させない）。
- R4: 都市設定のない会社、および本設定を持たない既存の保存データは、現在の挙動のまま変えない。

### 4.2 計画（便の予定）

- R5: 便の計画・計画の見通し・明日の見通しは、同じ規則で出発予定を最終出発時刻以前に収める。
- R6: 時間帯に収まらない便は「予定に入らない便」として数え、計画チェックに理由つきで表示する（黙って消さない）。契約の提案・増便の可否判定（仮想契約チェック）にも同じ判定を使う。
- R7: 手動で追加する便が最終出発時刻を過ぎる場合は、追加前に警告する（禁止するか警告にとどめるかは要決定）。

### 4.3 当日の運航

- R8: **出発の可否はスポットを離れる前に判定する。** 予測される離陸時刻（現在＋後退＋地上走行＋滑走路上の時間の見積もり）が夜間にかかる便は、スポットを離れない。誘導路・滑走路手前を一晩ふさがない。
- R9: R8 で止めた便の扱いを選べる。候補: (a) 翌朝の制限解除まで駐機して出発、(b) 欠航（補償あり）、(c) 回数・費用・住民満足度の低下と引き換えの特例離陸。既定と、プレイヤーが便ごとに選べるかは要決定。
- R10: 到着が夜間にかかる見込みの便は、上空で長時間待たせない。候補: (a) 出発地で待機して翌朝に到着、(b) 他空港へダイバート、(c) 欠航。上空で待つ時間には上限を設ける。
- R11: 最終出発時刻が近い便の遅れを早めに知らせる。予測される離陸時刻が離着陸制限の開始の一定時間前（案: 20 分前）を越えたら警告を出し、運航表から対応（優先・欠航など）を選べる。
- R12: 持ち越しの危険がある便を優先する方針を選べる（地上支援の手配・後退・離陸順）。既定は現状維持（優先しない）とし、有効にしたときだけ順序が変わる。
- R13: 朝の制限解除時は、持ち越した便を通常の間隔で順に処理する。待機していたことを理由に欠航・ダイバートにしない（現状の不具合 D-1 の解消が前提）。

### 4.4 評価・表示

- R14: 遅延の指標に「離陸の遅れ」を加える。スポットを離れた後の待機（滑走路手前・夜間待機）も遅延として数え、原因を「夜間制限」と記録する。
- R15: 日次の振り返りに次を表示する: その日の最終出発便の遅れ、夜間制限で止めた便数、持ち越した便数、夜間制限による欠航・ダイバート数。
- R16: 航空会社の評価と補償は、R14 の遅れと R9・R10 の結果を反映する。重みは要決定。
- R17: 能力ダッシュボード（docs/33）の夜の時間帯は、最終出発時刻を反映した枠で表示する。

## 5. 互換性

- 新しい設定があるときだけ働く（opt-in）。設定のない保存データの運航結果・既存のゴールデンは変えない。
- 保存形式に項目を足す場合は、版・移行・保存/復元テストへの影響を確認する（CLAUDE.md §3）。版を上げるかは実装時に判断する。
- R8・R10・R13 は都市設定のある既存データの運航結果を変える。旧データの扱い（従来の挙動を保つか、新しい挙動に切り替えるか）を先に決める。

## 6. 受け入れ基準（テストの観点）

1. 都市設定あり・既定の余裕時間で、全種類の都市×複数シードの計画に、最終出発時刻より後の出発予定がない。
2. 到着の遅れを最大まで与えた複数日の運航で、持ち越しの便数が現状（1 日 0〜3 便）より減る。目標値は要決定。
3. 予測される離陸が夜間にかかる便は、スポットを離れない。夜間に誘導路・滑走路手前で止まっている機体がない。
4. 夜間（22:00〜06:00）の離着陸が 0 件。境界（21:59:59 / 22:00:00 / 05:59:59 / 06:00:00）で、全機種について判定が実際の離着陸時刻と一致する（現状の不具合 D-2 の解消を含む）。
5. 朝の制限解除後、持ち越した便がすべて通常の間隔で離着陸する（欠航・ダイバートにならない）。
6. 滑走路手前や夜間の待機が遅延として記録され、日次の振り返りの「最終便の遅れ」と一致する。
7. 設定のない保存データで、運航結果が変更前と一致する。
8. 保存・復元をまたいでも、止めた便・持ち越した便の状態が保たれる。

現状を記録したテスト: `tests/audit/d_curfew.audit.test.ts`（合格）、`tests/audit/known-issues/d_curfew*.repro.test.ts`（不具合 D-1・D-2。失敗するのが現状）。

## 7. 先に直す必要がある不具合（docs/39 §11）

- D-1: 夜間制限で待った到着機が 2 機以上あると、06:00 の直前に 2 機目以降がダイバートになる。
- D-2: 大型機が制限解除の 1 秒前（05:59:59）に離陸し、夜間の移動として数えられる。

## 8. 決めること

1. 余裕時間の初期値と、プレイヤーが変えられる範囲。
2. 止めた出発便の既定の扱い（翌朝まで駐機 / 欠航 / 特例離陸）と、便ごとの選択を許すか。
3. 夜間にかかる到着便の既定の扱い（出発地で待機 / ダイバート / 欠航）と、上空待機の上限。
4. 特例離陸を設ける場合の回数・費用・住民満足度への影響。
5. 手動の便を最終出発時刻より後に置くことを禁止するか、警告にとどめるか。
6. 持ち越しの危険がある便の優先を、自動にするかプレイヤーの方針にするか。
7. 離陸の遅れを、既存の遅延指標に置き換えるか、別の指標として並べるか（docs/36 の「実績の遅延」と「評価対象の遅延」との関係）。
8. 都市設定のある既存データに新しい挙動を適用するか。
9. 夜間滞泊（docs/39 §7 の提案 A2）との関係。翌朝まで駐機する便は夜間滞泊と同じ仕組みで扱える可能性がある。
