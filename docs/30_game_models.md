# 30. ゲームのモデル: 天候 5 段階・難易度・航空会社の評価・目標（Phase 12B-3a Part B）

数値はすべて **ゲーム用の値** で、実在の運用基準・安全基準・気象の統計への適合をうたうものではない。

## 0. 有効化（opt-in）と互換性

- 会社の `company.game`（`GameSettings`）があるときだけ新しいルールが働く。**ない会社は従来と完全に同じ**（既存のゴールデン・初回起動のサンドボックスは不変）。
- `GameSettings`: `version 1`、`difficulty`（normal / hard / expert）、`weather`（`levels` = 5 段階 / `legacy`）、`airlineEval`、`goals`、`climate`（temperate / snowy / humid）。
- コアの `createSandboxCompany` / `createCareerCompany` は変更しない。UI の `newGame()` が新しいゲームに既定の設定（標準）を付ける。「新しいゲーム（設定）」（`new-game-setup`）で難易度・気候・ルールを選べ、建設モードの「ゲーム設定」（`tab-settings`）で既存の会社に付け外しできる（以後の運航から。「運航の結果が変わります」の確認）。
- 保存: `game`・`airlineEval`・`goals`・運航状態の `wx` を使うファイルだけ `formatVersion 2`。`SCHEMA_VERSION`・`SIM_MODEL_VERSION` は上げない。読み込みは形を厳格に検査し、不正なら何も適用しない（`checkGameFields`・`checkWxState`。`state.wx` は `game.weather === 'levels'` のときだけ必要）。`importCompany`（自動保存）は不正な任意項目を捨てるだけで止めない。

## 1. 天候 5 段階と予報（`src/core/sim/weather.ts`・`weatherStep.ts`）

- 計画 `weatherPlan(会社のシード, 暦の日, 気候, 難易度)` は純関数（乱数 `${seed}:wx:${day}`）。1 年 = 120 日（30 日ごとに春・夏・秋・冬）。**day 0（最初の日）は全時間が晴れ**。0 時の段階は分布 [50/30/15/5/0 %] から、以後 1 時間ごとに上昇確率 = 基準 × 難易度倍率 × 時間帯補正 × 0.55、下降確率 0.35 のマルコフ連鎖。
- 基準（春/夏/秋/冬）: temperate 0.20/0.24/0.20/0.24、snowy 0.20/0.16/0.24/0.40、humid 0.24/0.40/0.30/0.16。時間帯補正: 5〜9 時 ×1.3、夏の 14〜19 時 ×1.5、冬の夜 ×1.2。種類: 段階 0 晴れ・1 曇り・2 以上は冬（snowy は秋の夜も）= 雪、5〜9 時は 30% で霧、夏の 14〜19 時の段階 3 以上 = 雷雨、他は雨。
- 分布（受け入れ基準、単体テスト）: temperate/normal の 120 日の平均段階 0.5〜1.3、段階 4 の時間は 3% 未満、難しいほど悪天が多い。
- 予報 `forecast`: 6〜12・12〜18・18〜24 時の最大段階と代表の種類。各区間を確率 `1 − 的中率` で ±1 ずらす（乱数 `${seed}:fc:${day}`）。表示: 振り返りの「明日の見通し」（`review-forecast`）、天候カード（`weather-forecast`）、運航計画パネル（`plan-forecast`）。

| 段階 | 呼び名 | 離着陸間隔 | 走行速度 | 着陸復行（着陸の瞬間） | 欠航（時間の初め・2 時間以内の未到着便） | その他 |
|---|---|---|---|---|---|---|
| 0 | 晴れ | ×1.0 | ×1.0 | 0 | 0 | |
| 1 | 曇り・小雨 | ×1.1 | ×0.95 | 0.5% | 0 | |
| 2 | 雨 | ×1.25 | ×0.9 | 1.5% | 0 | 到着の遅れ（20% で +0〜10 分、次の 1 時間の到着便） |
| 3 | 荒天 | ×1.5 | ×0.75（雪は ×0.7） | 4% | 2%/便 | |
| 4 | 悪天 | ×1.9 | ×0.6 | 10% | 8%/便 | 雷雨は地上作業を 20 分ごとに 5 分止める |

- 運航状態 `state.wx`（計画・現在の段階・手動の上書き・専用乱数 `${state.seed}:wx`）。`state.rng`・会社の乱数を消費しない。天候欠航は `cancelTurnaround(…,'weather')`（到着・出発とも cancelled、機体は cannotOperate・理由 weather）。着陸復行は既存の `goAround` を使い、イベントに理由 weather。
- 既存の障害との関係: 手動・シナリオの天候の障害は上書き（雨 = 2、雪・霧 = 3）。ランダムな天候の障害は乱数だけ引いて登録しない（他の障害の乱数列を変えない）。`state.weather.kind`（従来の表示）は段階の種類から写像する。
- 表示: 上部バー（`weather-level-top`）、天候カード（`weather-level`・今日の 24 時間の帯）。1 日スキップは段階 4 の開始でも止まる。

## 2. 難易度

| 難易度 | 悪天の頻度 | ランダムな障害 | 要求定時率 | 初期資金 | 建設費 | 予報の的中率 |
|---|---|---|---|---|---|---|
| normal | ×1.0 | ON・×0.6 | 従来 | 従来（4,000,000 cr） | ×1.0 | 90% |
| hard | ×1.5 | ×1.0 | +5pt | ×0.75 | ×1.1 | 80% |
| expert | ×2.0 | ×1.5 | +10pt | ×0.5 | ×1.2 | 65% |

- ランダムな障害は `game` がある会社の運航だけ ON（`SimSettings.randomDisruptionScale`）。運航のシードは `game` があるとき運航を始める日ごとに変わる（`${site.seed}:ops:${day}`）。
- 欠航の満足度ペナルティ: 1 便 5。天候欠航は 1/4（折り返し 1 回 = 2 便で 2.5）。先行欠航（運航表の行メニュー `fids-cancel-<n>`、補償なし）は折り返し 1 回で 1。
  ペナルティは、その日に運航した便（`flights`）が 0 でも欠航が 1 便以上あれば引く（全便欠航の日を含む。欠航は `flights` に数えない）。この条件は評価が有効な会社の `updateContracts` に適用し、評価なしの従来経路は `flights > 0` のまま。

## 3. 航空会社の評価（`economy/airlineEval.ts`・`evalRules.ts`）

- 12B-1 の評価カードの 7 要素（otp / turnaround / stand / fees / slots / aircraft / pax）の点数を入力に、移動平均 `ema = 0.7·ema + 0.3·点数`（初期 60）を更新する（n/a は更新しない）。
- 満足度の変化 `Σ 重み × (ema − 60) / 10` を [−8, +4] に丸め（欠航のペナルティは別に引く）、要望の達成ボーナスを足す。重み（合計 1）: regional = otp .30 / turnaround .10 / stand .15 / fees .15 / slots .10 / aircraft .10 / pax .10、lcc = .30 / .15 / .10 / .25 / .10 / .05 / .05、fullService = .30 / .05 / .15 / .10 / .10 / .15 / .15。
- 不満: ema < 45 が 2 回の締めで続くと発生、ema ≥ 55 で解消（45〜55 は維持 = ヒステリシス）。「続く」回数は ema が 45 以上の締めで 0 に戻る（45〜55 の帯でも。帯の間は既存の不満だけ維持）。要望: 1 社 1 日 15%（乱数 `${会社のシード}:req:${日}:${航空会社}`）、未達は 1 件まで、期限 14 日。種類: `standFor`（運航できない機種）・`slot`・`contactGate`（フルサービスでバス搭乗が 30% 超）・`otp`（3 日連続で定時率が未達）。達成で +5・7 日間提案確率 ×1.3。
- 契約: 不満 2 件以上は更新で増便しない、aircraft の ema < 45 は運航できない大型機の提案を出さない、slots の ema ≥ 75 は増便依頼の下限を 60 → 50。
- UI: 航空会社カード（`airline-complaint-<id>`・`airline-request-<id>`）、評価の一覧（移動平均と傾向 ▲▼）、新しい不満のアラート（`alert-complaint:…`）、振り返りの航空会社の行（`review-complaint-<id>`）。

## 4. 目標と空港の格（`economy/goals.ts`）

| ID | 条件（その日） | 報酬 |
|---|---|---|
| flights10 | 完了 10 便 | 300,000 cr |
| otp85x3 | 定時率 85% 以上を 3 日連続 | 評価 +2 |
| mov50 | 50 発着 | 1,000,000 cr |
| firstHeavy | L 区分の機体の初就航 | 30 日間 提案 ↑ |
| firstBus | バス搭乗の便を初めて完了 | 200,000 cr |
| rail | 鉄道駅が運用中 | 評価 +2 |
| noMiss | 20 便以上で乗り遅れ 0 | 評価 +1 |
| pax10k | 旅客 10,000 人/日 | 2,000,000 cr |
| mov200 / mov500 | 200 / 500 発着 | 5,000,000 / 10,000,000 cr |
| rating80 | 評価 80 以上 | 30 日間 提案 ↑ |
| otp95x7 | 定時率 95% 以上を 7 日連続 | 3,000,000 cr・評価 +2 |

- 空港の格（次の格の条件を 3 日連続で満たすと昇格、降格しない）: 0 飛行場 → 1 地方空港（20 発着・旅客 2,000）→ 2 拠点空港（80 発着・旅客 10,000・評価 60）→ 3 国際ハブ（200 発着・旅客 30,000・L 区分が運航可能・評価 70）。格ごとに契約提案の 1 日の便数の上限 +1。
- 評価は日次の締めの最後（日報を積んだ後、日を進める前）。報酬の現金は `goals.grants` に記録して資金に足し、日報の営業収支には入れない（日報の `grants` に合計）。日報の `cashEnd`・`kpi.rating` は報酬を加えたあとの値（cashEnd(翌日) − cashEnd(当日) = 翌日の営業利益 + 建設 + 翌日の報酬）。破産の判定も報酬のあと。目標が無効な会社の日報は従来のまま。評価・目標のデータは、ゲーム設定の対応するフラグ（`game.airlineEval`・`game.goals`）があるときだけ効き、フラグのないデータは読み込みで捨て（`importCompany`）、プロジェクトの検証では拒否する。UI: 左列の目標カード（`goals-card`）、「目標」オーバーレイ、上部バーの格（`airport-tier`）、振り返りの「達成した目標」（`review-goals`）、達成のアラート。
