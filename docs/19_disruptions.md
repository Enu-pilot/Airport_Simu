# 19. 天候・障害・運航トラブル（Phase 7）

実装: `src/core/sim/disruptions.ts`、画面は運航モードの「天候・障害」タブ（`DisruptionBoard`）と機体情報の「対応」。

> ゲーム内の簡略化モデルであり、実際の航空管制・安全基準への適合を保証しない。

## 障害の種類と影響

| 種類 | 対象 | 影響 | 早期復旧の費用（cr） |
|---|---|---|---|
| 天候（雨・雪・霧） | 全体 | 離着陸間隔 ×1.2 / ×1.5 / ×1.8、地上走行速度 ×0.9 / ×0.7 / ×0.8 | — |
| 滑走路の一時閉鎖 | 滑走路 | 離着陸に使わない | 400,000 |
| 誘導路の使用不能 | 誘導路 | 経路に使わない（予約中の機体は再探索） | 80,000 |
| 駐機スポットの使用不能 | スポット | 新しく割り当てない | 50,000 |
| 搭乗ゲートの故障 | ゲート | 処理を止め、締切で搭乗を締め切る。そのスポットは後回し | 60,000 |
| 手荷物設備の故障 | 仕分け場・ベルト | 手荷物の処理を止める | 120,000 |
| 地上支援車両の故障 | 車両 | 作業に使わない | 40,000 |
| スタッフの欠勤 | 作業員（人数） | 作業員を減らす | 90,000 |
| 旅客需要の急増 | 全体 | 予約を増やす（座席数が上限） | — |
| 到着便の遅延 | 全体 | 到着時刻を遅らせる | — |
| 整備による一時停止 | 施設 | 閉鎖と同じ | 100,000 |

- 状態: 予定 → 発生中 → 復旧（期限が来る、またはプレイヤーが修理）。開始・終了時刻、対象、量、影響を受けた便・作業・ユニットを記録する。
- 時間の指定がない障害の長さは 2 時間。
- 閉鎖時点で割り当てられていた到着機（未着陸）はスポット・滑走路の割り当てを解除し、別の施設に割り当て直す（不変条件 D1）。
- 同じ滑走路に閉鎖（一時閉鎖・整備による一時停止）が重なった場合、後から始まる障害は先の障害が記録した元の運用モードを引き継ぐ。重なった障害がすべて終わると元のモードに戻る（`closeRunway`）。手動閉鎖だけのときは従来どおり。
- 停止した地上作業は停止理由を記録し、ユニットが戻れば自動で再割り当てされる。
- 運航中はスポット・誘導路ごとに手動の使用停止を設定できる。手動閉鎖と障害・整備による自動閉鎖は別の理由として保存し、一方を解除しても他の理由が残る間は閉鎖を維持する。
- スポットは新規割当から除外する。未着陸機の予約は解放して別のスポットを探索し、駐機中の機体は作業・出発を継続する。誘導路は新しく探索する経路から除外し、すでに走行中の機体はその経路を安全に抜ける。代替路がなければ `noRoute` で待機する。
- 運航画面のスポット・誘導路の詳細に閉鎖状態、理由、使用中の機体数を表示する。閉鎖理由台帳は運航セーブにも含み、旧セーブは既存の閉鎖配列・発生中の障害から移行する。
- 遅延評価では原因ラベルから秒数を推定しない。天候・到着遅延など外部要因を実際に運航へ加えた秒数を便に記録し、実績時刻は変更せず評価対象値だけで控除する（式は [docs/14](14_management_rules.md) §6）。

## ランダムな発生（設定で有効化）

1 時間ごとに種類ごとの確率で発生（天候 4%、到着遅延 2%、誘導路・スポット・ゲート・欠勤・需要 各 1%、滑走路 0.5%）。
長さは 30〜120 分（欠勤 4 時間、需要 3 時間、遅延 2 時間）。乱数はシミュレーションのシードから作るので再現できる。

## プレイヤーの対応

修理（費用を払って早期復旧）、代替スポットへの変更、便の遅延（+15 分）、作業の優先、作業員・車両の配置換え。
代替スポットへの変更（`reassignStand`）は、すでにスポットが割り当て済みの到着機にも効く。指定したスポットを `requestedStandId` に記録し、次の割り当てでホームスポット等より先に評価して、割り当てられたら消す。
欠航・ダイバートは運航ロジック（空中待機の上限・出発不能）で決まる。

## 天候 5 段階（Phase 12B-3a Part B）

会社の `game.weather === 'levels'` の運航では、天候は 5 段階の計画（会社のシードと暦の日から決まる）で決まり、離着陸間隔・走行速度・着陸復行・天候欠航・到着の遅れ・雷雨の作業停止に効く。手動の天候の障害は計画を上書きし、ランダムな天候の障害は登録しない。従来の運航（`state.wx` なし）の 4 種の天候は変わらない。表と式は [docs/30](30_game_models.md)。
