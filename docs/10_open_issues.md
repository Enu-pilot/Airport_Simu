## D. 仕様上の既知の簡略化（明示的に受け入れるもの）

- 空域・進入経路・管制交信は扱わない（進入は待ち行列として抽象化）。
- 後方乱気流間隔は3区分の簡易表。
- 誘導路はタイル中心を結ぶグラフで、機体の翼端クリアランスは区分と幅で近似。
- 旅客は施設間をネットワーク上で移動し、ターミナル内の群衆の物理的な押し合いは扱わない。
- 手荷物処理システム（BHS）はコンベア容量のみでモデル化。

これらは「ゲーム向け簡略化モデル」として仕様に明記し、実際の空港運用の参考には使えない旨をゲーム内に表示する。

## F. Phase 2 で生じた事項

| ID | 事項 | 現状 / 提案 |
|----|------|-------------|
| F-01 | 誘導路は全区間を一括予約する方式にした（Phase 0 案は前方の逐次予約＋デッドロック検出） | デッドロックが構造的に起きない代わりに処理能力は控えめ。混雑時の能力が不足するようなら、追従走行や区間ごとの方向ロックを追加する |
| F-02 | スポットは到着時点で空いているものを割り当てる（時間窓予約なし） | Phase 3 で時間窓予約・手動割り当てを追加する |
| F-03 | 時間倍率を「一時停止 / 実時間 / ×15 / ×60 / ×240 / ×600」にした（Phase 0 案は 1x〜8x、1x = ×60） | 運航を目で追える実時間・×15 と、1日を短時間で回せる ×600 を追加した |
| F-04 | 運航中はレイアウトの編集を禁止し、建設モードに戻ると運航状態は破棄される | 運航中の編集（撤去予約・再探索）と運航状態の保存は後続フェーズ |
| F-05 | 空中の機体は表示上の距離を縮めている（最終進入 = 滑走路端から 40 タイル、待機旋回 = 55 タイル） | 空域を扱わないための表示上の工夫。マップ外になる場合がある |
| F-06 | 離着陸は同じ方向（運用方向）で行い、方向はプレイヤーが手動で切り替える | 風向による自動切り替えは天候の実装時 |
| F-07 | 便の生成は暫定の乱数スケジュール（航空会社・契約なし） | Phase 3/5 で航空会社・契約に基づく生成に置き換える |
