# 10. 未決事項一覧

承認時に方針を決めていただきたい項目を **[要判断]**、Phase 1 以降に実装しながら決めてよい項目を **[実装時]** とする。各項目に本設計での暫定案を記載する。

| ID | 事項 | 暫定案 | 影響 |
|----|------|--------|------|
| A-01 | 技術構成の承認（TypeScript / Vite / PixiJS / React / Vitest / Playwright） | 提案どおり（[07](07_architecture.md) §1） | Phase 1 の全作業 |
| A-02 | 表示スタイル: トップダウン2D か 斜め見下ろし（アイソメトリック）か | 初期版はトップダウン2D。論理モデルは表示と独立なので後から変更可能 | 描画・アセット工数 |
| A-03 | グラフィック素材の調達方法（自作ベクター / フリー素材 / 生成） | 初期版は単純な図形とシルエットを自作（コードで描画） | 見た目の品質 |
| A-04 | 旅客の粒度: 旅客グループ（最大10人）か 個人エージェントか | グループ方式（[04](04_operations_passenger_spec.md) §9.1） | 性能・表現の細かさ |
| A-05 | マップの縮尺（1タイル=25m）と初期敷地サイズ（160×112） | 暫定値のとおり。滑走路が長く画面を占める点はズームで対応 | 操作感・性能 |
| A-06 | ゲーム時間の速さ（1x で 1実秒=1ゲーム分） | 暫定値のとおり | テンポ |
| A-07 | 通貨と金額スケール（架空の円、初期資金20億） | 暫定値のとおり | バランス |
| A-08 | UI言語（日本語のみか、英語も初期版に含めるか） | 日本語のみ、i18n キー化だけ行う | 工数 |
| A-09 | 実在の航空会社・機種名を使わない方針 | 架空名のみ | 法務リスク回避 |
| A-10 | 公開先（GitHub Pages 等）とライセンス | 未定。リポジトリのライセンス選定が必要 | 公開時期 |
| A-11 | パッケージマネージャ（npm / pnpm） | npm | 小 |

## B. ゲームデザイン（実装時に調整可）

| ID | 事項 | 暫定案 |
|----|------|--------|
| B-01 | 管制塔の配置条件（視認性判定をするか） | 初期版は「1つあればよい」。視認性は後続 |
| B-02 | 滑走路の方位を何方向まで許すか | 4軸（0°/45°/90°/135°）を予定。**斜め滑走路はタイル上のグラフ生成が複雑になるため、Phase 2 では直交2軸のみに絞る案も有力** |
| B-03 | エアサイドの GSE 車両の移動を道路グラフで扱うか | 初期版は直線距離近似。車両は見た目上のみ移動 |

## D. 仕様上の既知の簡略化（明示的に受け入れるもの）

- 空域・進入経路・管制交信は扱わない（進入は待ち行列として抽象化）。
- 後方乱気流間隔は3区分の簡易表。
- 誘導路はタイル中心を結ぶグラフで、機体の翼端クリアランスは区分と幅で近似。
- 旅客は施設間をネットワーク上で移動し、ターミナル内の群衆の物理的な押し合いは扱わない。
- 手荷物処理システム（BHS）はコンベア容量のみでモデル化。

これらは「ゲーム向け簡略化モデル」として仕様に明記し、実際の空港運用の参考には使えない旨をゲーム内に表示する。
