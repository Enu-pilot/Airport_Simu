# 35. 複数ターミナル旅客処理・監視仕様（2026-11-14）

## 1. 目的と実装状態

本仕様は、ターミナルが複数ある空港で、便・ゲート・旅客処理施設の所属を一致させ、誤ったターミナルへの誘導や構造上の乗客孤立を検知するためのルールを定める。

**実装済み**
- 出発旅客は搭乗ゲートの接続先ターミナル、到着旅客は到着ゲートの接続先ターミナルに所属する。
- チェックイン、保安検査、待合、搭乗口、および到着通路、手荷物受取、出口は便の所属ターミナル内で選択する。
- 独立ゲート・バスゲートは `GateAccess.terminalId` を所属ターミナルとして扱う。
- ターミナル別の計画能力、館内人数、平均待ち時間を表示する。
- 構造上の経路不成立、運航中の到達不能・長時間滞留を集約アラートに表示し、解消履歴を確認できる。
- 別ターミナル間の連絡設備を使った経路を計画する `findTerminalTransferRoute` API がある。
- 建設・運用中のターミナル間連絡設備は旅客経路グラフに入り、所要時間を伴う歩行として進行する。
- 旅客連絡設備は時間帯ごとに輸送人数を予約し、時間帯能力以下のグループは能力不足時に次の時間帯まで待機する。グループ人数が設備の時間帯能力を超える場合は、複数時間帯にまたがって輸送枠を確保し、確保完了後に通路へ入る。能力未指定時は幅に基づく有限の互換値を使う。
- スポット変更で搭乗ターミナルが変わった出発旅客は、現在位置・処理進捗を維持して接続経路を再探索する。経路がなければ到達不能として記録する。
- ターミナル階段・エスカレーター・エレベーターは、重なる上下階エリア間の経路接続として扱う。
- `PaxGroup.stepFree` が設定された旅客は、階段エリアを除外して経路を探索し、エレベーター等の段差のない接続を利用する。通常生成ではシミュレーション seed とグループ ID 由来の固定判定で約 5% のグループに割り当て、運航乱数列への影響を避ける。テスト・デバッグ用 `addDepartureGroup` は明示設定を優先する。
- 通常旅客への段差なし需要割当と、設備能力を超える旅客グループの通路利用は経路・状態を変え得るため、運航モデルは `skyport-sim-10.3`。10.2 以前の進行中シミュレーションは復元せず、空港・会社データを保持して建設モードで開く。

**未実装**
- ターミナル間・階層移動の完了人数・実待ち時間・混雑の履歴および日次分析への接続。運行画面には連絡設備ごとの時間帯内の予約人数と能力待ち人数のみ表示する。
- 到着旅客を別ターミナルの施設へ移動させる処理。
- 乗継旅客の需要生成、乗継便への割当、国際線の出入国審査・税関。
- 個人単位ではなく旅客グループ単位の簡略モデルで、車椅子利用などの個別属性・専用案内・アクセシビリティ実績 KPI は未実装。

経路計画 API があることだけを、旅客移動シミュレーションが完成している根拠として扱わない。現行の実旅客移動は出発旅客の明示的なターミナル間連絡に限る。設備能力は時間帯ごとの人数予約と待機に反映するが、詳細な混雑・実績レポートは未実装。

## 2. 所属ターミナルの決定

### 2.1 出発旅客

1. 便の搭乗ゲートを確定する。
2. ゲートがターミナルに隣接する場合は、そのターミナルを使う。
3. 独立ゲート・バスゲートの場合は `GateAccess.terminalId` を使う。
4. ゲートがない、または複数ターミナル環境で所属を一意に決定できない場合、ターミナルを推測しない（独立ゲートが 2 つ以上のターミナルに接し、`connectedTo` の指定もない場合は所属を決めず、検証が `GATE_TERMINAL_AMBIGUOUS` を報告する。T-1）。
5. 決定したターミナル内の入口・チェックイン・保安検査・待合・搭乗口だけを候補にする。

単一ターミナルでゲートがない便は旧仕様との互換性のため、そのターミナルを利用できる。複数ターミナルでゲート未割当ての場合は未割当てとして記録し、別ターミナルの施設に流さない。

### 2.2 到着旅客

到着ゲート・降機口の接続先ターミナルを所属先とする。到着通路、手荷物受取所、出口は同じターミナル内から選ぶ。到着ゲート未割当て、降機口なし、出口への経路不成立は到達不能として記録する。

### 2.3 バスゲート

バスゲートの選択は [docs/29](29_remote_stands_and_bus_boarding.md) と [docs/32](32_airline_stand_homes.md) に従う。出発側の搭乗口と到着側の降機口が同一ターミナルに接続していることを条件とし、指定ゲートが利用不能でも別ターミナルへ暗黙にフォールバックしない。リモートスポットに所属ターミナル（`Stand.terminalId`、K-1）を指定すると、候補をそのターミナルのゲートに限る（docs/29 §3.1）。旅客を生成した後のゲートは固定し、閉鎖中は再開を待つ（再開しなければ `facilityClosed`）。これにより、旅客の生成後は 1 便の出発旅客が 1 つのターミナルに留まることが保証される（§7）。

## 3. 施設経路・区域判定

ターミナル内の区域ルールは [docs/12](12_passenger_rules.md) を維持する。

- 一般区域から出発区域へは保安検査場を通過するときだけ移動できる。
- 到着区域から一般区域へは手荷物受取所を出る、または出口へ進むときだけ移動できる。
- 出発区域と到着区域を直接行き来できない。
- 出発旅客の保安検査前経路と保安検査後経路を混同しない。
- 経路のない施設へ旅客を割り当てない。別ターミナルの同種施設で穴埋めしない。

## 4. ターミナル間連絡経路の計画 API

`findTerminalTransferRoute(layout, query)` は、既存のターミナル内 AreaLink と明示された `terminalLinks` を組み合わせて経路を計画する純粋な読み取り API である。通常の出発旅客移動では同じ運用中リンクが `TerminalModel` にも入り、`PaxGroup` が区間ごとに実際の移動時間を進行する。

入力:
- `fromAreaId` / `toAreaId`: 起点・終点エリア ID
- `zone`: 対象旅客区域
- `uncleared`: 保安検査未通過の出発旅客か
- `stepFree`: 階段を利用できない旅客か
- `closedAreaIds` / `closedLinkIds`: 運用上閉鎖されたエリア・連絡設備

探索条件:
- 建設状態が operational の連絡設備だけを使う。
- 旅客区域がリンクの許可区域と両端エリアの区域に一致すること。
- 一方向リンクは指定方向だけ、双方向リンクは両方向を許可する。
- 閉鎖されたリンク・エリアは除外する。
- `stepFree` が指定された場合、ターミナル内の階段エリアと、そのエリアを端点とする連絡リンクを除外する。
- 保安検査未通過の出発旅客は、保安検査を完了せずにターミナル間連絡設備へ入れない。
- 同一コストの探索はエリア ID の辞書順で決定的に選ぶ。

戻り値:
- 経路を構成する全エリア ID
- 通過するターミナル間リンク ID
- 合計所要秒数・距離
- 通過リンクの最小能力。経路上のいずれかのリンクに能力未設定があれば null（未算出）

ターミナル間リンクの距離・所要時間はリンク設定値を使い、ターミナル内 AreaLink は歩行距離 / 既定歩行速度にリンク所要時間を加える。戻り値は経路計画結果であり、旅客を移動させたり、人数を予約したり、能力を消費したりしない。実旅客移動側は当該時間帯の連絡設備の利用人数を予約し、能力超過時は次時間帯まで待機する。

## 5. 監視・判定基準

### 5.1 構造検証

建設・配置検証では、施設の存在だけでなく、利用可能な入口から必須工程を経て搭乗口・出口まで到達できるかを確認する。特に以下を区別する。

- 入口からチェックイン・保安検査へ到達できない。
- 保安検査から搭乗口へ到達できない。
- 到着ゲートから手荷物受取所・出口へ到達できない。
- ゲートの接続先ターミナルと便のターミナルが一致しない。
- 独立ゲート・バスゲートの接続先が不正、未接続、または利用条件を満たさない。
- ターミナル間リンクが未完成・区域不一致・方向不一致で経路に使えない。

構造的に到達不能な状態を、通常の混雑や一時的な施設閉鎖と同じ警告にまとめない。

### 5.2 運航中の監視

運航中は旅客グループの実状態を監視し、構造検証とは別に次を検知する。

| 状態 | 警告基準 |
|---|---|
| 施設待ち | 15 分以上 |
| 処理待ち | 20 分以上 |
| 歩行中の無進捗 | 区間の通常所要時間 × 2 + 5 分。最低 10 分 |
| 到達不能 | 現在位置から次の必須工程への有効経路がない |
| ターミナル不一致 | 便・ゲート・旅客の所属ターミナルが一致しない |

通常の混雑は動線不成立と判定しない。動的な施設閉鎖は構造検証と区別し、旅客が待機・再探索できる状態かを確認する。歩行中の次区間が閉鎖された場合は、旅客の現在位置を維持してその場から再探索する。

アラートは現在継続中の問題と解消済み履歴を区別し、同一問題の重複生成を避ける。

## 6. ターミナル別能力・表示

- 計画能力はターミナルごとにチェックイン・保安検査需要と比較する。
- チェックイン・保安検査の施設能力は設定窓口数と処理秒数から計算する（詳細は [docs/33](33_capacity_dashboard.md)）。
- ターミナルカードは館内旅客数、設定能力、人あたり平均待ちをターミナル単位で表示する。
- 全体値はターミナル別値の合計とする。未割当て旅客を任意のターミナルへ加算しない。
- 計画値・設定能力・実績値を混同しない。

## 7. 不変条件

1. 1 便の出発旅客は1つの所属ターミナルを持つ。バスゲートのスポットでは、旅客生成後はゲートを固定するので、閉鎖・設定変更でも出発旅客が別ターミナルへ移らない（K-1。スポットの変更で固定したゲートが新しい設定を満たさない場合を除く）。
2. 1 便の到着旅客は1つの所属ターミナルを持つ。
3. 所属先が未確定の場合、別ターミナルへ推測で割り当てない。
4. 旅客数・発生時刻・予約人数・ID・搭乗/降機/乗り遅れ判定を、経路監視だけを理由に変更しない。
5. 旅客グループの搭乗・降機・退出人数は各グループ状態の合計と一致する。
6. ターミナルをまたぐ旅客移動には、区域・方向・建設状態に適合する明示リンクを必須とする。
7. 保安検査前の旅客を保安検査後区域へ通さない。
8. 閉鎖・未完成の連絡設備を有効経路として扱わない。

## 8. 次の実装要件

- `PaxGroup` に明示的な移動先・区域・移動状態を追加する。
- 既存の旅客 ID・人数・発生時刻を保ったまま経路再計算する。
- 連絡通路・上下移動設備の待ち行列、処理能力、実利用人数を記録する。
- 乗継需要を生成する場合は、需要生成規則と搭乗便の紐付けを別途仕様化する。
- 実績を日次レビュー・能力分析に連携する。
- 閉鎖・撤去・経路変更時の旅客救済と到達不能判定をテストする。

## 9. テスト観点

- 複数ターミナルでの出発・到着旅客の所属先決定。
- 独立ゲート・バスゲートの接続先反映。
- ターミナルをまたいだ施設への誤割当てがないこと。
- 未割当てゲート時にターミナルを推測しないこと。
- 閉鎖・未完成・区域不一致・一方向リンクの経路判定。
- 保安検査未通過旅客の越境拒否。
- 連絡設備の容量未設定時は幅に基づく有限の互換値が使われ、明示設定時はその能力を越えて同時間帯に利用できないこと。
- 閾値境界（14:59/15:00、19:59/20:00、通常時間の2倍+5分）で監視判定が正しいこと。
- 問題解消後にアラートが解消履歴へ移り、重複しないこと。
- セーブ/ロード後に接続設備・アラート履歴が破損しないこと。
