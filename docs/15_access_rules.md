# 15. 空港アクセス・周辺施設・拡張ルール（Phase 6 実装）

> **重要**: 交通手段の選択・混雑・料金・建設費・土地価格の式と数値は、すべて**ゲーム用の簡略化モデル**です。
> 実在の交通需要予測（四段階推定・ロジットモデルの推定値など）、道路・駅の設計基準、空港の土地取得・料金制度を再現したものではありません。
> 金額はゲーム内通貨 cr。数値は `src/core/economy/balance.ts`（`accessModel`・`accessFees`・`construction.access`・`scale` など）にまとめてあります。

実装: `src/core/access/landside.ts`（道路・鉄道の接続）、`src/core/access/model.ts`（手段の選択とアクセス係数）、
`src/core/access/runtime.ts`（運航中の満車・混雑・乗り場）、`src/core/economy/expansion.ts`（工事・一時閉鎖）、
`src/core/layout/operations.ts` の `purchaseLand`（土地購入）。

## 1. 施設

| 施設 | 配置の条件 | プロパティ | 建設費 / 運営費（日） |
|------|------------|------------|------------------------|
| 一般道路（出入口） | 取得済み敷地の外周に届く一般道路が「一般車の出入口」 | — | 1,500/タイル |
| 業務用道路（サービス道路） | 職員用駐車場・GSE 用。一般車は使わない | — | 1,500/タイル |
| 鉄道（空港連絡線） | 道路ツールの種別「鉄道」。敷地の外周まで敷く | — | 25,000/タイル |
| 駐車場 | 外部につながる一般道路に接し、ターミナルから 24 タイル以内 | 駐車台数 | 800/タイル |
| タクシー乗り場 | 一般道路に接し、ターミナルから 16 タイル以内 | 乗車枠 | 60,000 / 300 |
| バス乗り場 | 同上 | 乗り場数・バス便数（毎時） | 90,000 / 800 |
| 空港連絡駅 | 外部につながる鉄道に接し、ターミナルから 16 タイル以内 | 列車本数（毎時） | 2,500,000 / 6,000 |
| 職員用駐車場 | 外部につながる道路（一般・業務用）に接する | 駐車台数 | 600/タイル |
| 空港ホテル（周辺施設） | 一般道路に接し、ターミナルから 16 タイル以内 | 客室数 | 1,800,000 / 2,000 |

- **接続**: 道路・鉄道は種別ごとに別のネットワークとして扱い、敷地の外周に届く連結成分だけを「外部につながっている」とみなす。
  道路ノードを共有していても、鉄道と道路は互いにつながらない。
- **階層**: 敷地外周への到達は道路・鉄道とも階層を問わない（地下の道路・線路が外周に届けば外部接続＝トンネル状の出入口）。
  ただし階層が変わる区間は接続設備（道路=ランプ、鉄道=鉄道ランプ等）があるものだけを通し、施設は自分の階層の道路タイルに
  接していないと使えない。つまり「地下で外に出てランプで地上に上がる道路網」は地上の駐車場・バス乗り場から使えるが、
  「ランプ無しで地下区間だけが外に届く」場合は地上の施設は使えない。検証警告（`ROAD_NO_ENTRANCE` / `ACCESS_NOT_CONNECTED`）も
  旅客ルート判定と同じ条件で出す（駐車場も `ACCESS_NOT_CONNECTED` の対象。距離の上限も駐車場は 24 タイルで判定と一致）。
- **駅からターミナルへの徒歩の到達**: 外部につながった駅は、次のいずれかでターミナルへ届く場合に使える
  （旅客ルート判定と配置チェックで同じ条件を使う）。
  1. 旅客連絡通路の歩行経路がある（徒歩 16 タイル相当以内）。
  2. **隣接連絡**: 駅がターミナル内エリアと「同じ地図階層」で「辺を共有して」接している（例: ターミナルの地下階エリアに接する地下駅）。
     エリアの階層は「ターミナルの地図階層 ＋ 建物内階」で数える。角だけの接触・階層違いは対象外。徒歩は 1 タイル分。
  3. 従来ルール: 地上の駅はターミナルから 16 タイル以内。
  線路への接続（`STATION_NO_RAIL`）はこれとは別の条件で、隣接連絡があっても線路が敷地外へ届いていなければ駅は使えない。
- 外部につながっていない施設、ターミナルから遠い施設は**使われない**（配置チェックで警告: `ACCESS_NOT_CONNECTED` / `STATION_NO_RAIL` / `ACCESS_FAR_FROM_TERMINAL`）。
- 「車寄せ」= ターミナルに接する、外部につながった一般道路のタイル。送迎（乗降）に使う。

## 2. 手段の選択（ロジット型の簡易モデル）

手段: 自家用車（駐車）・送迎（車寄せ）・タクシー・バス・鉄道・徒歩。各手段 m について、

```
所要時間 = 外部の所要時間 + 施設からターミナルまでの徒歩 + 乗り場の平均待ち + 混雑の遅れ（前日の実績）
運賃     = 基本運賃 + 空港の使用料 × 料金倍率（自家用車は駐車料金 ÷ 1.6人）
効用 U_m = 定数項_m − 0.05 × (所要時間 + 運賃 / 60)
分担率   = exp(U_m) / Σ exp(U)（利用できる手段のみ）
```

| 手段 | 外部の所要時間 | 基本運賃 | 定数項 | 利用の条件 |
|------|----------------|----------|--------|------------|
| 自家用車 | 35分 | 駐車料金 400/台 | 0 | 使える駐車場（台数 > 0） |
| 送迎 | 35分 | 0 | +0.2 | 車寄せ |
| タクシー | 35分 | 2,500/台 | 0 | 使えるタクシー乗り場 |
| バス | 50分 + 待ち 30/便数 | 900 | −0.3 | 使えるバス乗り場（便数 = min(バス便数, 乗り場数 × 6)） |
| 鉄道 | 30分 + 待ち 30/本数 | 700 | 0 | 外部につながった駅 |
| 徒歩 | 120分 | 0 | −1 | 常に（ホテルがあると 5分・定数項 ln(min(1, 客室/400)) − 2） |

徒歩: ターミナルまで 1.2 m/s（1タイル 25m）。

### アクセス係数（需要への影響）

```
A = Σ exp(U_m)                        （アクセス性）
アクセス係数 = min(1.1, 0.3 + 0.85 × (1 − exp(−A / 0.2)))
```

アクセス係数は**搭乗率に掛かる**（docs/14 §5 の搭乗率の式にもう1つ係数が加わる）。
- 小さな飛行場・サンプル空港（駐車場と車寄せのみ）は約 1.0。道路がなければ 0.3（徒歩のみ）。
- 手段を増やすと A は増えるが係数は飽和する（同じ種類の施設を増やしても効果は小さい）。**道路や駅を置くだけで旅客が無条件に増えることはない**。
- 使用料を上げるとその手段の効用が下がり、アクセス係数も下がる。
- 前日の混雑（道路の遅れ・車寄せの遅れ・満車率×10分・乗り場の待ち）が翌日の所要時間に加わり、需要と分担率が下がる。

## 3. 運航中のアクセス

会社つきの運航（キャリア・サンドボックス）でターミナルがあるときだけ扱う（テスト用の会社なしの運航では扱わない）。

### 出発旅客（空港に着く時点）

1. 分担率で手段を抽選する（シード付き乱数）。
2. **自家用車**: 出庫時刻を過ぎた車を出してから、空きがあれば駐車（2日間）し、駐車料金を収入に記録。
   **満車**なら 10分探し回ったあと、送迎・タクシー・バス・鉄道・徒歩から改めて選ぶ（満車として記録）。
3. **バス・鉄道**: その時間帯の定員（バス 50人 × 便数、列車 200人 × 本数）を超えて受け入れることはない。超えるなら、空きのある次の時間帯まで待つ（24 時間先まで探す）。
   24 時間先まで空きがない、グループが 1 時間の定員を超える、定員が 0 のときは、満車の駐車場と同様に送迎・タクシー・徒歩から選び直し、`transitFull` に数える。
4. **車（自家用車・送迎・タクシー）**: 道路の交通量（自家用車 1台、送迎・タクシー 2台（往復）、バスは毎時 便数 × 2台）から
   `遅れ = 外部の所要時間 × 0.15 × (交通量/道路容量)^4`（上限 90分）。道路容量 = 出入口の数 × 900台/時。
   送迎・タクシーは車寄せも同様（基本 10分、容量 = 車寄せタイル × 40台/時）。
5. 施設からターミナルまでの徒歩を歩行時間に加える。
6. 遅れの合計だけ空港に着くのが遅くなる → 手続きが間に合わず**乗り遅れ**になることがある。
7. タクシー・バス・鉄道の使用料（100 / 60 / 80 cr/人 × 倍率）を収入に記録。

### 到着旅客（出口に着いた時点）

- 手段を抽選する。自家用車・送迎・徒歩はそのまま退出（徒歩分を加算）。
- **タクシー・バス・鉄道**は乗り場の待ち行列に並び、乗れるまで退出しない（待ち時間に数える）:
  タクシー = 乗車枠 × 30人/時、バス = 60/便数 分ごとに 50人、列車 = 60/本数 分ごとに 200人。

## 4. KPI・費用（日次締め）

| 項目 | 式 |
|------|----|
| 手段別の旅客 | 出発・到着旅客が使った手段ごとの人数 |
| 駐車場満車 | 自家用車で来て停められなかったグループ数 |
| アクセス道路の遅れ | 車で来た旅客の混雑による遅れの平均（分） |
| 乗り場の待ち | 到着旅客がタクシー・バス・鉄道の乗り場で待った平均（分） |
| アクセス係数 | §2 |
| 旅客満足度 | docs/14 の式 − 0.5 × 道路の平均遅れ(分) − 20 × 満車率 |
| 交通事業者の使用料（収入） | タクシー・バス・鉄道の利用者 × 使用料 |
| 空港ホテル収入 | min(客室数 × 0.9, 旅客数 × 0.03) × 60 |
| 交通施設・ホテルの運営費 | §1 の表 |
| 職員の通勤対策費 | 職員用駐車場の不足台数 × 600。必要台数 = 職員数 × 0.5、職員数 = 作業員 + 整備士 + カウンター + 保安レーン × 2 + ゲート |

- 日をまたいで駐車している車は会社に保存し、次の運航に持ち越す（途中で締めた日の残りは持ち越さない）。

## 5. 空港の成長（土地・規模）

- **土地購入**: 「土地を購入」ツールで敷地外（未取得地）をドラッグ。取得済みの敷地に隣接する土地だけ買える。
  購入した土地は元の地形（草地・森・水域など）になる。費用 = 2,000 cr/タイル × 規模係数。売却は未対応。
  一般道路の出入口は「取得済み敷地の外周」なので、敷地を広げたら道路も外周まで延ばす。
- **規模係数** = min(1.6, 1 + 0.5 × 資産額 / 1億 cr)。建設費（増えた分・払い戻し）と施設維持費に掛かる。
  大きな空港ほど拡張が割高になる（調整・安全対策・管理の複雑さを表すゲーム上の係数）。
  小さな飛行場は約 1.10、サンプル空港は約 1.20。

## 6. 拡張計画と工事（キャリアモード）

- 新しく建設した滑走路・誘導路・道路・スポット・施設は「建設中」になり、工期のあいだ使えない。
  工期: 滑走路 6日、誘導路・道路 1日、スポット 2日、ターミナル 5日、駅 5日、ホテル・格納庫 4日、管制塔・整備・燃料・消防・仕分け場 3日、その他 1〜2日。
- 運用中の施設の**形状**（位置・寸法・向き・ターミナルの階数・滑走路の長さ・幅）を変えると**改修工事**になり、工期のあいだ閉鎖される。
  名前・プロパティ（台数など）の変更は工事にならない。
- **一時閉鎖**: 運用中の施設を選んで日数を指定（1〜7日、費用なし）。
- 工期は**運航した日**（日次締め）ごとに 1日進む。完了した工事は運航を終えたときに運用中になり、次の運航から使える。
- 「元に戻す」で工事も取り消される（費用は編集時と同じ額で精算）。
- 拡張計画タブ: 工事中の一覧、計画中の施設の着工費用と一括着工、**工事の影響**（現在と工事完了後で、運用中の滑走路・スポット数、
  アクセス係数、次の運航日の計画の問題件数を比較）。滑走路が全て閉鎖中だと便は着陸できずダイバートする。
- サンドボックスでは工期はなく、従来どおりすぐに運用できる。

## 7. 前提と簡略化・未実装

- 交通需要は空港を利用する旅客のみ（送迎者・従業員の通勤交通・一般交通は道路容量の中で無視）。
- 道路は区間ごとの渋滞ではなく、出入口の数による全体の容量で扱う。車両の動きは描画しない。
- タクシー・バス・鉄道の事業者・運賃はプレイヤーが直接決めず、空港の使用料（倍率）だけを設定する。
- 駐車場は複数あっても合計台数で扱う（どの駐車場に停めたかは区別しない）。
- 土地の売却、地価の場所による差、公共交通の路線計画は未実装。騒音・夜間制限のゲーム内モデルは [docs/31](31_city_models.md) を参照。
- 運航中の編集（運航しながらの工事）は未対応。工事は建設モードで登録し、運航した日で進む。

## 8. 都市プロフィール（12B-3b、一部実装）

会社の `city` がある場合は、都市距離と道路・鉄道品質からアクセス外部所要時間を計算し、旅客需要上限・日次人口成長にも反映する。式は [docs/31](31_city_models.md)。`city` のない旧会社では従来のアクセス時間・需要式を維持する。

駅・列車頻度・定員・乗り場待ち・収支は Phase 6 の既存モデルを使う。駅ごとに各停/快速/特急を設定でき、都市鉄道品質の要件、外部所要時間、運賃加算、運営費倍率へ反映する。数値と前提は [docs/31](31_city_models.md)。都市鉄道への追加投資は未実装。

## フェーズ 4 の追加（区間能力モデル）

レイアウト設定 `accessCapacityModel: 'segment'` で、道路・線路を区間ごとの能力で数えるモデルに切り替えられる（既定は従来の集約モデルで、結果は変わらない）。区間の能力は明示値か車線数・線路数から決まり、出入口から目的地までの最も太い経路のボトルネックが上限になる。運航中の遅れは区間ごとの混雑（BPR 型）で計算する。駅のホーム数と、駅からターミナルへの連絡通路の能力も鉄道の受け入れ上限に入る。仕様は [docs/44](44_hub_and_international.md) §5。
