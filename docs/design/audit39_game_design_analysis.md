## 1. 現在のゲームループ（コードと文書から）

### 1.1 ループの骨格

```
建設（費用即時・工期あり=キャリア） → 経営（契約提案の受諾/拒否・料金倍率・運用時間・便数変更）
  → 運航（ライブ介入 or 1日スキップ） → 0:00 締め（日報・満足度・評価・提案・目標・格・都市成長）
  → 振り返り（収支・遅延原因・便別分析・航空会社評価・明日の見通し/予報） → 建設 or 次の日
```

- 締め: `settleDay`（src/core/economy/ops.ts:514〜）→ 航空会社評価（ops.ts:540-546）→ `updateContracts`（company.ts:507）→ `nextRating`（ops.ts:487-491）→ `generateOffers`（company.ts:430、ops.ts:551）→ 目標・格（goals.ts:116）。
- 1 日のループ・スキップ・振り返り: docs/14 §10、docs/36（12B-2 実装済み）。
- 天候 5 段階・予報・難易度・評価要素/不満/要望・目標/格: docs/30（12B-3a Part B 実装済み、opt-in = `company.game`）。
- 都市・需要上限・人口成長・駅別列車種別・騒音ポイント・22–06 時の計画除外: docs/31（部分実装、`company.city`）。
- 能力ダッシュボード・仮想契約チェック: docs/33（部分算出）。

### 1.3 成長

- 目標 12 個（goals.ts:72-85）、格 0〜3（goals.ts:89-96、3 日連続で昇格・降格なし）。
- 格の効果は **契約提案の 1 日便数上限 +格**（evalRules.ts:45、company.ts:458）と上部バーの表示（App.tsx:339）のみ。
- 都市: 人口成長 最大 +0.07%/日（city.ts:136-152）。道路整備度は人口 1.5 倍・2 倍で自動 +1、鉄道整備度は上がらない（docs/31「次の作業」1・3）。

## 3. 提案

各提案の形式: 内容 / 価値（判断・緊張・視点: 経営=E、運航管理=O、パイロット=P、マニア=M）/ ループと継続への効果 / 依存 / 課題・リスク / 規模 / 優先度。関係: 新規 / 拡張 / 既に計画（その場合は不足分のみ）。

共通の制約（全提案）: opt-in（`company.game` の新フラグ or 新データがあるときだけ）、既存ゴールデン・既存 e2e・`SIM_MODEL_VERSION` 不変、core で Math.random/Date.now 不使用、専用乱数（`${seed}:<用途>:${day}`）で既存乱数列を乱さない、`formatVersion` の段階的引き上げ（docs/21・27）。

### (a) 成長と解放

**A1. 格による「機能の解放」（格に中身を）** — 関係: 拡張（docs/30 §4 の格。現状は便数上限 +1 のみ）
- 内容: 格ごとに解放される建設・契約の種類を明示する（例: 格 1 = 夜間滞泊契約・ホテル、格 2 = 拠点航空会社・乗継・ワイドボディ常設、格 3 = 国際線（CIQ）・貨物）。解放前は「次の格で解放」と表示し、目標カードに条件を出す。
- 価値: E。「次は何ができるようになるか」が長期の動機になる。格 3 の名前と中身の矛盾（T1）を解消。
- 依存: goals.ts、Toolbox の表示、generateOffers（解放済みの契約種別だけ提案）。
- 課題: サンドボックスと `game.goals` なしの会社は全解放（従来と同じ）。解放の対象機能自体が A2〜A6 で必要 → A1 は「器」として先に作り、中身は機能の実装に合わせて増やす。
- 規模: S（器）〜M。優先度: **P1**（他の解放系の前提。安い）。

**A2. 夜間滞泊（ナイトステイ）と朝一番の出発** — 関係: 新規（docs/09:155「航空機配置/夜間滞泊は未実装」）
- 内容: 夕方到着→翌朝出発の契約パターン。夜間はスポットを占有し、駐機料が入る。朝 6〜8 時に出発が集中（朝の波）。格納庫・整備施設があると夜間整備で翌日の機材不具合確率が下がる、などの効果の候補。
- 価値: E（駐機料・スポット投資の採算、T5 の解消）、O（朝の波の処理、夜のスポット割当）。都市の夜間制限（docs/31）と組むと「門限の直前に到着・直後に出発」の緊張が生まれる。
- 効果: スポット数の意味が「ピーク時の同時数」から「夜間在泊数＋ピーク」に変わり、建設判断が増える。T6（格納庫）にも役割を与えられる。
- 依存: planning.ts（2 日にまたがる便の組）、sim の日境界（0:00 締め・settleDay）、建設モードへ戻るとき運航状態を捨てる現行の流れ（simRunner）、能力ダッシュボードのスポット需要。
- 課題（大）: 現在は運航開始のたびに sim を作り直すため、夜間に駐機中の機体の継続をどう表すか。選択肢: (i) 「仮想在泊」— 締めで在泊を記録し、翌日の運航開始時に機体をスポットに置いた状態で生成（軽い、決定的）、(ii) 運航状態を日をまたいで保持（重い、保存・建設モードとの整合が難しい）。(i) を推奨。在泊中のスポットを建設で消した場合の扱い（強制移動・欠航）を決める必要がある。
- 規模: L。優先度: **P1**（ただし (i) の軽量版で。駐機・スポット・格納庫・夜間制限を一度に意味あるものにする費用対効果が最大）。

**A3. 拠点航空会社（ホームベース）** — 関係: 拡張（docs/32 のホームスポットは日次・自動・物理占有なし）／新規（契約形態）
- 内容: 航空会社が N 機を常駐させる「拠点契約」。条件: 夜間在泊スポット・整備施設・作業員。見返り: 長期・多便数・提案の優先。リスク: 1 社依存（満足度が下がると大量撤退）、拠点会社は専用スポット/ターミナルを要望。バンク（波）型ダイヤ（同時に多数到着→乗継→同時に出発）の素地。
- 価値: E（交渉力と依存のトレードオフ）、O（バンクの処理）。
- 依存: A2 必須、airlineEval（要望の種類に「専用スポット」「整備」を追加）、docs/32。
- 課題: 契約の形の追加（保存形式）、撤退時の大きな収入減のバランス。
- 規模: L。優先度: P2（A2 の後）。

**A4. 乗継旅客** — 関係: 既に計画（docs/34 §「次」1、docs/35:24・142、docs/09 次の優先 1）。不足分のみ提案
- 既存計画は「ターミナル間移動の実行」が中心で、**ゲーム上の役割** が未定義。追加すべき点:
  - 乗継旅客は都市のアクセス需要を使わない → 地方都市で需要上限（T3）を越える成長経路になる（成長の第 2 軸）。
  - 最小乗継時間（MCT）を空港の指標として表示し、航空会社（拠点会社）の評価要素にする。
  - 乗継失敗（コネクション切れ）を補償・満足度に反映。乗継手荷物（docs/13:85 未実装）の積み残し。
- 依存: passengers.ts の旅客生成（到着便と出発便の紐付け）、findTerminalTransferRoute、A3（バンクがないと乗継の意味が薄い）。
- 課題: 旅客生成の乱数順の非干渉、決定性、到着遅延時の乗継判定、性能（旅客グループ数の増加）。
- 規模: XL（簡易版「乗継は人数だけ移す」でも L）。優先度: P2。

**A5. 国際線（出入国審査・税関）** — 関係: 既に計画（docs/09:154、docs/12:78、F-PAX-07）。データ（国・就航先・評価条件）は実装済み（registry.ts:153-160）。不足分:
- ゲーム上の役割: 格 3（国際ハブ）の中身、国際線は単価が高く（使用料・免税店の店舗係数）、旅客の到着が早い（docs/04:253）＝ターミナルの滞在が長い。
- レイアウト判断: 国際/国内の区域分け、スイングゲート（どちらにも使えるが切替に時間）、CIQ 施設の能力と配置。
- 簡易版: 既存の手続きの列（チェックイン→保安）に「出国審査」「入国審査」「税関」を工程として追加し、ゲート/スポットに国際/国内/兼用の属性。
- 課題: 区域（制限区域が 2 種類になる）の検証規則、旅客経路の分岐、計画分析（INTERNATIONAL_PROCESSING_REQUIRED は既にある: planning.ts の PlanIssueCode）。
- 規模: XL（簡易版 L）。優先度: P2（A1 と組んで格 3 の目玉。PO 確認後）。

**A6. 貨物** — 関係: 既に候補（docs/09 後続「貨物」、F-OPS-13）。データ先行（registry.ts:133-134）
- 内容: 貨物機契約（旅客なし、貨物上屋の処理能力、トラックのランドサイド交通）、夜間便が多い（騒音・門限と対立）、旅客需要と独立の収入源（地方都市向け）。
- 評価: 新しい施設・資源・UI が多く、旅客側の未完成部分（乗継・国際）より先にやる理由が弱い。「たくさん離発着」には貢献するが、運航の見た目は旅客便と同じで遊びの差が出にくい。
- 規模: XL（簡易版「旅客なし便＋上屋能力」で L）。優先度: **P3**（A2 の夜間在泊ができた後の追加として検討）。

**A7. 施設の格上げによる解放（管制塔レベル・消防の区分）** — 関係: 新規（docs/02 §4.1「管制塔: レベルで同時処理が上がる（後続）」「消防: 運航規模に応じた必須条件」が未実装、T6）
- 内容: 消防施設の区分（ゲーム値）で受け入れ可能な最大機体区分を制限、管制塔のレベルで 1 時間の発着上限（計画の RUNWAY 基準値の係数）を上げる。
- 価値: E。安い「解放」の段階が増える。既存の operableTypes に条件を 1 つ足すだけで効果が出る。
- 課題: 既存の会社・レイアウトの結果を変えないため opt-in 必須（従来は消防なしでも L 機が飛べる）。
- 規模: S〜M。優先度: **P1**（A1 の中身として最安）。

## 4. 推奨の順序（効果/工数）

1. **第 1 波（S〜M、主に表示と小さな規則。2〜3 週間相当）**: C1（地方都市のバランス確認と修正）→ D1（満足度の内訳）→ D2（契約の先行き）→ B1（搭乗率を評価に）→ A1＋A7（格の解放の器と、消防・管制塔の格上げ）。
   目的: 既存の仕組みの「見えない結果」を見えるようにし、成長の到達点に中身を入れる。
2. **第 2 波（M、判断の層）**: B2（交渉）→ B4（投資効果のプレビュー）→ F1（ゲートホールド）→ E1（目標の連鎖）→ F2 簡易（専用指定）。
   目的: 便数・旅客・能力に結びつく判断を、経営と運航の両方に 1 つずつ増やす。
3. **第 3 波（L、成長の新しい軸）**: A2 軽量版（仮想在泊）＋B7（夜間の経営判断の残り）→ A3（拠点航空会社）→ A5 簡易（CIQ 工程・国際区分）→ A4（乗継）。
   目的: 「大きくなる」ことの中身を増やす。A2 が A3・A4・A6・B3 の土台。
4. **並行・余力**: 3b の「出来事」カタログ（既に設計済み。T7 の都市イベントを出来事に置き換える）、C2（立地の型）、C3（季節）、E2（挑戦シナリオ）、F3（風向）。A6（貨物）は最後。

Phase 13〜16（曲線誘導路・実寸機体・3D）との関係: 上記はほぼすべて economy/planning/passengers 側で、幾何の作業と衝突しにくい。F3 だけは滑走路の運用（Phase 12）と天候に触れる。

## 5. PO への確認事項

1. **新規ゲームの都市の既定**: 地方都市のままでよいか（T3: 格 1 の旅客 2,000 人/日に届きにくい見込み）。中核都市を既定にする／格の条件を都市に連動させる／乗継を成長手段にする、のどれか。先にヘッドレス実行での確認を推奨。
2. **格を「解放」の段階にするか**（A1）。する場合、サンドボックスは全解放でよいか。
3. **夜間滞泊の表し方**（A2）: 軽量の「仮想在泊」（翌朝の運航開始時に機体を置く）で十分か、運航状態を日またぎで保持する本格版が必要か。
4. **国際線と乗継の優先順位**（A4/A5）: 格 3「国際ハブ」の目玉としてどちらを先にするか。
