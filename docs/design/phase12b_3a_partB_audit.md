## 指摘

### 重要
- **M1 その日の便がすべて欠航した航空会社に、欠航のペナルティがかからない。** `src/core/economy/company.ts` の `updateContracts` が `cancelPenalty(r)` を `if (r && r.flights > 0)` の中だけで呼ぶ（`flights` は運航した便の数）。docs/30 §2 では欠航 1 便あたり 5（天候は 1/4、事前欠航は 1/10）。再現: 事前欠航 2・運航 0 → 期待 −1・実際 0、天候欠航 2・運航 0 → 期待 −2.5・実際 0。運航が 1 便あれば正しく −1。
  - 修正案: `r` があれば常に `cancelPenalty` を適用する。**注意**: 従来の分岐（ゲーム設定なし）にも同じ条件があり、PR 前からの挙動。従来の結果を変えないため、修正はゲーム設定（`game.airlineEval`）がある経路に限るのが安全。従来の経路も直すならゴールデンへの影響を確認し、PO に確認する。

### 軽微
- **m1 不満の連続回数が「連続」になっていない。** `src/core/economy/airlineEval.ts` は移動平均が 45 未満で `low[k]` を増やすが、45〜55 の帯では 0 に戻さない（55 以上でだけ戻す）。仕様は「45 未満が 2 回の締めで続く」。再現: 50 → 44 → 45.8 → 41.1 で、2 日目が帯の中なのに 3 日目に不満が出る。修正案: 45 以上で `low[k] = 0`（解除は従来どおり 55 以上）。
- **m2 `game.weather: 'legacy'` なのに `state.wx` を持つ保存データが受理される。** 仕様では `wx` は `levels` のときだけ。`stepWeather` は天候の方式を見ないので、手で編集したファイルでは従来の設定のまま 5 段階の天候で動く。修正案: 設定と状態が食い違えば拒否する。
- **m3 着陸復行の回数が段階に対して単調でない（標本が少ない）。** 段階 0〜4 で 0/0/3/4/2（欠航は 0/0/0/2/8 で単調）。段階 4 は着陸が少なく、1 回あたり 10% の率が見えていない。長い運航で確認するとよい（不具合ではない可能性が高い）。
- **m4 下限 `DELTA_MIN = −8` に届かない。** `evalDelta` の最小は −6（重みの合計が 1）。害はない。ドキュメントの値を実際に合わせるか、重みを見直す。

## 確認できたこと（問題なし）
- 天候: 同じシード・日で計画と予報が同一。難易度に関係なく 0 日目は晴れ。分布（温帯、120 日 × 5 シード）の平均段階は normal 0.60 / hard 0.95 / expert 1.34、段階 4 の割合は 1.4% / 4.2% / 8.4%。予報の的中率（300 日）は 0.92 / 0.83 / 0.71（公称 0.90 / 0.80 / 0.65 以上）。離着陸間隔・走行速度・着陸復行の率は段階に対して単調。段階 4 の雷雨が 3 日続いても作業は止まりきらない（98 便完了）。
- 欠航した便の後始末: スポット・横断・経路・作業・バスの運行を持ち続ける機体なし（不変条件を 30 ティックごとに検査）。
- 難易度: 初期資金 4.0M / 3.0M / 2.0M、建設費 ×1 / 1.1 / 1.2、要求定時率 +0 / +0.05 / +0.10、障害の倍率 0.6 / 1 / 1.5。
- 評価: 移動平均は有限、欠けた項目は更新しない、55 以上で不満が解除され帯の中では保たれる、要望は航空会社ごとに最大 1 件・14 日で期限切れ。事前欠航のペナルティは運航がある日に 1 回だけ。
- 目標と空港ランク: 報酬は 1 回だけ、条件を 3 日続けて満たすとランクが上がる、目標の ID は重複なし。
- バスの故障: 迎え・乗車・走行・降車のどの段階で故障しても不変条件が保たれ、修理後に運行が止まったままにならない。走行中の故障は救援で完了。全台故障 20 分でも修理後に再開。
