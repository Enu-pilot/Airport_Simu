# 45. 施設・構造物のライフサイクル実装標準

> 文書種別: 共通実装基準  
> 状態: PO承認済みの共通基準（2026-11-19）  
> 適用範囲: 建築物、固定設備、車両・移動機材、道路・通路・配管・電力等のインフラ/ネットワーク、およびそれらを利用する運営機能  
> 関連正本: [42. 実装ロードマップ](42_implementation_roadmap.md)、[Phase 6 総合実装計画](implementation/planned/phase6_airport_facility_expansion_plan.md)

## 1. 目的と位置づけ

本書は、Airport_Simu に施設・構造物・設備・車両・インフラを追加または変更するときに共通して適用するライフサイクル基準である。

構造物を「配置できるオブジェクト」として実装して終わらせず、解放、建設、設備構成、接続、稼働準備、能力算出、実際の運航/業務計算、実績評価、保守まで一貫して扱う。

本書は新規実装の設計・レビュー・受入基準であり、既存施設が全段階に対応済みであることを意味しない。既存施設の対応状況はコード・テスト・各機能仕様を監査して別途記録する。未実装の基準を現行仕様として記載しない。

### 1.1 文書の役割と優先関係

- 本書: あらゆる施設・設備の共通ライフサイクル、状態分離、能力とSimulation接続、最低限の受入基準を定義する。
- docs/42: PO承認済みの全体優先順位・Phase状態・要求・受入条件を管理する。
- Phase 6計画: P0〜P4の対象範囲、タスクID、既存Phase 5/A6との依存関係を管理する。
- docs/11〜44等の機能別仕様: コードとテストで確認した各機能の現行挙動を記録する。
- 個別実装計画: 特定施設・機能の詳細設計、作業分割、進捗、検証結果を記録する。

本書と既存仕様が食い違う場合、既存挙動を本書に合わせて独断で変更しない。コード・テスト・保存データへの影響を調査し、必要な仕様変更はPO判断を得る。

## 2. 基本原則

1. **解放と設置を分ける。** 空港格や機能条件を満たしても、施設・車両・設備を自動配置しない。
2. **設置と稼働を分ける。** 建設完了だけで処理能力が有効になるとは限らない。
3. **物理的な存在と接続を分ける。** 必要な通路・道路・配管・電力・通信等につながらない設備は、その接続を必要とする機能を提供しない。
4. **能力の算出とSimulation利用を分ける。** 能力値を画面に表示しただけで、実際の処理へ組み込んだことにしない。
5. **理論能力・有効能力・実績を分ける。** 設備の名目能力を、そのまま処理実績として扱わない。
6. **施設種別ごとの違いを維持する。** 建物・固定設備・車両・ネットワークを同じデータ型や同じ能力式へ無理に押し込まない。
7. **共有資源を一度だけ計上する。** 人員、車両、道路、通路、電力、燃料等を複数機能で重複使用・重複計上しない。
8. **計算根拠のない値を作らない。** 式・単位・対象時間窓・データが揃わない値は「未算出」とする。
9. **既存の保存・決定性を守る。** 旧保存、乱数消費、Simulation結果、既存テスト/ゴールデンへの影響を実装前に評価する。
10. **段階導入する。** すべての施設へ一度に詳細な在庫・個人・車両挙動を追加せず、必要な運営効果から実装する。

## 3. 施設・資産の分類

実装着手時に、対象がどの資産種別に属するかを明確にする。複数種別が連携する場合は、責務を分けて関連付ける。

| 資産種別 | 例 | 管理する主な情報 | 注意点 |
|---|---|---|---|
| 建築物・区画 | ターミナル、格納庫、貨物上屋、GSE基地、倉庫 | 用途、面積、階層、収容範囲、親子関係、建設/稼働状態 | 建物の面積を設備能力や車両数として扱わない |
| 固定設備 | チェックイン機、保安検査機、仕分け機、GPU/PCA、ポンプ、充電器 | 台数、仕様、処理速度、対象、接続先、保守状態 | 設置台数と実際に稼働できる台数を区別する |
| 車両・移動機材 | 給油車、トーイング車、ランプバス、ローダー、フォークリフト | 個体/台数、容量、基地、要員、移動/作業/充電/故障状態 | 同一車両の同時二重割当を防ぐ |
| インフラ・ネットワーク | 道路、歩行路、燃料管、電力、給排水、通信 | ノード/区間、接続、容量、供給元/先、流量、閉鎖/障害状態 | ネットワークは接続経路・共有区間・容量を評価する |
| 運営機能・サービス | 給油、旅客検査、貨物荷役、消防、商業営業 | 対象業務、稼働条件、必要資産、処理結果 | 施設オブジェクトそのものと業務処理ロジックを分離する |

例: GSE基地は建築物、トーイングトラクターは車両、共用充電器は固定設備、サービス道路はインフラ、プッシュバックは業務機能である。複数の資産が業務を構成する場合、施設を置いただけで業務が完了した扱いにしない。

## 4. 共通ライフサイクル：10段階

すべての施設に10段階を同じUI・同じ状態遷移で強制するものではない。車両は建設でなく購入/導入、ネットワークは接続自体が中心、既存施設は一部段階を既に満たしている場合がある。各段階の適用要否と完了条件を対象計画に明記する。

| 段階 | 名称 | 主な処理 | 次段階へ進む条件 |
|---:|---|---|---|
| 1 | 解放 | 空港格、研究/契約/シナリオ条件、機能ON/OFFを確認 | プレイヤーがその資産・機能を選択可能 |
| 2 | 建設場所・導入条件の判定 | 敷地、階層、寸法、干渉、アクセス、設置制約を検証 | 配置/導入可能と判定される |
| 3 | 建設・購入・設置 | 費用、建設時間、完成状態、車両導入を処理 | 物理資産が利用可能な状態で存在する |
| 4 | 設備構成・設定 | 設備台数、仕様、対象範囲、営業時間、容量等を確定 | 提供する機能と構成が確定する |
| 5 | 接続 | 通路、道路、配管、電力、給排水、通信、対象区域との接続を確認 | 必須経路・ネットワーク接続が成立する |
| 6 | 稼働準備 | 人員、資格、車両、燃料、電力、資材、保守状態、運用時間を確認 | 必要な稼働条件を満たす |
| 7 | 能力算出 | 理論能力・有効能力・制約・単位・根拠を算出 | 算出可能な能力が共通契約で参照できる |
| 8 | 業務/Simulationへの接続 | 旅客・航空機・手荷物・貨物・地上支援等の処理が能力を参照 | 実際の処理結果に能力が反映される |
| 9 | 実績計測・経営評価 | 需要、実績、使用率、待ち、滞留、収益、ボトルネックを計測 | 同じ定義の指標をUI/日報/分析で参照できる |
| 10 | 維持・拡張・停止・撤去 | 点検、劣化、故障、修理、増設、閉鎖、撤去を管理 | 状態変化が能力・Simulation・経営へ反映される |

### 4.1 段階1：解放

- 空港格による施設/機能の解放は、既存の5-20の8段階体系と unlocks/features の一元管理を使う。新しい格番号・独自解放テーブルを作らない。
- 「格による解放」「会社設定による機能有効化」「建設/購入」「接続」「稼働」は別々の条件とする。
- 解放条件を満たしても、既存施設・車両・契約・便を自動生成しない。自動付与が必要な場合は別の明示仕様・PO承認を得る。
- サンドボックス、旧保存、格移行、機能OFF時の既存挙動を5-20および保存仕様に従って確認する。

### 4.2 段階2：建設場所・導入条件の判定

- 敷地境界、階層、建物内外、寸法、占有範囲、他資産との干渉、必要なアクセス、配置可能な地面/区域を確認する。
- 建物・固定設備・車両基地・道路/配管等で検査項目を分ける。
- 設置可能/不可能だけでなく、不可の場合の理由を表示できるようにする。
- 既存の幾何・階層・接続・Undo/Redo・配置検証を再利用し、表示だけの検査を追加しない。

### 4.3 段階3：建設・購入・設置

- 建設中/完成、購入待ち/導入済みなど、資産種別に適した物理状態を持たせる。
- 建設中や導入前の資産を稼働能力へ含めない。
- 即時設置か時間経過型工事かは施設別に定義する。共通基盤のためだけにすべてを工事化しない。
- 費用・建設期間・維持費は既存経済モデルと整合させ、未決の値を独断で確定しない。

### 4.4 段階4：設備構成・設定

- 建築物と内部の固定設備、車両基地と所属車両、ネットワークと接続設備を別資産として扱う。
- 台数、処理速度、容量、対応機種/対象、稼働時間、利用区域など、能力式に必要な設定を保持する。
- 設備台数・設備仕様の変更が、どの能力・Simulation・保存値へ影響するかを明示する。
- 既存の建物内設備、複合体、階層モデルを再利用し、同一設備の二重登録を避ける。

### 4.5 段階5：接続

- 施設の機能に必要な接続種別を列挙する。例: 旅客通路、サービス道路、誘導路、燃料配管、電力、給排水、通信、貨物搬出入。
- 接続の有無だけでなく、経路、接続先、容量、通行可否、閉鎖、階層、方向、共有区間を評価する。
- 物理的に隣接していることと、論理的/ネットワーク上で接続されていることを混同しない。
- 必須接続が欠ける場合、対象機能の有効能力を制限または0とし、その理由を記録する。接続が不要な資産は NotRequired として明示する。
- docs/34・docs/35・docs/15等の接続/経路ルールと重複する別ネットワークを作らない。

### 4.6 段階6：稼働準備

能力・業務の成立に必要な資源を確認する。対象に応じて以下から必要なものを選ぶ。

- 人員数、資格、勤務時間、同時作業可否。
- 車両・移動機材の台数、容量、対応機種、位置、稼働/移動/充電/修理状態。
- 電力、燃料、水、資材、部品、廃棄物処理等の供給/受入。
- 営業時間、運用時間、夜間制限、施設閉鎖、工事予定。
- 故障、点検、整備、Work Order、保守による利用制限。

人員・車両・設備・供給源は予約/割当の単位を明確にし、同じ資源を複数業務で同時に使用しない。条件が満たされない場合、施設の存在状態は保ったまま NotReady 等の理由を示す。

### 4.7 段階7：能力の付与・算出

能力は共通の意味・メタデータを持たせるが、計算式は領域別に実装する。Phase 6 F6-01の共通能力契約と既存の算出源/adapterを再利用し、既存式を画面や新APIで独立に再計算しない。

| 指標 | 定義 |
|---|---|
| 理論能力 | 設備構成・仕様・規定処理時間等から求める名目能力 |
| 有効能力 | 接続、稼働状態、人員、車両、供給、保守、時間帯等の制約を反映した現在利用可能な能力 |
| 需要 | 対象時間窓に処理が必要な量。計画需要と実績由来需要を区別 |
| 実績処理量 | 同じ単位・対象時間窓で実際に完了した量 |
| 使用率 | 需要または実績を有効能力で割った値。分母が0/未算出なら数値を出さない |
| 待ち・滞留 | 待ち人数、待ち時間、待ち台数、未処理貨物等。測定できる指標だけを出す |
| 能力余力 | 有効能力から需要を差し引いた値。同じ単位・時間窓の場合のみ算出 |

能力表示には必ず単位、対象時間窓、算出根拠、対象範囲を付ける。例: 人/時、個/時、個/分、発着回/時、機/夜、m³/時、保管m³、台/時、kW、m³/日。単位が異なる指標を総合能力として加算しない。

#### 直列・並列・共有資源の集計規則

- 直列工程は、同一フロー・同一単位・同一時間窓で接続された工程の最小能力を基本とする。
- 独立した並列設備は、同じ需要を実際に分散でき、共通ボトルネックがない場合のみ合算する。
- 共用道路・通路・駅・バス・車両・人員・電力・燃料などは、その資源が消費される場所で一度だけ計上する。
- 異なる旅客フロー、到着/出発、ターミナル、貨物、航空機、インフラ等の値を、定義なしに合算しない。
- 名目定員/便を人/時へ変換する場合は、運行頻度・往復時間・乗降・車両数等の根拠を揃える。根拠がなければ便あたり定員のみ、または未算出とする。
- 能力の計算でSimulationの乱数列を消費しない。既存の決定的な算出源を再利用する。

#### 能力状態の区別

最低限、以下を混同しない。

| 状態 | 意味 |
|---|---|
| 未解放 | プレイヤーが利用条件を満たしていない |
| 未設置 | 資産が存在しない |
| 建設中/導入中 | 完成・導入前で利用できない |
| 未接続 | 必要なネットワーク/供給源につながっていない |
| 稼働準備不足 | 人員・車両・資源・時間等が不足 |
| 閉鎖/停止 | 運用判断・工事・障害等で一時利用不可 |
| 故障/保守中 | 修理・点検等で利用不可または制限 |
| 0能力 | 計算可能だが現在利用可能な能力が0 |
| 未算出 | 能力式または必要データがなく算出できない |
| 稼働中 | 必要条件を満たし有効能力を提供している |

「未設置」「未算出」「0能力」をすべて数値0として扱わない。未算出の項目をボトルネック順位、達成率、格の昇格条件へ混ぜない。

### 4.8 段階8：業務・Simulationへの接続

- 対象施設の能力を、実際にその施設を使うドメイン処理へ接続する。例: 旅客工程、航空機の折り返し、GSEタスク、手荷物、貨物荷役、給油、インフラ供給。
- 表示用の能力計算とSimulation側の処理能力を別々に実装しない。共通契約/adapterまたは同じ正本の計算関数を参照する。
- 能力不足が発生したとき、実際の待ち、遅延、未処理、積み残し、供給不足など対象領域の現象に反映する。
- 増設、接続、人員/車両配置、供給改善、閉鎖解除により、有効能力と運用結果が定義どおり変化することを確認する。
- 施設の計画値・能力値を参照するだけで、実際の業務を完了扱いにしない。タスク開始・資源予約・完了記録等の既存ドメイン規則を維持する。
- ATCゲームモードは経営モードと独立境界を保ち、本書を理由に状態・時計・保存・操作権限を統合しない。

### 4.9 段階9：実績計測・経営評価

- 需要、能力、実績、待ち、滞留、使用率、費用/収益の定義・単位・時間窓を区別する。
- 建設画面と経営画面は同じ算出源/共通契約を参照する。UIごとに別の式や丸めを持たない。
- 空港全体、ターミナル、施設、工程の階層を設ける場合、共有資源・共通工程を二重計上しない。
- 旅客は既存5-21のローリング60分等の時間窓を維持する。貨物、夜間、車両、インフラ等は各領域に適した時間窓を使い、無関係な時間窓を混在させない。
- 測定データがない場合は「未計測/未算出」とし、架空の実績値を補わない。
- ボトルネック表示は原因となる施設・接続・人員・車両・供給等へ追跡できるようにする。複数候補がある場合は曖昧な設備を自動選択しない。

### 4.10 段階10：維持・拡張・停止・撤去

- 施設の保守・劣化・故障を実装する場合、対象資産、発生条件、停止範囲、修理条件、必要資源、費用、完了条件を明確にする。
- 保守/工事中に利用できない範囲を有効能力・経路・Simulationへ反映する。
- Work Orderはdocs/5-25の既存計画/実装を再利用し、夜間滞泊や既存周期整備と二重実施・二重課金しない。
- 増設・仕様変更・撤去時は、既存の契約、便、タスク、予約、旅客/貨物の参照先、保存データの整合性を確認する。
- 撤去により参照先が消える場合、予約/作業中資源/保存データをどう解決するかを個別仕様で定義する。参照切れを黙って放置しない。

## 5. UIでの表示基準

### 5.1 建設・設置画面

対象施設を選択したとき、実装・算出可能な範囲で次を表示する。

- 施設名、分類、設置数、対象ターミナル/階/区域。
- 解放状態、建設/導入状態、接続状態、稼働準備、運用/保守状態。
- 理論能力、有効能力、単位、対象時間窓、算出根拠。
- 必要な接続先、供給源、人員、車両、資材。
- 不稼働/能力制限の具体的理由。
- 配置・増設・設定変更による能力差分（同じ実計算で試算可能な場合のみ）。

試算できない要素を含む場合は「仮の理論能力」「有効能力未確定」等と明示する。UIだけで独自の効果を仮定しない。

### 5.2 経営・能力画面

- 空港全体・ターミナル・分野・施設の階層を区別する。
- 理論能力・有効能力・需要・実績・使用率・待ち/滞留を別指標として表示する。
- 未設置、未算出、0能力、未接続、建設中、閉鎖、故障、資源不足を視覚的に区別する。
- ボトルネックの原因と、改善可能な設備/資源への導線を表示する。
- 指標には単位・時間窓・対象範囲を付ける。集計対象が重複する値を足し合わせない。

## 6. 実装着手時の標準手順

新しい施設・設備・車両・ネットワーク・運営機能を追加するときは、次の順で作業する。

1. **現状監査**: 関連Docs・コード・テスト・保存モデルを調査し、実装済み/一部実装/未実装/不具合/テスト不足を分ける。
2. **既存機能確認**: 既存の解放、建設、配置、接続、能力算出、Simulation、UI、経済、保守の正本を探し、重複実装を避ける。
3. **個別計画**: 複数ファイル、データ/状態遷移/能力/Simulationに影響する場合は、既存計画を更新またはTEMPLATEで個別計画を作成する。親要求IDと受入条件を明記する。
4. **資産分類**: 建築物・固定設備・車両・ネットワーク・運営機能のどれか、または複合かを定め、責務と所有関係を定義する。
5. **10段階の適用表**: 各段階を「適用」「対象外」「既存機能を再利用」「未実装」に分類し、必要な入力・出力・完了条件を記録する。
6. **状態・能力契約**: 独立状態と能力指標、単位、時間窓、算出根拠、未算出理由、共有資源を定義する。
7. **Simulation接続**: どのドメインのどの処理が能力を参照し、能力不足が何に影響するかを明記する。
8. **UI・経営指標**: 建設画面・経営画面・日報・分析のどこに何を表示するかを定義する。
9. **保存・決定性確認**: ProjectFile、SCHEMA_VERSION、SIM_MODEL_VERSION、移行、乱数、ゴールデンへの影響を調査し、必要なPO承認を得る。
10. **テスト・文書更新**: 正常/境界/異常/回帰、単体/統合/E2E、保存復元、決定性、性能を検証し、実装確認済みの仕様だけを機能別Docsへ反映する。

## 7. 施設別の適用例

| 例 | 主に必要な段階 | 能力/Simulation接続の例 |
|---|---|---|
| チェックインカウンター | 解放→配置→設置→旅客通路接続→人員配置→能力算出→旅客処理 | 窓口/人員の有効能力が旅客受付・待ち行列に反映 |
| 給油設備 | 解放→施設/機材設置→燃料供給接続→給油車/人員→能力算出→折り返し | 貯蔵/配管/給油車/人員の制約が給油待ち・作業時間に反映 |
| GSE基地 | 解放→建物建設→固定設備/車両導入→サービス道路/充電等の接続→人員/車両配置 | 車両の供給可能数・基地からの移動・整備状態が地上支援タスクに反映 |
| 貨物上屋 | 解放→建設→荷役設備設置→道路/エプロン等接続→要員/機材→能力算出 | 上屋能力・荷役・道路制約が貨物便・積み残し・搬出入に反映 |
| サービス道路 | 配置条件→建設→区間接続→通行状態→区間能力算出 | 車両経路・区間容量・閉鎖がサービス車両の移動へ反映 |
| 商業施設 | 解放→建設→区画/店舗設定→旅客動線接続→営業準備 | 旅客が実際に到達できる区域・需要・営業状態に応じて利用/収益を計測 |

適用例は実装の完成状態を示すものではない。対象機能の現行実装・個別計画で、未実装項目と受入条件を確認する。

## 8. 受入チェックリスト

新規施設/設備/車両/ネットワークの実装を完了とする前に、該当する項目を確認する。

- [ ] 資産種別、所有関係、既存モデルとの責務境界が明確である。
- [ ] 10段階それぞれの適用要否・完了条件が記録されている。
- [ ] 格解放と機能ON/OFF、設置、接続、稼働が分離されている。
- [ ] 配置条件・階層・占有・干渉・接続の検証がある。
- [ ] 建設中/未導入の資産が誤って稼働能力に含まれない。
- [ ] 必要な接続・人員・車両・供給・時間・保守状態が判定される。
- [ ] 理論能力・有効能力・需要・実績・使用率・待ちが単位/時間窓/根拠付きで区別される。
- [ ] 未設置・未算出・0能力・未接続・停止・故障・資源不足を混同しない。
- [ ] 直列/並列/共有資源の集計と二重計上防止がテストされている。
- [ ] 実際のSimulation/業務処理が能力を参照し、能力不足が運用結果に反映される。
- [ ] 建設画面・経営画面・日報等の指標が同じ算出源/定義を使う。
- [ ] 増設/接続/人員配置等で能力と運用結果が期待どおり改善するE2Eがある。
- [ ] 保存/復元/旧保存、決定性、乱数、ゴールデン、性能への影響を確認した。
- [ ] CLAUDE.mdの品質ゲートを実行し、未実行・失敗・未検証を明記した。
- [ ] 実装で確認した現行仕様とテスト根拠を該当機能Docsへ反映した。

適用対象外の項目はチェックを外すだけでなく、その理由を個別計画へ記録する。未実装・未検証のまま受入済みとしない。
