## 2. データモデル

```ts
type RunwaySuffix = 'L' | 'C' | 'R' | 'none';        // 'none' = 明示的に付けない。欠落 = 自動
interface RunwayBase { id; name; surfaceWidthM: 30 | 45 | 60; buildState; designatorSuffix?: RunwaySuffix }

/** 従来形（v1/v2 のデータはすべてこれ）。意味は永久に不変 */
interface RunwayGrid8 extends RunwayBase { alignment?: undefined; start: Tile; heading: Heading; length: number /* ステップ数 */ }

/** 自由方位・実寸 */
interface RunwayFree extends RunwayBase {
  alignment: 'free';
  start: WorldPoint;          // 実数可（World フレーム、タイル単位）
  headingDeg: number;         // 真方位 [0, 360)。保存時に normalizeDeg 済み
  lengthM: number;            // 実長（m）。丸めない実数。範囲 25 m 〜 約 7,071 m（FREE_RUNWAY_MIN_M / MAX_M）
  dims?: RunwayDims;          // 欠落した項目はゲーム既定値
}
type Runway = RunwayGrid8 | RunwayFree;

interface RunwayDims { shoulderWidthM?; stripHalfWidthM?; stripEndM?; resaLengthM?; resaWidthM?; holdingPositionM?; elevationStartM?; elevationEndM? }
interface AirportLayout { …; magneticVariationDeg?: number /* 東偏差を正 [-180, 180]、欠落 = 0 */; ruleSet?: 'classic' | 'realistic' /* 欠落 = 'classic' */ }
```

- 自由形は **終点を保存しない**。`end = start + bearingToDir(headingDeg) × lengthM / 25`（`runwayAxis(r)`）。番号は保存した方位から決まる。
- 既定値のキーは書かない（`alignment`・`headingDeg`・`lengthM`・`dims` は自由形のときだけ、`designatorSuffix`・`magneticVariationDeg`・`ruleSet` は設定したときだけ）。従来データの JSON はバイト列まで不変。
- すべての呼び出し元は `runwayAxis` / `runwayEnd` / `runwayLengthM` / `positionOnRunway` / `designatorsOf` を通す。従来形の式は 1 文字も変えていない（演算順の保存）。

### 従来形と自由形の違い

| | 従来形（バッジ「従来」） | 自由形（バッジ「実寸」） |
|---|---|---|
| 向き・位置 | 8 方位・整数タイル、長さはステップ数（斜めは 1 ステップ = √2 タイル） | 任意の真方位・実数の位置、長さは m |
| 占有・検証 | ゲームの簡易判定（幅 3 タイル + 保護区域 87.5 m、整数ラスタ） | 実寸の多角形（舗装 + 肩、着陸帯、RESA）。多角形どうしの重なり判定 |
| 停止位置 | `HOLD_SHORT_M = 87.5` m（エッジに沿って） | `dims.holdingPositionM`（既定 90 m、60 m 幅は 107.5 m）を中心線からの垂直距離とし、エッジに沿った距離へ換算 |
| 描画 | 舗装は実寸の幅（30/45/60 m）。判定の範囲は薄い輪郭で表示（S12） | 肩・舗装・着陸帯・RESA・標示・番号 |
| 交差 | 従来形どうしは従来どおり `OVERLAP` エラー（交差点を作らない） | 自由形が関与する組は交差点を作り、運航は従属運用 |
| 建設費 | 現行の式 | `lengthM / 25 × 単価 × 幅 / 30`（肩の費用は加えない） |
| 回転（R） | 45° | 中点まわりに吸着角度（0 のとき 15°） |

従来形 → 自由形は **「自由形に変換」**、自由形 → 従来形は **「グリッドに合わせる」** の明示操作だけ（自動変換はしない。どちらも Undo で戻せる）。

- 変換（従来形 → 自由形）: 位置・方位は同じ、長さは丸めない実長（斜めは n√2 × 25 m）、`dims` は書かない。終点は従来の整数の終点と 1e-15 タイル程度の差で、`POS_EPS_T` の判定で既存の誘導路ノードは滑走路上と認識され続ける。
  変わるもの: 占有と検証が実寸（着陸帯の半幅 87.5 m → 140 m など。周囲の施設が「保護区域内」になりうる）、停止位置（87.5 m → 90 m）、ほかの滑走路との交差・平行間隔の判定の対象になる。経済上は改修として扱わない。
- 「グリッドに合わせる」: 方位を 45° の倍数、始点を整数、長さをステップ数に丸め、`dims` を捨てる。長さが従来形の最大（200 ステップ）を超えるときは `TOO_LONG_FOR_GRID` で拒否（黙って短くしない）。

## 3. 滑走路番号（`designatorsOf(r, layout)`）

- 磁方位 = `magneticFromTrue(真方位, layout.magneticVariationDeg ?? 0)`（東偏差が正。真 090°・10°E → 磁 080° → 「08/26」、10°W → 「10/28」）。真方位と磁方位は型・ラベルで常に区別する（`trueDeg` / `magDeg`）。
- 番号 = 磁方位の 1/10 に最も近い整数（01〜36）。1 桁は 0 を前置。逆向きの番号は `((n + 17) % 36) + 1` で、必ず 18 差。
- **ゲームの規則**（資料で確認できなかった項目。参考資料 §8 NOT FOUND）: 5° の境界（x5°）は切り上げ、0 は 36。1e-6 度に丸めてから判定。
- 接尾辞（参考: FAA AIM 2-3-3、EASA CS-ADR-DSN L.525）: 同じ番号の **自由形** が 2 本 → L・R、3 本 → L・C・R（進入方向から見て左から右）。終点側は L ↔ R が入れ替わる。
  4 本以上は自動では付けず `RUNWAY_DESIGNATOR_CONFLICT`（手動の接尾辞で対応）。手動の `designatorSuffix` は自動より優先。UI の「自動」は上書きの解除（キーを消す）。
- 従来形には接尾辞を自動で付けない（表示・データとも従来どおり。PM の暫定判断 Q-A）。従来形の向きの選択肢（プロパティ）は、磁気偏角を設定すると磁方位の番号を表示する。
- 運航画面の運用方向の表示（`09 方向 / 27 方向`）も `designatorsOf` を使う。

## 4. 参考値とゲーム値

表示は常に **参考値**（公開資料の値。判定には使わない）と **ゲーム値**（判定・描画に使う）を分ける。UI・本書には次の定型文を添える:
**「参考値。ゲーム内の判定であり、実際の安全基準への適合を保証しません」**（`RUNWAY_REFERENCE_DISCLAIMER`）。

### 4.3 描画の標示（表示用のゲーム値、`RUNWAY_MARKING_M`）

中心線の破線 30 m・間隔 20 m、進入端の縦じま（30/45/60 m 幅で 8/12/16 本）は端から 6 m・長さ 30 m、番号は端から内側へ `min(0.1 × 長さ, 150 m)`。標示の概形に倣うが規格の値ではない。

## 5. 検証ルール（概要。詳細は [26](26_validation_rules.md)）

- 自由形の領域 `runwayAreas(r)`: 舗装、舗装 + 肩、着陸帯、RESA（両端、別々の凸 4 角形）。多角形どうし（SAT）と、従来形のタイル（正方形）との重なりを判定する。境界の接触は重ならない。
- 施設が着陸帯内 → `IN_RUNWAY_STRIP`、RESA 内 → `IN_RUNWAY_RESA`、舗装 + 肩どうし → `OVERLAP`。自由形の判定の issue は `params.criterion = 'real'`（IssuesPanel に「実寸」タグ）。
- 誘導路が滑走路に接している（端が中心線上、または中心線と 1 点で交差）なら舗装との重なりは許す。
- **交差する滑走路の組**（ネットワークに交差点ノードがある組）は、滑走路・着陸帯・RESA の相互の重なりを免除する。同一直線上の重なりと、中心線が交わらない舗装の重なりは `OVERLAP` のまま。
- 平行間隔・番号の重複は、自由形が関与する組、または `ruleSet = 'realistic'` のとき。

## 6. ネットワーク

- 誘導路 × 自由形の交点は **実数の位置** のノード（滑走路入口）にする。`POS_EPS_T` 以内の既存ノードに併合し、重複を作らない。従来形の交点処理（タイル中心のときだけ）は変えない。
- 滑走路 × 滑走路（少なくとも一方が自由形）の交差点は論理ノード `runwayIntersection`（ID `${a}:X:${b}`、`a < b`）。交点から `POS_EPS_T` 以内に誘導路ノードがあればそれを使う。
  両方の滑走路のエッジは交差点で分割される。交差点には誘導路が接続しないので離脱・進入の候補にならない。
- 端のノード（`T0`/`T1`）は端から `POS_EPS_T` 以内の誘導路ノードを再利用する。

## 7. 交差する滑走路の運航モデル

### 7.1 従属運用（既定。実装済み）

自由形が関与する交差点ごとに、**2 本の離着陸を 1 本の滑走路とみなす**（`dependent`）。従来形だけのレイアウトでは `ctx.crossings` は空で、運航結果は不変（`SIM_MODEL_VERSION = skyport-sim-10.0` のまま）。

| 場面 | ルール |
|---|---|
| 離陸許可 | 相手の滑走路が離着陸で占有中、または相手に進入予約があり到着まで `DEPARTURE_WINDOW_SEC`（90 秒）未満 → 待つ（理由 `intersection`、遅延の原因は `runwayQueue`）。間隔（`separation`）は相手の最後の離陸も数える |
| 進入許可 | 組全体で同時に進入できる到着は 1 機（相手に予約 → `separation`）。相手が離着陸中 → `runwayBusy`。「先行機」の判定と飢餓防止（`DEPARTURE_STARVATION_SEC` = 10 分）も組全体 |
| 接地 | 相手が離着陸中なら着陸復行（最終防壁。進入許可の条件で通常は起きない） |
| 横断 | 横断する場所が交差点ノードなら **両方の滑走路を同時に予約**（どちらも未占有で、予約が `CROSSING_WINDOW_SEC`（60 秒）以上先）。完了で両方を解放。`ac.crossing.alsoRunwayIds` に相手を持つ |
| 解放 | 離陸の占有は離陸距離（`takeoffDistanceM`）に達した時点（リフトオフ）で解放する。それ以降の機体は空中として扱い、もう一方の滑走路の運用を妨げない |

### 7.2 優先順位（決定的）

1. 着陸: 進入予約が入った時点から、組の相手の離陸・交差点の横断は窓の時間のあいだ拒否される。
2. 離陸: `runwayControl` が滑走路 ID の順に離陸待ちの先頭を処理する。同じティックで一方が許可済みなら、他方は `intersection` で待つ。
3. 横断: 各滑走路の離陸の後に処理する（既存の順序）。

### 7.3 一貫性の保証

不変条件 R2（占有の目的が `crossing` なら、`ac.crossing.runwayId` または `alsoRunwayIds` が占有している滑走路）、R6（従属の組で 2 本が同時に離着陸で占有されない）をティックごとに検査可能。
ゴールデン（`crossing-sim.golden.json`）: 交差のレイアウトで交差点の原子的な横断が起き、競合は 0。

### 7.4 未実装（S7b: 交差点予約モード）

「交差点を通らない運用どうしは同時に許す」モード（設計の `intersection` モード、`state.runwayCrossingModes`）は **実装していない**。運航画面には交差の行（「従属運用: 2 本の離着陸を同時に使いません」）を表示するだけで、モードの切替はない。
関連して、近接した平行滑走路を運航上も従属にする機能もない（間隔の警告だけ）。

## 8. エディタの使い方

- **滑走路ツール**（既定は従来形・8 方向のグリッド。既存の操作は不変）: 配置オプションの「方式」で **自由形** を選ぶ。
  - ドラッグ（始点 → 終点。クリック 2 回も可）: 始点は格子（タイル / 半タイル / なし）、方位は吸着（なし / 1° / 5° / 10° / 15° / 45°。既定 1°）、長さは吸着（なし / 10 / 50 / 100 m。既定 10 m）に丸められる。プレビューに番号・真方位・磁方位・長さを表示。
  - 数値入力: 「真方位（°）」「長さ（m）」「基準点（始点 / 中点）」を入力し、置きたい位置をクリック。R で方位を吸着角度ずつ回す。
  - 舗装幅は 30/45/60 m（従来と同じ）。
- **選択した自由形**: 端のハンドルをドラッグ → 中点まわりに回転（長さは保つ）。Shift + ドラッグ → 反対の端を固定して方位と長さを変える。R キー → 中点まわりに吸着角度（0 のとき 15°）。矢印キー・ドラッグでの移動は従来どおり（整数タイル）。
- **誘導路ツール**: 8 方向に引いた線が自由形の中心線と、カーソルの近く（0.75 タイル以内。斜めの線ではタイル中心どうしが √2 離れるため 0.5 では届かない）で交わるなら、その交点（実数）を次の点にする。
- **プロパティ（自由形）**: 名前、真方位（0〜359.99、0.1 刻み）、磁方位（表示）、長さ（m）、舗装幅、番号と接尾辞（自動 / L / C / R / なし）、実寸（肩・着陸帯の半幅と端部延長・RESA の長さと幅・停止位置）と標高（始点・終点）、勾配（表示のみ）、参考値と出典の表、「グリッドに合わせる」。
  実寸の欄の既定値はゲーム値で、変更すると「上書き」の印が付く。「ゲーム既定値に戻す」で上書きを解除。交差する滑走路があれば一覧表示する。
- **プロパティ（従来形）**: 判定の基準（「従来（ゲームの簡易判定）」）と「自由形に変換」（変わるものを列挙した確認つき）。
- **空港の設定**（何も選択していないとき）: 磁気偏角（東を正、「10°E」「5°W」の形で表示）、判定ルール（従来 / 実寸）と説明、滑走路番号の一覧。
  ルールの説明: 実寸にすると平行間隔・番号の重複の警告が従来形にも適用される。実寸の判定の大半は今後の版で追加される予定で、現時点では自由形の滑走路が中心。
- 滑走路の一覧・プロパティに「従来」/「実寸」のバッジ。IssuesPanel は実寸の判定の問題に「実寸」タグ。

## 9. 描画

2D（`MapRenderer`）と 3D（`Scene3D`）は、同じ core 関数 `runwaySurfaces(r, layout)`（World フレーム）の結果を `worldPolyToMap` / `worldPolyToScene` で変換して描く。面は舗装 + 肩・舗装・着陸帯・RESA、中心線の破線、進入端の縦じま、番号（位置と向き）。

- 自由形: 着陸帯（薄い面と輪郭）→ RESA（斜線）→ 肩 → 舗装 → 破線 → 縦じま → 番号。選択時は着陸帯・RESA の実寸の輪郭。3D は番号の文字を描かない（Phase 16）。標高は 3D に反映しない（平坦）。
- 従来形（S12・表示のみ）: 舗装を実寸の幅（30/45/60 m）で始点〜終点に描く。判定に使うゲームの占有の多角形（`footprint`）と着陸帯は薄い破線の輪郭で残す（選択時は濃く）。占有・検証・運航は不変。
- 2D の停止位置の線は、自由形のノードでは実寸の停止位置（`sim/routes.ts holdShortDistanceAt` と同じ式）。frames lint（座標の ±0.5 の生リテラル禁止）と、2D/3D の頂点の一致テストがある。

## 10. 制限（実装していないこと）

- 交差点予約モード（S7b）、近接平行の従属運用、勾配・標高の警告と 3D への反映、3D の番号の文字、従来形の平行滑走路への L/R の自動付与（PM の暫定判断 K / Q-A）。
- 実寸の判定は自由形（と `ruleSet = 'realistic'` の警告）だけ。翼端クリアランスなど機体の実寸を使う判定は Phase 14/15。
- 停止位置は滑走路ごとに 1 つの距離（`holdingPositionM`）。浅い角度では `SIN_MIN = sin 15°` で頭打ち（ゲーム値）。
- 着陸復行（`goArounds`）は、ゴールデンのレイアウト・負荷では 0 のまま（進入許可で防ぐため）。[10](10_open_issues.md) M。
