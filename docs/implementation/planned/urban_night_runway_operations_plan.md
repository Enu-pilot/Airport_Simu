## 1. 現状と課題

### 1.1 実装済みの夜間制限

- 都市設定がある空港では、原則22:00〜06:00を離着陸不可とする。計画側には最終出発時刻（既定21:15）があり、遅延便の夜間待機・翌朝持ち越しを扱う。
- city.nightOpsには最終出発時刻、上空待機上限、持ち越し危険便の優先等がある。設定UI・保存・日報が存在する。
- 騒音は実測dBではなく、機種/機体規模等によるゲーム内ポイントで集計し、住民満足度へ反映する。
- 滑走路は自由方位・実長を持つモデルがあるが、現在確認できる仕様は22:00〜06:00の一律門限であり、夜間に使える到着/出発方向を飛行経路の都市上空回避から検証する仕組みは未確認。

### 1.2 解決する課題

都市型空港でも、都市・住宅地・騒音敏感地域の上空を通過しない到着/出発経路を設定できる場合は、全空港一律の夜間閉鎖ではなく、その経路に対応する滑走路方向だけ夜間運用できるようにする。夜間に安全な方向がない場合は従来どおり運航を止める。

実装開始時に滑走路割当・方位・実際の離着陸処理・計画生成・気象/閉鎖との優先関係をコードで再監査する。現状で方向別の到着/出発経路制御があると推測しない。

## 2. 目的・対象範囲

### 目的

- 都市上空を横切らない到着/出発経路を明示的に設定・検証する。
- 夜間は、検証済みの経路に対応する滑走路方向・到着/出発だけを許可する。
- 許可方向がない、経路未設定、都市保護区域と交差する場合は、夜間運航を許可しない。
- 既存の全便門限型夜間制限を維持し、空港ごとに運用方式を選択できるようにする。

### 対象

- 夜間運用方針: 従来型の全面カーフュー、方向/経路制限型の夜間運用。
- 滑走路端ごとの到着/出発許可。
- 到着進入経路と出発経路の独立設定。
- 都市/住宅地等の上空通過を避ける保護区域と、経路回廊の交差判定。
- 計画生成、仮想能力チェック、当日運航、実績/日報、UI/validationへの一貫反映。

### 非目標

- 実在する航空法・自治体条例・騒音基準・実測dBの再現。
- 航空機の3D飛行軌跡、上昇性能、旋回・高度・レーダー誘導の完全シミュレーション。
- SID/STARの実在データベースをそのまま再現すること。
- 経路回廊の交差判定を、騒音予測や健康影響の科学的評価とみなすこと。

## 3. 設計方針

### 3.1 運用方式

最低限、次の方式を明確に分ける。

| 方式 | 夜間の離着陸 | 初期値/互換 |
|---|---|---|
| fullCurfew | 夜間時間帯は全方向で到着/出発を禁止 | 既存の都市空港・旧saveの挙動を維持 |
| directionalNightOps | 検証済みの到着経路/出発経路を持つ滑走路方向だけ許可 | 明示的に選んだ空港だけ有効 |

夜間時間帯は既存22:00〜06:00を初期対象とし、開始/終了時刻の自由設定は別途バランス・互換性を確認する。方向別方式でも日中の滑走路・気象・能力・工事閉鎖制約は引き続き適用する。

### 3.2 到着/出発経路と都市保護区域

- 滑走路の両端を別々の運用方向として扱う。到着許可と出発許可は別々に持ち、片方だけ許可する構成を認める。
- 各方向に、到着進入経路・出発経路をそれぞれ設定できる。滑走路中心線や滑走路方位だけから「都市上空を通過しない」と推測しない。
- 経路は滑走路端から空港敷地外へ続く順序付きwaypointと回廊幅で表す。必要な場合、空港外の座標を持つ経路データを空港内施設の配置範囲/衝突判定と分離して保存できるようにする。
- 都市・住宅地・騒音敏感地域は、地図上に設定する保護区域polygonとして定義する。到着/出発経路の回廊と保護区域が交差する場合は夜間不適合と判定する。
- 経路の状態を clear / intersectsProtectedZone / notConfigured / invalid に分類する。notConfigured/invalidを安全とみなさず、directionalNightOpsでは使用不可にする。
- 実装時に既存geometryのpolygon/line intersection・buffer/offset機能を監査し、自己交差・精度・座標範囲を確認してから利用する。根拠のない交差判定を追加しない。

### 3.3 運航判定の統一

- 滑走路方向・運航種別（arrival/departure）・予定/実時刻・経路検証状態から夜間可否を返す純粋な判定関数を正本にする。
- 計画、計画プレビュー、仮想契約チェック、滑走路割当、到着処理、離陸処理、日報集計が同じ判定を利用する。計画だけ許可して実運航で禁止される、またはその逆を発生させない。
- 方向別方式では、夜間に許可されない方向を予備滑走路として自動選択しない。到着は既存の出発地待機/欠航・ダイバート方針へ、出発はスポット待機/翌朝持ち越し等へ渡す。
- 滑走路手前・滑走路上・誘導路上で夜間閉鎖を待つ状態を作らない。出発可否はスポットを離れる前に予測し、到着可否は着陸進入の開始前に判定する。
- 許可方向であっても、滑走路閉鎖・競合・風/天候・機体適合・滑走路能力を無視して通すことはない。既存の運航制約との優先順位を実装前監査で決定する。
- 方向別方式で夜間便を計画可能にする時間帯の扱いを、既存departureCutoffMin（全面カーフュー前の最終出発）と分離する。既存値をそのまま22:00以降の運航枠として流用しない。

### 3.4 UI・警告・日報

- 滑走路の各方向ごとに、夜間の到着/出発可否、経路状態、交差する保護区域、判定理由を表示する。
- 2D上に到着/出発経路回廊と都市保護区域を重ね、経路の未設定/交差/正常を識別できるようにする。
- 空港設定で夜間方式を選択し、方向別方式の場合は経路と保護区域の設定を必須にする。
- 計画/運航画面には、夜間に使えない方向と次善の運航可能方向、運航を止めた理由を表示する。
- 日報に夜間の到着/出発数、方向別移動数、規制による待機/持ち越し/欠航、経路違反0件の監査値を記録する。
- 既存の騒音ポイントはゲーム用指標として維持する。夜間に静穏経路を利用したことを、実測dBが下がったかのように表示しない。

## 5. 互換性・リスク

- 既存の都市設定・旧saveはfullCurfew扱いとし、自動で方向別夜間運用へ移行しない。
- airport layoutの保護区域/飛行経路追加は保存形式・schemaの変更を伴う可能性がある。docs/21・27の移行方針と往復/旧データテストを先に決める。
- SIM_MODEL_VERSIONの変更要否は実装時に決定する。夜間便数・滑走路選択・住民評価・翌日状態が変わるため、既存seedへのKPI影響を提示する。
- 飛行経路は夜間適合判定用の概念回廊であり、実際の飛行位置や高度を表さない。実装範囲を超える3D軌跡をUI/レポートで表示しない。
- 回廊の未設定・データ不正・保護区域との交差は、夜間の許可として扱わない。
- 現行の最終出発時刻・上空待機上限・翌朝持ち越しと、方向別夜間許可を別々の制約として扱う。どれか1つを無効化して他を迂回しない。
