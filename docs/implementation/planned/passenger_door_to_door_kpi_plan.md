## 1. 現状と課題

- 旅客グループはターミナル内を移動し、施設待ちや乗り遅れを記録する。Step-free属性も既存のPaxGroupにある。
- Phase 6の外部アクセスは、車・送迎・タクシー・バス・鉄道・徒歩の利用割合や容量/所要時間を集約して扱う。道路車両・列車の個別移動や、外部境界からPortalまでのすべての旅客経路は未統合であり、5-16がその正本となる。
- 5-19のターミナル詳細計画には平均/95 percentile所要時間、待ち、Step-free到達率、搭乗締切遅れ相当が含まれている。本計画で、その値の対象区間・起点終点・分位点・搭乗締切を明確にし、単なるターミナル内歩行時間と外部からゲートまでの全行程を区別する。
- 5-21はローリング60分の工程能力/需要/処理実績を扱う。本計画は能力値そのものではなく、実旅客コホートの移動時刻・待ち・到着成否を扱う。

## 2. 目的・対象範囲

### 2.1 対象旅程

「Door-to-Door」は実在する自宅住所からの移動を意味しない。個々の住宅位置がモデル化されていないため、空港外部ネットワーク境界または明示した交通施設を起点/終点とする。

| 旅程 | 起点 | 終点 | 記録する工程 |
|---|---|---|---|
| 出発旅客 | 外部交通境界/交通施設への到着 | 対象便の搭乗ゲート到着 | 外部交通、待ち、Portal、歩行、上下移動、チェックイン、保安、出国審査等 |
| 到着旅客 | 対象便の到着ゲート | 外部交通境界/交通施設から退出 | 降機後の移動、入国審査、手荷物受取（対象者）、出口、Portal、外部交通 |
| 乗継旅客 | 到着便のゲート | 乗継便のゲート | 到着工程、ターミナル間移動、乗継保安/審査等、出発ゲート到着 |

- car / dropoff / taxi / bus / rail / walkを別々に集計する。未設置手段は5-16のnotConfiguredとして扱い、ゼロ利用と同じ意味にしない。
- 国内/国際、出発/到着/乗継、ターミナル、時間帯、Step-freeを区別する。
- 空港外部境界からの所要時間が設定値しかない場合は「推定/集約」と記録し、実旅客のp50/p95を算出した扱いにしない。

### 2.2 必須KPI

- 総所要時間: 起点の実出発/到着時刻から終点の実到着時刻まで。
- 工程別所要時間: 外部交通、待ち、Portal、水平歩行、階層移動、チェックイン、保安、審査、手荷物受取、ターミナル間連絡など。実際に通過しない工程は対象外。
- 総所要時間および工程別所要時間のp50/p95。平均だけでなく、遅い側の旅客を見られるようにする。
- 搭乗ゲート期限内到達率: 対象便の搭乗締切までに搭乗ゲートへ到着した旅客数 / 対象旅客数。
- 搭乗完了率: 搭乗締切/搭乗閉鎖までに実際に搭乗状態へ移った旅客数 / 対象旅客数。ゲート到着率と混同しない。
- Step-free到達率・期限内到達率: Step-free属性の対象旅客を分母として別集計する。通常旅客の割合で代用しない。
- 経路不能、サービスなし、容量不足、閉鎖、締切後到着、乗り遅れの人数と原因。
- 旅客アクセス手段別・ターミナル別・便別の人数、時間分布、完了率。

### 2.3 分位点・人数の扱い

- 旅客グループ数ではなく、グループ人数で重みづけした分位点を算出する。5人グループ1件と1人グループ1件を同じ1サンプルとして扱わない。
- 分位点の計算法（重み付きnearest-rank等）は実装時に固定し、単体テストで境界を確認する。
- 未完了・経路不能旅客は所要時間0秒として分位点へ入れない。完了者の時間分布と未完了者率を別々に表示する。
- 旅程サンプルが存在しない、または時刻の記録がない場合はnull/未計測とし、平均・ゼロ・推測値で埋めない。
- 詳細モードの分布を集約モードで再現できない場合は、集約値をp50/p95に見せかけず「詳細モードのみ」または「未計測」とする。

## 3. 設計方針

### 3.1 旅客ごとの時刻台帳

- 旅客グループごとに、外部境界/施設への到着、Portal通過、各工程の開始/終了、ゲート到着、搭乗完了、空港退出を記録する。
- 既存PaxGroupのID・人数・flightId・route状態を維持し、必要なイベント時刻のみを追加する。個人旅客を無制限に生成せず、グループ単位で処理する。
- 到着/乗継/出発の同一旅客を別の旅客として二重計上しない。乗継旅客は同じ旅程IDで到着側から出発側へ継続する。
- 時刻はシミュレーションclockに基づく決定的な値とし、UI表示時刻・壁時計を計算へ混ぜない。

### 3.2 搭乗締切の正本

- 搭乗締切は予定出発時刻から固定分数を推測せず、既存の搭乗処理・バスゲート締切・搭乗閉鎖状態遷移から、便ごとの実際の締切時刻を特定する。
- 現在の仕組みに一貫した締切時刻が存在しない場合は、既存ルールと矛盾しない明示的なdeadlineを定義する。設定値・推定値・実際の閉鎖時刻を区別する。
- ゲートに到着したが搭乗できなかった旅客、締切後に到着した旅客、ゲートへ到達できず別理由で乗り遅れた旅客を異なる原因として記録する。
- 遅延やゲート変更により締切が変わる場合、対象旅客の締切を決定的に再評価し、旧deadlineを使ったままにしない。

### 3.3 共通メトリクスと5-19/5-21連携

- 5-21の工程別利用人数・能力・待ち時間と、5-19の2モードが使う共通工程メトリクスを正とする。独自の別clock・別待ち時間モデルを作らない。
- 5-19の空港全体集約モードでは、実際に計測できる集約指標・人数保存則を出す。旅客個々の起終点時刻がない値は「集約/推定」と表示する。
- 5-19のターミナル詳細モードでは、旅客グループ時刻台帳からDoor-to-Door分布・分位点・締切到達率を計算する。
- 5-22のScenarioDefinition/ScenarioComparisonに、シナリオID・実行モード・対象ターミナル・seed・期間・入力バージョンとともに指標を渡す。

## 5. 互換性・リスク

- 時刻台帳の保存が必要か、運航中のみの計算で足りるかを監査し、日報/履歴/プロジェクトへ不要な重複データを保存しない。
- SIM_MODEL_VERSIONや保存形式を変更する場合、旧saveの移行、復元後の継続、決定性、ゴールデンへの影響を先に評価する。
- 5-16の複合歩行グラフが未完成の段階で、近接距離だけからDoor-to-Door成功を推測しない。
- 既存の乗り遅れ・搭乗・バスゲート締切の判定を二重に実装しない。deadlineの正本を1か所へ定める。
- 5-21のローリング60分能力は供給/処理率の指標、本計画の旅程時刻は実旅客の体験指標として分離する。使用率だけから旅客p95を推測しない。
