## 1. 現状と課題

- src/core/access/verticalWalk.ts の findPedestrianRoute() は、運用中かつレベル接続が有効な RoadEdge.roadClass === walkway を使い、同一階と階層コネクタを経由する施設間の歩行時間・経路エッジ・明示容量を算出する。
- src/core/access/landside.ts はgeneral/service road、rail、walkwayを別々の連結成分として構築し、階ごとの接続タイルと駅からターミナルへの到達可能性を検証する。
- この道路・歩行ネットワークはアクセス需要の分析・鉄道受入容量等に利用されるが、通常のPaxGroupが使うTerminalModel / findPaxRoute()の内部エリア経路へは直接接続していない。docs/34も「道路グラフの階層コネクタは駅アクセス経路に使うが、旅客グループの階層移動には未接続」と明記する。
- 現行analyzeAccess()は、鉄道駅に明示walkwayがある場合は実徒歩ルートを計算するが、駐車場・タクシー乗り場・バス停は主に一般道路への接続とターミナルまでの近接距離を使う。空港アクセスruntimeも外部交通の所要時間/容量/遅延を集約的に処理しており、交通施設からターミナル入口までの歩行を全手段で個別移動させてはいない。
- 現行の配置検証は、鉄道駅の徒歩経路を中心にACCESS_ROUTE_UNREACHABLEを出す。駐車場・送迎・タクシー・バス・徒歩を含む全手段について、外部接続→交通施設→徒歩Portal→ターミナル→ゲート/出口までの完全な経路を検査する機能は不足している。
- TerminalModelはTerminalAreaと内部AreaLink、上下設備、明示TerminalTransitLinkを中心に構築される。エリアは矩形で、階は現状0以上。複数の交通グラフ間をつなぐ明確なPortalモデルはない。
- 既存5-13計画は経路全体のoperational / underConstruction / unreachable判定を対象にする一方、初版の非目標でRoadEdge徒歩網と通常PaxGroupの統合を除外している。今回のPO依頼によりこの除外を解除し、本書で分割して扱う。
- RoadEdge.roadClassの一般道路・サービス道路・鉄道・燃料管は歩行通路と別の責務。歩行者経路に使うのは明示されたwalkwayだけとする。

## 2. 目的・対象範囲

- 空港外周/外部交通接続点/駅/バスターミナル/駐車場/車寄せ/タクシー乗り場/道路階層/建物Portal/TerminalArea/TerminalTransitLinkを横断する一貫した旅客動線グラフを構築する。
- 車両用の一般道路・鉄道グラフと、旅客が歩く歩行グラフを別のエッジ種別として保ち、交通手段ごとの乗降施設からターミナル内への接続を明示する。
- 階層を移動する道路・歩行路について、レベル・標高・コネクタ・向き・建設状態・容量が接続判定に反映されるようにする。
- 通常の航空機運航中のPaxGroupが、必要な範囲で階層歩行路・駅コンコース・ターミナル間連絡を歩行時間と容量を伴って移動できるようにする。
- 5-13の3状態判定をグラフ全体へ適用する。将来経路の建設中設備を現在の旅客へ歩かせない。
- 構造検証・運航アラートに「通行可能」「建設完了待ち」「未接続」を区別して表示する。

### 非目標

- 一般道路・サービス道路上の車両や列車を個別に走らせること（この計画は歩行者ネットワーク）。
- 鉄道ダイヤ・バス運行の車両位置をシミュレートすること。
- 建設中・計画中の歩行路を実際の旅客が使用すること。
- 初期段階で都市全体の自動車・バス・列車を車両単位で走行させること。交通の外部供給は道路/鉄道の接続、頻度、定員、容量、待ち時間として集約する。
- 旅客需要発生・座席予約・便割当てを、この経路統合だけを理由に変更すること。
- 詳細なターミナル単独運用画面の実装（5-19）。ここでは航空機運航に必要な実旅客経路のみ対象。

## 3. 設計方針

### 3.1 統合するグラフの責務

- グラフは少なくとも次のノード/エッジを区別する:
  - TerminalAreaノードと自動生成される内部AreaLink（区域・階・閉鎖を保持）。
  - RoadNodeと、明示walkway RoadEdge（レベル・標高・方向・buildState・capacityPerHour・travelSecを保持）。
  - AccessBoundary / AccessFacilityノード（外部境界、駐車場、車寄せ、タクシー乗り場、バス停/バスターミナル、駅、周辺徒歩入口）。どの交通手段に属するか、外部ネットワークへの接続ID/状態を保持する。
  - TerminalPortal / PedestrianPortal（交通施設・駅コンコース・バスターミナル・歩行入口とTerminalAreaを明示接続する境界エッジ）。
  - TerminalTransitLink（建物間・ターミナル間の徒歩/動く歩道/高層通路等。現行責務を保ち、必要なら内部橋・複合体接続へ拡張）。
- グラフは派生データとし、レイアウトから決定的に再構築する。保存データにはユーザーが作った道路・エリア・ポータル・リンクのみ持つ。
- 同じ階/座標にあるだけで道路とTerminalAreaを自動接続しない。接続先階、地図level、建物床階、旅客zone、入口位置を持つ明示Portalを置く。
- 駐車場・車寄せ・タクシー乗り場・バス停/バスターミナル・駅は、交通ネットワーク側の接続と旅客歩行側の接続を両方持つ。一般道路につながっているだけ、またはターミナルから近いだけでは旅客が入口へ到達できると判定しない。
- 車両用public道路/rail辺は歩行グラフへ入れない。徒歩移動はwalkway・駅コンコース・施設内通路・Portalだけを通る。バス/鉄道はサービス頻度・定員を別の交通サービス情報として扱う。
- 物理的な線路rail・自動車道路public/service・燃料管fuelを歩行可能に扱わない。駅ホームからコンコースへは駅施設内のPortal/連絡施設を通す。
- mapLevel（地図階層）とfloorIndex（建物内階）を別々に検証し、地図階層と内部階を変換するPortal情報を明示する。

### 3.2 旅客経路と接続状態

- 5-13の3状態判定を複合グラフへ適用する:
  1. operational edgeだけで到達可能ならoperational。
  2. operationalに加えunderConstruction edgeを含めて到達可能ならunderConstruction。
  3. どちらも不可能ならunreachable。
  plannedは完成待ちに含めない。閉鎖・区域不一致・oneWay逆走・stepFree制約はどの状態でも尊重する。
- 現在旅客の経路と将来の完成後経路は別フィールド/別型とし、将来経路をPaxGroup.routeに設定しない。
- PaxGroupのルートは複合ステップ（terminalArea path / roadway walkway path / terminal link path）として進行できるようにする。旧route:string[]を破壊的に変更する前に移行・互換層を設計し、既存ターミナル内のみの経路を保護する。
- 経路上の最小容量・所要時間は、未算出能力と明示能力を区別する。容量未算出の辺を「容量0」や「無限大」として扱わない。時間帯予約/待機モデルは既存TerminalTransitLink・階層エレベーターのルールと整合させる。
- stepFree旅客はstairs/step-free非対応connectorを除外する。代替経路がなければ到達不能として診断する。

### 3.3 旅客アクセスと運航の整合

- 鉄道アクセスの集約能力（列車本数×定員、walkway capacityの最小値）と、旅客グループの個別歩行を二重計上しないよう、どの時点で需要を計上/予約するかを定義する。
- 航空機運航モデルでは旅客生成・予約・発生時刻・便割当ては維持し、経路/歩行/能力の変更が待ち時間・乗り遅れ・旅客総数に与える差を別計測する。
- ターミナル複合体が同じでも、実際の通路が無い建物間は到達不能。complex IDのみを歩行エッジとみなさない。
- 旅客の通路占有/transport reservationはグループの部分移動・複数時間帯・再経路探索・リンク閉鎖・建設完了を一貫して扱う。

### 3.4 対外交通を含む往路・復路

- 旅客の出発側は「外部境界/交通路線 → 駐車場・車寄せ・タクシー・バス・鉄道・徒歩入口 → 徒歩Portal → ターミナル入口 → 必須工程 → 各搭乗口」までを一連の経路として評価する。
- 到着側は「各到着ゲート → 到着/国際審査等の必須工程 → 手荷物受取（対象旅客のみ） → ターミナル出口 → 徒歩Portal → 駐車場・車寄せ・タクシー・バス・鉄道・徒歩入口 → 外部境界」までを逆方向に評価する。
- 6手段（car / dropoff / taxi / bus / rail / walk）をそれぞれ独立に検査する。手段が未設置ならnotConfigured、設置済みで接続がなければunreachableとし、未設置を一律エラーにしない。
- 各経路を operational / underConstruction / unreachable の3状態に分類する。経路の状態とは別にserviceActive / noService / noCapacity / closedを持ち、「通路はつながるが列車が来ない」「車寄せはつながるが処理枠が0」等を識別する。
- 出発/到着、国内/国際、乗継、Step-freeを別条件で検査する。Step-free旅客は階段を使えず、エレベーター等を含む代替経路がない場合は到達不能とする。
- 外部の移動時間・車両容量は初期段階では集約値でもよいが、旅客が歩く交通施設〜Portal〜ターミナル区間は実際の複合グラフ上で到達可能でなければならない。

## 5. 互換性・リスク

- RoadEdgeとTerminalAreaを直接1つの既存unionへ押し込む前に、グラフ境界/Portalの明示方式を検討する。互換性を保つ小さなadapterが優先。
- 通常旅客の経路進行が変わる場合、SIM_MODEL_VERSIONと保存中simの復元条件を事前に整理し、独断で版上げ/ゴールデン更新しない。
- 古いセーブにPortal/TerminalArea floor情報がない場合、既存のターミナル内ルートを保持する。自動接続推測はしない。
- 3状態判定のunderConstructionは構造診断であり、旅客の通行許可ではない。
- アクセス集約モデルと旅客グループモデルの同時集計は過大な人数/容量利用を起こす。人数保存則と計上箇所をテストで固定する。
