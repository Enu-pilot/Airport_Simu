# 基盤完成後の実装計画: 風向・風速に応じた滑走路運用方向の選択（F3）

> 管理状態: planned（基盤ゲート待ち）  
> 作成日: 2026-11-18  
> 更新日: 2026-11-18  
> 根拠: docs/11 §6、docs/30 §1、docs/39 §7.2（F3）、docs/42 §3.8  
> 正本: 本書は実装計画。現行の風向・滑走路運用仕様ではない。

## 1. 現状と課題

- 天候モデルは5段階の天候推移・予報を持つが、風向・風速はモデル化していない。
- 滑走路ごとに運用方向・運用モードを変更できるが、風向に応じた自動選択はない。
- Phase 12 で自由方位・実長の滑走路と交差/平行滑走路の構造が導入されているため、8方向固定の角度計算を前提にしない。
- 滑走路方向の変更は、進入予約・滑走路占有・交差/従属運用・都市上空保護・夜間制限と整合させる必要がある。

## 2. 目的・対象範囲

### 目的

ゲーム内の風向・風速を時間変化させ、滑走路の方位・利用可能な運用方向・機体区分の制限を考慮して、適切な滑走路方向を選択する。方向変更による切替時間・処理能力・待機を運営上の判断にする。

### 対象

1. **風データ**
   - 天候モデルに風向（風が吹いてくる方位）と風速を追加する。
   - まずは空港全体に共通の風とし、局地的な風・滑走路端別の乱流は対象外とする。
   - 風は決定的な専用シードで日別・時間別に生成し、既存の天候乱数列を変えない。
   - 予報に風向・風速の時間帯別見通しと不確実性を表示する。
   - 現実の気象の再現をうたわず、単位・値域・確率はゲーム用と明示する。

2. **滑走路端ごとの風成分**
   - 滑走路の幾何学的な中心線・真方位から両端の運用方位を求める。
   - 風向との角度差から向かい風・追い風・横風成分を計算する。
   - 滑走路長・幅・運用モード・機体区分・既存閉鎖状態を同時に評価する。
   - 許容値はゲーム用の設定値として一元管理し、実在の航空安全基準への適合を主張しない。

3. **運用方向の選択**
   - 各滑走路について利用可能な方向を評価し、向かい風の利得と横風/追い風の制約を比較する。
   - 既存の依存/交差/平行滑走路の運用制約を維持する。
   - 既定モデルでは1本の滑走路の到着・出発は同じ運用方向を使用する（方向別の独立運用は別途PO判断）。
   - 適切な方向がない場合の待機・ダイバート・欠航条件を定義する。

4. **方向切替**
   - 現在の滑走路占有・進入予約・横断予約が解放されるまで切替を開始しない。
   - 切替中は当該滑走路を新規の進入・離陸許可対象から外す。
   - 切替時間をゲーム値として設定し、予報変化だけで頻繁に方向が反転しないようヒステリシス・最短維持時間を設ける。
   - 手動指定と自動選択の優先関係を明確化し、手動設定は自動設定で意図せず上書きしない。

5. **表示・分析**
   - 現在風・予報・各滑走路端の風成分・選択理由・切替中/待機状態を表示する。
   - 方向変更による待ち・遅延・ダイバート・処理能力の変化を日報に記録する。
   - 風データがない旧セーブは従来の手動運用方向を維持する。

### 非目標

- 実在空港のATIS/METARや実際の気象予報との同期。
- 乱気流、ウインドシア、マイクロバースト、局地風・地形風の詳細再現。
- 実際の機体性能表・航空法規・滑走路運用基準への適合保証。
- 初期版で到着・出発の滑走路方向を独立して設定すること。
- 自動選択を使わない既存保存データの運航結果変更。

## 3. 設計方針

- 風計画は天候段階の計画と同様に純関数化し、同じ会社seed・日付・気候から同じ結果を返す。
- 風向の生成に既存の weather RNG・ops RNG を追加消費しない。用途別シードを使用する。
- 風成分計算は自由方位の滑走路中心線を基準にし、磁気偏角による滑走路番号表示とは分離する。
- 滑走路方向の自動選択器は、運航シミュレーションの予約/占有状態を直接書き換えず、利用可能性・候補方向・切替要求を返す。
- 既存の滑走路排他・横断・従属運用を優先し、風向だけを理由に既存の安全側制約を解除しない。
- 都市上空回避型の夜間運用（5-24）と同じ滑走路端・到着/出発回廊を参照できるようにし、夜間許可と風向適性をAND条件で評価する。
- 選択理由・制限値を表示し、なぜその方向が採用/不採用になったかを説明できるようにする。

## 5. 互換性・リスク

- 保存形式: 風設定・現在風・切替状態を運航中保存する必要がある場合のみ、formatVersion 変更を検討する。
- SIM_MODEL_VERSION: 新しい風ルールを opt-in にしても、ONの会社では運航結果が変わるため、バージョン・ゴールデン影響を計測しPO承認を得る。
- 既存の天候stage・weather RNG・ops RNGを変えない。風専用乱数列を設ける。
- 滑走路方向切替によるデッドロック・予約漏れ・進入中機の進路変更を防ぐため、切替は現在の予約解放後に行う。
- 急な方向変更を抑えるため、閾値に余裕幅と最短維持時間を設ける。
- 5-24の都市保護回廊と相反する場合は、片方の制約を無視せず、適合する方向がなければ運航制限へ移る。
