# 基盤完成後の実装計画: 除雪・滑走路/誘導路の雪氷処理・航空機防除氷（F4）

> 管理状態: planned（基盤ゲート待ち）  
> 作成日: 2026-11-18  
> 更新日: 2026-11-18  
> 根拠: docs/10 §O、docs/30 §1、docs/11、docs/13、docs/39 §7.2（F4）、docs/42 §3.8  
> 正本: 本書は実装計画。現行の天候・地上作業仕様ではない。

## 1. 現状と課題

- 天候モデルは snowy 気候・雪の天候段階を持ち、荒天時の地上走行速度を低下させる。
- 降雪による路面への積雪量・滑走路/誘導路の汚染状態・除雪作業・閉鎖時間は管理していない。
- 航空機の防除氷工程、専用車両、処理待ち、処理期限/再処理の概念はない。
- 既存の地上作業には給油・搭乗等があるが、滑走路・誘導路の除雪と航空機の防除氷は別の資源・場所・時間を使うため、同じ処理として扱わない。
- 5-25 の夜間Work Order/整備シフトと作業計画・設備閉鎖を共有する必要がある。

## 2. 目的・対象範囲

### 目的

雪が降る空港で、滑走路・誘導路の除雪と航空機の防除氷に必要な人員・車両・時間を計画させ、運航能力・遅延・閉鎖・費用へ反映する。

### 対象

1. **降雪・路面状態**
   - snowy気候と雪の天候段階に応じて、滑走路・誘導路の路面状態を時間経過で変化させる。
   - 初期版は各滑走路/誘導路区間の状態を段階化（例: clear / contaminated / reduced / closed）する。
   - すべてのタイルに詳細な積雪物理を持たせず、運航に関係する舗装資産・区間単位で管理する。
   - 降雪停止後も自然に即時回復しない。除雪・再凍結相当の状態変化はゲーム用の簡略値で扱う。

2. **除雪・路面処理**
   - 除雪車・スイーパー等の種類別台数、作業員、作業可能時間、単位時間当たり処理能力を管理する。
   - 除雪対象の優先順位を定義する（運用滑走路、主要誘導路、スポット接続路等）。
   - 作業中の滑走路・誘導路は、閉鎖または能力低下として運航計画・運航中の予約に反映する。
   - 5-25 の Work Order を利用し、作業開始・進捗・完了・資産閉鎖・作業員/車両競合を一元管理する。
   - 初期版で個別除雪車の実走行をモデル化しない場合は、処理能力が集約モデルであることを表示する。

3. **航空機の防除氷**
   - 防除氷が必要な天候条件をゲーム内ルールで定義する。
   - 防除氷車両・作業員・処理場所の能力を追加し、航空機の出発準備工程へ接続する。
   - 防除氷の待ち・作業時間が出発遅延へ反映される。
   - 処理完了後の有効時間（ゲーム用Holdover相当）を設け、期限を超えた場合の再処理または出発不可を定義する。
   - 除雪（路面を使える状態に戻す）と防除氷（航空機表面への処理）を別資源・別タスクとして扱う。

4. **経営・運航への影響**
   - 除雪車・防除氷車・作業員・設備の導入費・維持費・作業費を設定する。
   - 路面状態に応じて滑走路の使用可否・能力・地上走行速度を変える。
   - 除雪・防除氷が間に合わない場合は、遅延・出発待ち・到着待機・ダイバート・欠航の条件を定義する。
   - 予報から必要な設備・作業余力を判断できる画面と日報指標を用意する。

5. **有効化条件**
   - 初期版は snowy気候または明示的に冬季運用を有効にした会社でのみ動作する。
   - 温帯・熱帯設定や既存会社に新しい路面状態を自動追加しない。

### 非目標

- 実際の積雪深・路面摩擦・制動性能・航空機性能の精密シミュレーション。
- 実在の防除氷液・濃度・凍結点・実時間Holdover表の再現。
- 個々の除雪車が道路を走行する完全な車両交通シミュレーション。
- 全タイルへの積雪メッシュ描画・地形変化。
- 気象観測値・実際の除雪基準・空港の安全運用基準への適合保証。
- 防除氷設備がない空港でも、すべての天候で無条件に運航を継続すること。

## 3. 設計方針

- 路面状態・除雪タスク・航空機防除氷タスクを別モデルとして管理する。
- 路面状態は舗装資産/区間に保持し、広大なマップ全体へ毎tickの走査を行わない。降雪イベント・時間経過・除雪完了時に差分更新する。
- 除雪作業の能力単位は、5-17で確定した舗装幅/長さまたは一貫したゲーム単位を用いる。幅が未算出なら面積能力を推定しない。
- 作業能力は、車両台数だけで処理率に変換しない。1台の作業速度・幅・稼働時間・作業員数が決まるまで能力は未算出にできる。
- 5-25 Work Order を共通の作業・資産閉鎖管理基盤とし、別の保守キューを二重に作らない。
- 防除氷は通常の折り返しタスクへ接続し、作業員/車両/処理場所の能力予約、期限、再処理を明示する。
- 雪状態の乱数・天候計画は既存乱数と分離する。既存の雪天候ペナルティを新しい路面状態と二重に適用しないよう、既存速度係数との責任範囲を定義する。
- すべての値はゲーム用と明記し、現実の安全基準に適合するような表現を避ける。

## 4. 着手ゲート・タスク分割と受入条件

### 着手ゲート

- 5-17（誘導路実幅・高速離脱）で除雪能力算出に必要な舗装幅/長さの扱いが確定していること。
- 5-25（夜間Work Order・整備シフト）が受入済みで、作業員・車両・資産閉鎖・作業進捗を共通管理できること。
- 5-21（ピーク能力）へ除雪/防除氷による能力低下・待ちを重複なく反映する方法が確定していること。
- ゲーム用の積雪状態閾値、防除氷対象条件、処理期限、作業能力・費用をPOが承認していること。

## 5. 互換性・リスク

- 保存形式: 降雪状態・除雪進捗・防除氷の作業状態を運航中保存する場合は formatVersion の変更要否を評価する。
- SIM_MODEL_VERSION: 冬季運用ONのときに限り運航結果が変わる設計を基本とし、旧save/既存goldenへの影響を切り分ける。
- 降雪と除雪で多数の舗装資産を毎tick走査しない。状態更新はイベント駆動または粗い時間間隔で行う。
- 既存 weather level 3 の雪速度係数と、路面汚染による速度/閉鎖を二重適用しない。
- 除雪中の滑走路・誘導路を閉鎖する際、既に占有中・進入予約中・走行中の機体を不整合にしない。作業開始は資源解放を待つか、明示的に安全な段階へ遷移させる。
- 防除氷の期限切れ処理は、tick境界・出発許可・再処理タスクとの競合をテストする。
- 施設・車両の保有台数だけで時間当たり能力を捏造しない。作業時間・処理量の根拠がない場合は未算出と表示する。
