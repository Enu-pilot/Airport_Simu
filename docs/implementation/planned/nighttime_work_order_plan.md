# Phase 5 / 5-25 実装計画: 夜間整備シフト・設備保守・工事時間帯

> 管理状態: **planned（計画済み・実装未着手）**  
> 作成日: 2026-11-18  
> 更新日: 2026-11-18  
> 根拠: PO依頼（2026-11-18）、docs/44 §2（夜間滞泊・整備）、docs/41、docs/42 §3.4  
> 依存: Phase 4 / 4-05（既存の夜間機体整備）、5-24（夜間滑走路運用・資産閉鎖との調整）

## 1. 現状と課題

### 1.1 実装済みの夜間整備

- 拠点契約の所属機は出発12回ごとに定期整備対象となる。
- 夜間滞泊中の機体を対象に、格納庫1棟あたり最大1機、整備施設はbaysに応じた枠を持つ。整備士数・機体サイズも能力条件に使う。
- 日次締め時に整備枠を割り当て、未整備機には決定的なseedで技術遅延/欠航を判定する。整備済み機体のcycleはリセットされる。
- 現行方式は「日次締めで周期・枠を一括判定」する軽量モデルであり、作業時間を時間軸上で予約し、途中進捗・人員競合・複数設備の作業順序を表示する作業管理システムではない。
- 現在の整備仕様は航空機の定期チェックが中心。GSE、滑走路/誘導路、照明・航空保安施設、ターミナル設備の予防保守と、夜間工事の作業時間帯を統合する仕様は未確定。

### 1.2 解決する課題

昼間の運航・旅客処理への影響を抑えながら、夜間の時間帯に整備・点検・修理・設備更新・工事を計画し、利用可能な人員/設備/閉鎖時間の範囲内で進捗させる。方向別夜間運用を行う空港では、運航中の滑走路と作業中の滑走路・誘導路を同時に使用しないよう、施設閉鎖と運航を調停する。

## 2. 目的・対象範囲

### 目的

- 夜間作業をWork Orderとして可視化し、作業時間・必要能力・進捗・費用・未完了理由を管理する。
- 既存の航空機定期整備を二重計上せず、既存の周期/整備枠/不具合判定との連携を整理する。
- GSE・滑走路/誘導路・照明/保安施設・ターミナル設備の保守、修理、夜間工事を段階的に扱う。
- 夜間運航が継続する場合は、作業対象と運航中資産・旅客動線が競合しないよう閉鎖/代替ルートを管理する。

### 対象と段階

| 段階 | 対象 | 受入の考え方 |
|---|---|---|
| A | 航空機の周期整備・追加点検、GSEの点検/修理 | 既存整備枠を作業時間・資格/人員・設備として表現し、日次締めの二重判定を避ける |
| B | 滑走路・誘導路・灯火・航空保安設備の点検/修理/更新 | 対象区間の閉鎖時間を確保し、他の運航可能経路があれば継続。使用中の区間では作業しない |
| C | ターミナル・アクセス施設の保守、施設更新・建設工事 | 工事区画・時間帯・代替動線を扱い、旅客/車両の経路を塞がない |

段階Aを先に成立させ、段階B/Cは同じWork Order/時間割当基盤を使って拡張する。初回実装で全施設の詳細な施工工程を再現しない。

### 非目標

- 現実の航空整備規則、整備士資格要件、耐空証明を完全再現すること。
- 作業員/整備士の個人単位の出退勤・疲労・技能成長を初回で実装すること。
- 夜間に作業を割り当てただけで、資源や閉鎖条件なしに完了すること。
- 工事中の滑走路・誘導路・設備を運航が使用すること。
- 既存の定期整備確率・遅延/欠航バランスを、根拠なく変更すること。

## 3. 設計方針

### 3.1 Work Orderの共通モデル

各作業は次の情報を持つ。実装時に既存型を調査し、重複する項目は追加せずadapterで統合する。

- 対象資産: 航空機、GSE、滑走路、誘導路区間、灯火/保安設備、ターミナル/アクセス施設。
- 作業種別: 定期点検、予防保守、故障修理、検査、交換/更新、建設/改修。
- 必要時間、残作業時間、必要人数/資格/設備、優先度、費用。
- 作業可能時間帯、予定開始/終了、実績開始/終了、進捗、保留理由、完了検査状態。
- 対象資産の使用可否、閉鎖範囲、代替経路、作業中の安全状態。

Work Orderの状態は、少なくともplanned / queued / inProgress / blocked / completed / failedを区別する。blockedは資源不足・閉鎖不成立・運航競合などの原因コードを持つ。

### 3.2 既存の航空機周期整備との統合

- 現行のcycle閾値、整備枠、格納庫の機体サイズ制限、整備士数、seedによる遅延/欠航判定をコードで再監査する。
- 既存の定期チェックをWork Orderとして表現するか、既存の締め処理を維持してUI/Work Order側へ結果だけを渡すかを、挙動互換性と処理コストで判断する。
- どちらを採用しても、同じ機体の同じ周期チェックを二回実施/計上しない。既存のcyclesリセット・techHoldUntil・techCancelと整合させる。
- 整備枠は施設ごとのスロット、作業時間、整備士/設備能力を区別する。単なる施設数だけから完了件数を推定しない。

### 3.3 夜間作業時間とシフト

- 初期作業時間帯は夜間制限と整合する22:00〜06:00とする。将来の営業時間変更は独立設定として扱い、空港の運航時間と工事可能時間を同じ値として暗黙に結合しない。
- 作業時間はsimulation clockで進行させる。日次締めの瞬間にすべての作業を即時完了させない。
- 夜間作業員・整備士・工事班は初期段階では夜勤枠として明示する。昼間の折り返し要員を二重に割り当てない。
- 複数作業が同じ人員/設備を要求する場合、優先度と予定時間に基づき決定的に割り当てる。割り当てできない作業は未完了/blockedとして記録する。
- 天候・施設閉鎖・運航延長等で作業時間が短くなった場合、残作業時間を保持して次の有効な時間帯へ繰り越す。

### 3.4 滑走路・誘導路・施設の閉鎖調整

- 滑走路/誘導路の作業は、対象資産の使用を停止し、占有/予約/進入中の機体がいないことを確認してから開始する。
- 滑走路1本の作業中も、他の運航可能滑走路・誘導路・回廊があればそちらで運航を継続できる。代替経路がなければ作業開始を遅らせるか、運航/工事計画側で影響を表示する。
- 方向別夜間運用（5-24）と共存する場合、夜間使用可能な滑走路方向と作業中の閉鎖を同じ判定に反映する。夜間運用に必要な唯一の滑走路/経路を作業で塞がない。
- ターミナル設備・アクセス施設の作業は、該当エリア/階/Portalを閉鎖し、5-16/5-19の旅客動線に迂回路があるかを確認する。
- 作業が時間内に終わらなければ、対象資産を自動再開しない。点検/安全確認が完了するまでclosed/underMaintenanceを維持し、計画/運航へ警告する。

### 3.5 工事・施設保守との接続

- 既存の建設進捗モデルを監査し、現状の工事日数/工期計算と、夜間作業時間による進捗を分ける。
- 夜間工事を追加する場合、施工班・必要時間・資材/費用・施工可能時間・対象区画・閉鎖時間をWork Orderへ接続する。
- 工事の完了時刻は「暦日が進んだ」ことだけで決めず、作業時間帯・資源が確保された実績に基づく。
- 既存の建設予定日・契約開始日・供用開始条件を壊さず、夜間工事を利用しない旧データは従来どおりとする。

## 5. 互換性・リスク

- Phase 4の整備モデルを時間ベースへ変更すると、機体cycles・整備数・技術遅延/欠航・翌日便が変わる可能性がある。既存挙動との比較を先に行い、必要な場合はユーザー承認なしにゴールデン/model versionを更新しない。
- 同じ夜に既存の周期整備と新しいWork Orderを二重実施しない。既存のmaintenanceCredit・格納庫・整備施設・engineerCountを二重に能力計上しない。
- 夜間作業は運航state、施設buildState、道路/誘導路予約、旅客動線、契約能力、日次会計へ影響する。変更前に影響範囲を洗い出す。
- 作業対象が閉鎖中のまま翌日を迎えた場合、機体/旅客/車両が閉鎖区域に残らない不変条件を追加する。
- Work Orderの時刻・進捗・割当を保存する場合、プロジェクト形式/シミュレーション状態の版、旧save移行、途中保存からの再開テストが必要。
- 作業順・乱数は決定的にする。機能別seed streamを使い、夜間作業を追加しただけで便計画や旅客乱数の列をずらさない。
