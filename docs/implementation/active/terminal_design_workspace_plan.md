## 1. 現状と課題

- src/ui/Toolbox.tsx にターミナル施設配置、ターミナル内部エリアの範囲指定、道路/鉄道/歩行路、内部階表示が混在している。
- 内部階UIは現状[0,1,2] = 1F〜3Fのみ。施設の親建物選択・floorIndex配置はあるが、ビル単位の独立ワークスペースではない。
- PropertiesPanelは建物と内部エリアを同じ選択画面内で編集し、全体空港レイアウト上で作業する。Terminal-only modeとしてのフロア一覧・屋内ナビゲーション・動線編集専用UIは存在しない。
- 現行TerminalAreaは矩形エリアの集合で、同階の共有辺と上下移動設備で旅客経路を生成する。個別設備の配置/面積は表現するが、全館メッシュの集約能力プロファイルやフロア別ダイアグラムは別データ層が必要。
- 対外交通は駅/バス停等の存在・外部接続の検査が一部あるものの、全手段について交通施設→徒歩Portal→入口→各搭乗口、到着各ゲート→出口→交通施設の連続経路を一覧・可視化する専用UIはない。

## 2. 目的・対象範囲

- 空港全体マップからターミナルを選び、建物内部に専念して設計できる独立ワークスペースを追加する。
- B3〜4Fのフロア切替、建物外形、内部エリア、上下移動、駅/バスターミナル/ゲート/店舗/トイレ/処理施設の配置と接続を視覚的に編集する。
- 全体空港マップのエアサイド/ランドサイドとの接続ポータルを確認しながら、内部経路や能力を設定する。
- 自家用車・送迎・タクシー・バス・鉄道・徒歩の対外交通について、施設の外部接続と徒歩経路、ターミナル入口、各搭乗口/到着出口までの動線をまとめて確認・検証する。
- 1つのターミナル複合体内の複数棟・サテライト・高層連絡通路を一覧・俯瞰する。
- 直線・直交ポリゴンに加え、円弧を含む複合外形のターミナルを全体マップで設計し、その同じ形状を内部Workspaceの床面・壁面・配置可能領域へ引き継ぐ。
- 空港らしい旅客処理設備、移動設備、商業・サービス施設、航空会社向け施設をカタログから配置し、接続・能力・営業時間・利用条件を編集する。
- 設計結果を旅客動線、待ち時間、混雑、旅客満足度、航空会社満足度、施設収益・運営費の評価へ接続する。

### 非目標

- この計画だけで独立した詳細旅客シミュレーションエンジンを実装すること（5-19）。Workspaceは施設・動線の設計と診断UIを担い、旅客の移動/待ち/利用実績の計算は5-19の正本に委ねる。
- 施設ごとの能力計算式を独自に作ること。共通能力契約・工程別集計は5-21およびPhase 6 P0/P2を利用する。
- 旅客/航空会社満足度の最終スコアやゲームバランス値を本書だけで確定すること。指標の入力要素とUI表示を定義し、算式・重み・経営効果は関連計画でPO承認する。
- 3D建築CAD・BIM・構造解析・防災法令適合。
- 運航中に現在の空港全体レイアウトを破壊的に編集すること。

## 3. 設計方針

### 3.1 Workspaceの境界

- 空港全体マップの建設モードから、選択したターミナルまたは複合体の「内部設計」を開く専用画面/routeを追加する。
- Terminal Design Workspaceでは選択建物/complex、床階一覧（B3〜4F）、2D平面図、3D断面/プレビュー、設備・経路・区域・能力設定を表示する。
- 既存layout/history/actionsを利用し、Undo/Redo・保存/復元・dirty state・Escape・selectionを統一する。専用の別保存形式を安易に導入しない。
- 建物外形からはみ出す内部エリア、親施設の階数外、未接続ポータルをリアルタイムに可視化する。
- 動線監査パネルで交通手段×出発/到着×対象ゲート/出口の接続マトリクスを表示する。operational / underConstruction / unreachable / notConfiguredを区別し、noService / noCapacity / closedはサービス状態として別表示する。
- 選択したマトリクス行の実経路を階ごとにハイライトし、最初の切断Portal/辺、方向/階層/区域/Step-freeの不一致、経路上の最小能力を表示する。
- 建物外の滑走路・誘導路・道路をこの画面で直接編集しない。建物出口/駅ポータル/ゲート接続は空港全体図へ戻る参照・選択機能を持たせる。
- 外部接続の実体は空港全体図側で編集し、Workspaceではその接続状態・切断位置・必要な外部編集対象を表示する。

### 3.2 外形・曲線形状の設計UI（幾何モデルの正本は5-15）

- 空港全体マップで作成したターミナル外形をWorkspaceでも同一の形状として扱い、内部床・壁・設備の配置可能領域と一致させる。Workspace専用の別形状データや別占有判定を作らない。
- 外形編集は、既存の矩形/直交ポリゴンに加え、直線区間と円弧区間を組み合わせた複合輪郭を扱えるUIを用意する。円弧は少なくとも中心・半径・開始角・終了角、または端点と曲率を編集でき、時計/反時計回り、半径数値入力、ハンドル操作を提供する。
- 直線と円弧の接線接続、頂点/制御点の追加・削除・移動、辺の直線/円弧切替、複製・回転・移動を可能にする。複合輪郭の自己交差、ゼロ面積、重複点、極端に短い辺、建物/滑走路/道路/スポット等との干渉を編集時に診断する。
- 円弧を描画用の多数の直線へ変換した結果だけを保存しない。保存する幾何表現は5-15で定める正規データを利用し、描画・ピッキング・タイル占有・衝突検証では用途に応じた近似/分割を行う。
- 曲線外形とタイルグリッドの関係（タイル中心/面積交差の採用規則、境界接触、床面積の算出、建物内外判定）を5-15と共通化する。外形内でも床がない吹抜け/アトリウム/階段開口は別のvoid領域として表現し、建物外形と歩行可能床面を混同しない。
- 5-15の形状モデルが未対応の間は、UIだけで曲線外形を実装済みと扱わない。幾何モデル、保存互換、占有/衝突、2D/3D描画、E2Eが揃って初めてプレイ可能と判定する。

### 3.3 内部施設カタログと配置・運営設定

施設カタログはカテゴリ、検索、名称、説明、必要階/区域、設置条件、建設費、運営費、能力単位、接続要件を持つ。個々の値は共通Facility Lifecycle/Capability契約と既存施設定義を再利用し、未算出能力を推定値で埋めない。

| カテゴリ | 施設例 | 主な設定・ゲーム上の役割 |
|---|---|---|
| 旅客処理 | チェックインカウンター、セルフチェックイン、Bag Drop、保安検査レーン、優先/ファミリーレーン、出入国審査、自動化ゲート、税関、手荷物受取、搭乗ゲート、乗継保安 | レーン/台数、処理時間、対象旅客、営業時間、国内/国際・出発/到着区分、能力・待ち |
| 通路・移動 | 通路、コンコース、動く歩道、階段、エスカレーター、エレベーター、垂直動線、連絡橋 | 幅/長さ、方向、速度、輸送能力、稼働状態、Step-free可否、接続Portal |
| ターミナル内交通 | AGT駅、ホーム、乗降場、路線、車両/編成、折返し設備 | 駅位置、路線接続、定員、運転間隔、停車時間、運行時間、待ち、運営費、故障/閉鎖。初期は個々の車両位置を描かない集約運行でもよいが、駅間接続・定員・運転間隔・待ちを計算する |
| 商業・滞在 | ラウンジ、書店、免税店、売店、コンビニ、飲食店、カフェ、ホテル、休憩/仮眠、シャワー | 面積、席数/定員、価格帯、営業時間、対象旅客、サービス品質、売上・運営費 |
| 旅客サービス | トイレ、授乳室、キッズスペース、医療/救護、案内所、両替/ATM、手荷物預かり、祈祷/静養スペース | 利用可能区域、利用条件、処理能力、営業時間、清潔度/サービス品質、アクセシビリティ |
| 航空会社向け | 航空会社専用/共用ラウンジ、専用カウンター、優先保安、航空会社事務所、乗務員室、専用ゲート/搭乗導線 | 利用対象会社・契約、専用/共用枠、利用料、優先条件、対象便/旅客クラス |

- カタログ上の施設は、選択→配置プレビュー→費用/条件確認→建設確定→稼働準備→運用開始の状態遷移を持つ。配置しただけで能力・サービスを有効化しない。
- 施設ごとに配置可能階、必要床面積、向き/入口、接続先、区域制約、必要スタッフ/車両/電力/水/通信等を表示し、満たさない条件は理由付きで表示する。
- 施設の配置・移動・回転・複製・削除は既存Undo/Redo、保存/復元、建設費・運営費・資産管理と一貫させる。
- 動く歩道は歩行ネットワークの区間能力/所要時間を変える設備として扱い、単なる装飾物にしない。AGTは駅/ホーム/路線/運行供給を分け、徒歩経路・駅の接続が成立しない場合は利用可能と判定しない。
- ラウンジ/店舗/飲食等は、全旅客が必ず利用する必須工程にしない。旅客属性・利用資格・価格・営業時間・混雑・搭乗締切までの余裕に応じた選択的立寄りとして扱う。

### 3.4 旅客動線・満足度・航空会社評価への接続

- 出発旅客の基本動線は「外部交通→ターミナル入口→チェックイン/Bag Drop（必要な旅客）→保安/出入国（対象旅客）→任意の店舗/ラウンジ等→搭乗ゲート」。到着旅客は「到着ゲート→入国/税関（対象旅客）→手荷物受取（対象旅客）→出口→外部交通」とする。
- 商業/ラウンジ等は任意の寄り道としてグラフへ接続し、必須工程を迂回させない。乗継・国内/国際・保安区域・Step-free・旅客クラスの区域制約を維持する。
- 旅客選択は、旅客属性/航空券クラス/会員資格、価格、営業時間、待ち、混雑、移動距離、搭乗締切までの時間、施設の利用資格を考慮する。利用資格のないラウンジや閉店中の店舗を利用可能にしない。
- 旅客満足度の診断要素として、歩行時間/距離、待ち時間、混雑密度、移動快適性、処理品質、トイレ/清潔度、案内、アクセシビリティ、ラウンジ/商業サービスの利用可能性、搭乗期限内到達を表示できるようにする。
- 航空会社満足度の診断要素として、ゲート/カウンター配置、専用施設・ラウンジ利用、優先動線、乗継/MCT、搭乗遅延、手荷物品質、施設利用料、拡張余地を扱う。航空会社専用施設は利用契約・対象会社・利用条件と紐付け、契約外会社が利用できないようにする。
- 施設を増やすだけで満足度が必ず上がる設計にしない。接続されていない、営業時間外、利用資格外、容量不足、品質不足の施設は、該当する評価要素を改善したものとして数えない。
- 満足度の算式・重み・評価期間・航空会社の契約更新/就航判断への波及は、5-19/5-04/Phase 6 P2の責務とし、本書ではWorkspace上の入力・根拠・診断表示を定義する。指標が未算出なら未算出と表示する。

### 3.5 編集機能


- フロア選択、階複製、テンプレート、複数エリア選択、ドラッグ範囲、回転、移動、複製、削除、Undo/Redo。
- ゾーン（landside/departure/arrival/international/transfer等）と区域遷移ルールを色分け。
- 通路・上下移動設備・Door/Portalを線やグラフとして表示し、接続なし・建設完了待ち・通行可能を区別する。
- 店舗/レストラン/トイレ/チェックイン/保安検査/出入国審査/手荷物受取等の能力・サービス時間・営業時間・休止状態を設定できるようにする。
- meshモードではメッシュセルに能力、標準歩行時間、サービス種別、ゾーンなどを割当て可能にする。セル境界が建物外形・エリア形状を越えないようにする。
- 標準操作を阻害しないよう、内部設計画面でも小さい数値ラベル・検索・階層一覧・キーボード操作を用意する。

## 5. 互換性・リスク

- 画面状態と空港レイアウトの状態を混同しない。ズーム・選択階・フィルタはUI stateとし、配置/設備/能力だけをレイアウトデータに保存する。
- 保存形式を増やす前に、現在のProjectFile.layoutに含められるか確認する。内部設計で追加した値がformatVersion / layoutSchemaのどれに属するかを明確にする。
- 複雑形状と詳細表示はレンダリングコストが高い。320×320と多層の性能測定を必須にし、単に描画品質を下げることでテストを通さない。
- 既存の全体空港マップの操作を削除せず、Terminal Workspaceは別ビューとして追加する。

## 運営モード別の施設シミュレーション粒度（5-19連携案・2026-11-19）

- 店舗・飲食店・ラウンジ・待合室等は、設計Workspaceでは**個別施設**として配置・編集・選択し、施設ID、位置、階、カテゴリ、能力、営業状態、価格/品質等を保持する。
- Workspace自体は設計・編集画面とし、編集のたびに全旅客×全店舗のSimulationを常時計算しない。配置プレビュー/動線・能力の静的診断と、必要時に起動するTerminalDetail Simulationを分ける。
- ターミナル詳細運営/詳細Simulationでは、旅客が個々の店舗・飲食店・ラウンジを具体的な施設IDで選び、そこまでの経路、待ち、滞在、利用人数、売上を個別に扱う。旅客の内部表現は性能テストにより個人単位/重み付きbatchを選べるが、店舗ID別の利用実績は保持する。
- 空港運営モードでは、各施設の定義をカテゴリ×ターミナル/区域（必要時はメッシュ）へ集約し、「物販」「飲食」「ラウンジ」「待合」等の利用率・総能力・平均滞在・売上等を扱う。店舗ごとの立寄り先・経路探索・待ち行列は空港運営モードに持ち込まない。
- この粒度分離の詳細、集約変換、性能ベンチマークと判断ルールは [5-19 Terminal Simulation計画](../planned/terminal_simulation_modes_plan.md) の「運営モード別の施設シミュレーション粒度」を正本とする。5-18では店舗個別配置と編集のプレイ可能性、および5-19の両粒度で設定値が一致することを受入対象とする。
- 施設をカテゴリ集約するのは空港運営Simulationの実行時表現であり、レイアウト/セーブから個別店舗を消去・統合することではない。施設数・カテゴリ・位置・階・営業状態を変更したときに集約profileが再生成されることをテストする。

### 5-18側の受入条件追加

- Workspace上で同一カテゴリの店舗を複数配置し、個々に異なるID・位置・能力・営業時間・価格/品質を設定できる。
- 保存/再読込後も各施設の個別IDと設定が維持される。
- 同一layoutからAirportDay用のカテゴリ集約profileとTerminalDetail用の個別施設一覧を生成し、施設数・能力等の集計が一致する。
- Workspace編集操作自体がAirportDay/TerminalDetailのclock・state・seedを進めない。
- 店舗数を増やしたときの設計画面/配置操作の応答時間も5-19のSimulation性能とは分けて測定する。
