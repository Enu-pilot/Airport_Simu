## 1. 現状と課題

### 1.1 データモデルの確認（2026-11-22、main 4be176999c で確認）

- 座席数は**航空会社の保有機材側**で持つ。`src/core/data/airlines.ts` の各社 `fleet: { typeId, seats }[]` が正本で、機種カタログ（`src/core/aircraft/catalog.ts` の `AircraftModel`）側は型式の物理諸元（全長・翼幅・MTOW・最大定員 `maxPax`・代表座席数 `defaultSeats`）を持つ。検証（`src/core/data/validate.ts`）は typeId の実在と `1 <= seats <= maxPax` を担保する。
- 経済層はフリート項目を **typeId 単位で一意**とみなす箇所がある（`seatsFor` の先頭一致、`setFleetEntry` の同一 typeId 更新、`changeContractAircraft` の typeId 指定、契約は typeId のみ保持）。したがって同一 typeId を座席数違いで 2 行並べる表現は採れない。**仕様（国内線／国際線）はフリート項目の属性として持たせ、(typeId, spec) を一意キーに拡張する**のがモデルに合う形（§3.1）。
- シミュレーション側の機種表（`src/core/sim/aircraftTypes.ts`）はカタログから導出され、**セーブデータは機種表をスナップショットとして保持**する。カタログ変更は既存セーブの運航結果を変えない（新規の会社状態・提案から効く）。

### 1.2 個別の課題

- **IBEXエアラインズ（FW）**は会社カタログに存在するが、機材は汎用 `regional70`（70 席）で代替されている（airlines.ts のコメントにも「CRJ700 は機種表にない」と明記）。実機の **Bombardier CRJ700 が機種カタログに存在しない**。
- **JAL・ANA の座席数**は型式ごとに 1 値しか持てず、国内線仕様／国際線仕様の違い（例: ANA 787-8 は国内線 335 席・国際線 240 席）を表現できない。なお ANA 787-8 の現行値 244 席は両仕様のどちらとも一致しない（公式の現行仕様は国内線 335／国際線 240）。
- **天草エアライン（MZ）**は現行カタログで既に ATR42-600（48 席）のみで、A320 の紐付けは会社カタログ・機種カタログ・目的地・経済層・docs の全域を確認しても**存在しない**（§4 の精査表参照）。PO の認識との差異は残るが、データ上は実態どおりであり、本件は精査で「適合」を確認したものとして記録する。
- 機種の表示は全文（型式名・ICAO コード）が各表に散在し、略号のみで表示するモードがない。

## 2. 目的・対象範囲

### 目的
- IBEX の実機 CRJ700 を機種カタログへ追加し、FW の機材を実機へ差し替える。
- JAL・ANA について、国内線仕様と国際線仕様の両方を実際に運航する型式に、実在の座席数で仕様バリアントを追加し、「787-8（335席/国内線機材）」形式で表示できるようにする。
- カタログの全航空会社（実在会社）について保有機材の紐付けを実態と精査し、明らかな誤りを修正する。
- 機種表示に「略号のみ」モードを追加する（全文／略号の切替、表示のみの変更）。

### 非目標（PO の線引き）
- **国際／国内の使い分けに制限は入れない**。バリアントは機材の選択肢として増えるだけで、路線への割当制限チェックは追加しない。
- 片方の仕様しか運航していない型式に、存在しない仕様を無理に作らない。
- 架空会社（レガシー 8 社・架空都市系）は精査・修正の対象外（先頭 8 件は値・順序とも凍結の既存規約）。
- 判断が微妙なもの（過去に運航していた型式、グループ内移管、貨物改修等）は §3.3 の慣例に従い、理由を §8 に残す。

## 3. 設計方針

### 3.1 仕様バリアントの表現（CabinSpec）

- `fleet` 項目に任意の `spec?: 'domestic' | 'international'` を追加する（`AirlineInput` と会社状態の `FleetEntry` は同じ形）。
- 一意キーを (typeId, spec) に拡張する: `seatsFor(c, airlineId, typeId, types?, spec?)` は spec 指定時に一致する項目を引き、無指定時は従来どおり先頭一致（既存セーブ・既存契約の互換）。`setFleetEntry` / `removeFleetEntry` / `changeContractAircraft` も (typeId, spec) で対象を特定する。
- 提案生成はフリート項目（typeId + spec）単位で候補を選び、契約に `spec` を保持する。便計画（planning）の座席数は契約の spec で引くため、国内線仕様で契約した便は国内線仕様の座席数で飛ぶ。乱数消費の回数・順序は従来と同一に保つ（候補列の長さだけが変わる）。
- セーブ互換: `spec` は任意項目の追加のみ。旧セーブ（spec なし）は「仕様なし」として従来動作し、保存形式の版（SCHEMA_VERSION）は上げない。
- カタログ版は慣例どおり `CATALOG_VERSION` を `2026.11.3` → **`2026.11.4`** に上げる（データ変更の版。SIM_MODEL_VERSION は据え置き）。

### 3.2 バリアントの表記（全文モード）

- フリート項目の表示は `fleetEntryLabel`（`src/ui/aircraftLabel.ts` に集約）で行う: 仕様ありは「**787-8（335席/国内線機材）**」「**787-8（186席/国際線機材）**」、仕様なしは「737-800（165席）」。
- 型式の短縮名は id から導く（Boeing は先頭の B を落とす: B787-8 → 787-8、B767-300ER → 767-300ER。その他は id のまま: A350-1000、E190、ATR42-600、DHC8-Q400）。汎用機材（generic）は型式名で表示する。

### 3.3 フリート精査の判断慣例

- 基準は**現行フリート**（2026-11 時点で運航している型式・仕様）。先行事例（北海道エアシステムの Saab 340B は「2022 年に退役し機種表にもないため現行の ATR42-600 で代表」、オリエンタルエアブリッジの DHC-8-200 は機種表にないため Q400 に席数を入れて表現）と同じく、退役済み型式は現行型式で代表するか外す。
- ただし就航地（networkDestinations）に過去就航を含む既存慣例はネットワーク側の話であり、フリートには適用しない。
- 同一型式に複数の実仕様がある場合は、その会社の代表的な現行仕様 1 値を置く（国内線／国際線の両仕様がある大手 2 社のみ §3.1 のバリアントで併記する）。
- 発注済み・就航開始済みの型式は現行に含める（例: スカイマーク 737-8 は 2026-05-28 就航済みのため適合）。

### 3.4 略号コードの方針（2026-CODE）

- コードは Flightradar24 等で使われる機種略号（ICAO 機種コード系）を基にし、PO 指定の 2 例を固定する: **B787-8 → 788**、**A350-1000 → A35X**（ICAO の A35K から変更）。
- 体系: Boeing は先頭の B を落とす（B738 → 738、B77W → 77W、B78X → 78X）。Airbus は A を残す（A359、A20N、A21N）。貨物型は基コードに F を付す（B747-400F → 74F、B777F → 77F 等）。対応表は §7 に全型式分を残す。
- 切替は表示設定 `OpsPrefs.typeLabelMode: 'full' | 'code'`（localStorage 保存・プロジェクトには保存しない表示専用設定。既存の noMap 等と同じ流儀）。フォーマッタは `src/ui/aircraftLabel.ts` の 1 箇所に集約し、各表はそれを使う。
- コードモードのフリート項目は「788（内）」「A35X（際）」（仕様なしはコードのみ）。便・契約など仕様が伝播している箇所では契約の spec から（内）／（際）を付ける。

### 4.3 判断を保留・慣例に従ったケース

- NH 777-200ER（271 席）: かつての国際線仕様の値。現在は国内線転用が進むが、型式自体は現行運航中であり、値は実在した仕様のため残置（バリアント化はしない）。
- NH 777-300ER（250 席）・787-9 国際線（246 席）: 現行は新仕様（212 席・215 席等）への移行途中だが旧仕様機も運航中のため、代表値として残置。
- JL A350-900（369 席）: 国内線専用。391 席の国内線仕様も存在するが同仕様区分内の差異であり、国内線／国際線バリアントの対象外（単一値のまま）。
- JL 787-9（239 席）: 国際線専用（195／203／239 席の仕様が併存）。代表値 239 を残置。
- 外国会社: 一覧照合で明らかな誤り（未運航型式の紐付け・全機退役型式のみ等）は見つからなかった。ロシア 2 社（SU・S7）の日本路線は過去就航であり、就航地に過去就航を含む既存慣例どおり残置。個別の座席数の小差（同一型式の複数仕様のうち 1 値を採用しているもの）は代表値の範囲として残置。

## 5. CRJ700 の機種データと出典

IBEX 公式「使用機材について」（CRJ700）: 全長 32.51 m、全幅 23.2 m、全高 7.57 m、座席数 70 席、航続距離 2,794 km。IBEX は 2017 年に CRJ700 へ機材統一し、現在 9 機を全便 ANA とのコードシェアで運航（仙台拠点）。就航地は現行カタログの networkDestinations と整合するため変更しない。

カタログ登録値（`AircraftModel`）: id `CRJ700`、Bombardier / CRJ / 700、ICAO `CRJ7`。
- 全長 32.51 m・全幅 23.2 m・全高 7.57 m・代表座席 70 席: IBEX 公式（official）
- 最大離陸重量 34,019 kg（ER 型）・最大定員 78 席（Series 702 の上限）・貨物室容積 15.5 m³: Bombardier 公開諸元（Wikipedia 転載、MD-11F の前例と同種の出典扱い）

## 9. 互換性・リスク

- 会社カタログの変更は提案列（候補の型式・仕様と offerFleetWeight の型式数）を変えるため、運航ゴールデン／フィンガープリントへの影響を確認する。カタログ変更だけが原因の差は本指示の範囲として再採取し、内訳を §10 に記録する。それ以外の不一致は再採取しない。
- CRJ700 化で IBEX 便のゲーム内プロファイル（着陸ロール・ターンアラウンド・手荷物容量・MTOW 由来の料金）が regional70 から変わる。これもカタログ変更起因として扱う。

- 既存セーブの会社状態に spec は無いが、任意項目のため読み込み・継続に影響しない。
