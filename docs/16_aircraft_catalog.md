# 16. 機種カタログ（Phase 7、2026.11.0 で拡充）

実装: `src/core/aircraft/catalog.ts`（データ）、`src/core/sim/aircraftTypes.ts`（シミュレーション用の機種テーブル）、
`src/ui/CatalogPanel.tsx`（機種カタログ画面）。

## 方針

- 機種は安定した ID で管理し、派生型は別の機種とする（例: `B777-300` と `B777-300ER`、`B767-300` と `B767-300ER`、`A350-900` と `A350-1000`）。
- 実機データ（全長・翼幅・全高・最大離陸重量・最大座席数・標準座席数・貨物室容積・燃料容量）は値ごとに状態を持つ。
  - **official**: メーカーの公開資料で確認した値。出典（発行者・資料名・URL・参照日）と値の定義（どの表・どの列か）を付ける。
  - **game**: ゲーム用の設定値（汎用機材の寸法、性能・地上作業時間・運航費など）。
  - **unset**: 公開資料で確認できなかった値。推定・換算で埋めない（`null`）。
- 航空会社の実際の座席数（`company.fleets`）は機種の最大座席数とは別に持つ。座席数の上限は最大座席数（未設定なら既定座席数の 1.25 倍）。
- 旧形式の汎用機材（`regional70` / `narrow180` / `wide300`）は実在機種に対応付けず、汎用のまま残す。
- 収録データを変えたら `CATALOG_VERSION` を上げる。保存済みのプロジェクト・シナリオは保存時の機種データ（スナップショット）で動き、
  最新カタログへの切り替えは差分を確認してから明示的に行う（`catalogDiff`）。

## ゲームの区分（簡略化モデル）

- 翼幅からコード文字（A〜F、ICAO Annex 14 の翼幅区分を参考）を求め、実在機種は コード C 以下 = M、D・E = L、F = L ＋ コード F 対応施設が必要。
  したがって ATR・E-Jets・A321・737 は M、767・787・777・A350 は L、A380 は L（コード F）。翼幅が未設定の機種は安全側（L・コード F 扱い）。
- 性能（進入速度・必要滑走路長・誘導路速度）、折り返し時間、地上作業の人数・車両、貨物室の手荷物個数、運航費はすべてゲーム値。
  ターボプロップ機・リージョナルジェット用のテンプレート（`TURBOPROP` / `REGIONAL_JET`）を追加した。
- これらは実際の航空機の運用・空港設計に使える値ではない。

## 3D 表示との関係

機種ごとに `assetId`（`src/core/assets/registry.ts`）を持つ。3D の機体は手続き生成で、寸法はカタログの値をそのまま使う。
全高が未設定の機種は、3D 表示だけ全長の 25% を仮の高さとして使う（シミュレーションには使わない）。
2026.11.0 で `proc-wide-767`・`proc-regional-jet`・`proc-turboprop`（主翼は低翼で近似）のテンプレートを追加した。専用モデルはない。
