# 20. 3D 表示と 3D アセット（Phase 9）

実装: `src/render/three/Scene3D.ts`（シーン）、`src/render/three/aircraftMesh.ts`（機体の手続き生成）、
`src/render/View3D.tsx`（React 部品・性能表示）、`src/core/assets/registry.ts`（アセット登録簿・塗装）。

## 切り替え

- 上部バーの「3D表示へ / 2D表示へ」で切り替える（`EditorState.viewMode`）。
- シミュレーションのループ（`editor/simRunner.ts`）は描画と独立しているので、切り替えても止まらず、状態も初期化されない。
- 3D に切り替えたときは 2D の表示範囲の中心を見下ろす位置から始まる。視点はマウスで回転・移動・拡大（OrbitControls）。
- 運航中は機体をクリックすると選択できる（レイキャスト。2D と同じ選択状態を使う）。

## 何を描くか（論理データ → 3D）

| 対象 | 元データ | 表現 |
|---|---|---|
| 地面 | `layout.site.terrain` | 地形色のテクスチャ |
| 滑走路 | `runwayPolygon`（2D と同じ形） | 平面 |
| 誘導路・道路・鉄道 | ノード間のエッジ | 幅つきの帯（誘導路幅は S/M/L とコード F で変える。表示用の値） |
| スポット | `standDims` | 平面 |
| 施設 | `facilityDims`・種別 | 箱。高さは種別ごとの表示用の値（ターミナルは階数で増やす）。建設中・計画中は半透明 |
| 機体 | `sim.state.aircraft` の位置・方位（前ティックとの補間は 2D と同じ） | 手続き生成メッシュ（下記） |
| 作業車両 | `sim.state.units` | インスタンス描画の箱（1回の描画命令） |

- 位置はすべてシミュレーションの値を読む。3D 側で動きを計算しない。
- 高度はシミュレーションにないので、**表示専用の簡略式**: 進入中は滑走路端までの距離 × tan 3°（最大 900 m）、
  離陸滑走は浮揚速度を超えた分に比例、出発後は経過時間 × 10 m/s（最大 1,500 m）。
- 座標は 1 単位 = 1 m（1 タイル = 25 m）。

## 機体の手続き生成と LOD

- 寸法（全長・翼幅・全高）は機種カタログの値をそのまま使う。全高が未設定の機種（ATR など）は表示だけ全長の 25% で代用。
- 形の違い（胴体の太さ、垂直尾翼の比率、主翼の後退角、機首の形）はアセット登録簿のテンプレートで持つ。
  エンジン数（2 / 4）と 2 階建て（A380）はカタログの値を反映する。
- LOD 3 段階: high（〜900 m: 胴体・主翼・尾翼・エンジン・塗装の帯）/ medium（〜3,500 m: エンジン・帯を省略）/ low（箱 2 つ）。
- ジオメトリは（アセット × 機種 × 詳細度）ごと、マテリアルは色ごとに共有する。

## アセット登録簿（`ASSET_VERSION = 2026.11.0`）

各アセット: ID・表示名・版・寸法の出典（`catalog`）・原点（機体中心・接地面）・単位（1 m）・LOD・出典・ライセンス・
専用（dedicated）か・代替（fallback）か・形のテンプレート。

| アセット | 対象 | 区分 |
|---|---|---|
| generic-regional / generic-narrow / generic-wide | 旧形式の汎用機材 | 代替（汎用の形） |
| proc-narrow-boeing | 737-800 / -800W / 737-8 | 系統テンプレート |
| proc-narrow-airbus | A320ceo / neo、A321ceo / neo | 系統テンプレート |
| proc-wide-767 | 767-300 / -300ER | 系統テンプレート |
| proc-wide-777 | 777-200 / -200ER / -300 / -300ER | 系統テンプレート |
| proc-wide-787 | 787-8 / -9 / -10 | 系統テンプレート |
| proc-wide-a350 | A350-900 / -1000 | 系統テンプレート |
| proc-a380 | A380-800 | 系統テンプレート（2 階建て） |
| proc-regional-jet | E175 / E190 | 系統テンプレート |
| proc-turboprop | ATR 42-600 / 72-600 | 系統テンプレート（主翼は低翼で近似、プロペラは描かない） |

- **専用モデル（その機種のために作った精密モデル）は 0 件**。外部の 3D モデルファイルは使っていない（出典: SkyPort 内製の手続き生成）。
- 登録簿にない ID は `generic-narrow` で代替表示する。対応状況の一覧は機種カタログ画面の「3D 表示の対応状況」に出る。
- 塗装は架空の航空会社（SK / NP / RJ / AQ / HB）の配色のみ。実在の航空会社の塗装・ロゴは使わない。契約のない便は無地。

## 性能計測

画面左上に FPS・フレーム時間・描画命令数・三角形数・機体数・車両数・JS ヒープ（Chromium のみ）を表示し、
`window.__skyport3d` に同じ値を出す。E2E `tests/e2e/view3d.spec.ts` が値を読み、`test-results/perf-3d.json` に記録する。

計測例（2026-11-10、ヘッドレス Chromium、**ソフトウェア描画（SwiftShader）**、1600×900）:

| 条件 | FPS | フレーム時間 | 描画命令 | 三角形 | JS ヒープ |
|---|---|---|---|---|---|
| 建設モード（機体なし） | 38 | 26 ms | 54 | 約 300 | 48 MB |
| 運航中・機体 20〜25 機（遠景、LOD low） | 23〜25 | 40〜44 ms | 59〜76 | 約 400〜900 | 18〜82 MB |
| 運航中・機体 2 機を近景（LOD high） | 27 | 37 ms | 50 | 約 1,100 | 93 MB |

- ソフトウェア描画での値であり、GPU のある通常のブラウザでの値ではない（GPU 環境では未計測）。
- フレーム時間の多くは SwiftShader のラスタライズで、三角形数・描画命令数は小さい。
- 静的な施設は 1 施設 1 メッシュ（描画命令は施設数に比例）。大きな空港で問題になれば、施設の結合（マージ）が次の改善候補。
