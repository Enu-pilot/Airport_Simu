# 06. UI設計書

## 1. 原則

- UI はシミュレーション状態を **読み取り専用の表示モデル**（セレクタ経由）で参照し、変更はすべてコマンド送信で行う。
- 数値（収支・KPI・予測）はコアが計算し、UI は書式化（桁区切り・単位・色）のみを担当する。
- マップ表示（Canvas/WebGL）と HUD・パネル（DOM）を分離する。
- 状態は色だけでなくアイコン・パターンでも示す（色覚多様性対応）。

## 2. 画面一覧

| 画面 | 内容 |
|------|------|
| タイトル | 新規ゲーム / ロード / 設定 / クレジット |
| 新規ゲーム設定 | モード、マップ（初期版は1種）、初期資金、シード、イベントON/OFF |
| メイン画面 | マップ + HUD + ツールバー + パネル群（下図） |
| 設定 | 音量（後続）、UI拡大率、スクロール速度、オートセーブ間隔 |

### 2.1 現行のページ構成

上部の主ナビゲーションは **建設 / 経営 / 運行** とし、設定メニューは通常ページのタブ列から分離して必要時に開く。

| 領域 | 既存機能の配置 |
|---|---|
| 建設 | マップ編集、ツールボックス、施設一覧、プロパティ、配置チェック。運航中は読み取り専用で、構造変更は運航終了後 |
| 経営 | 運航計画と契約、空港能力、航空会社評価、アクセス、財務、分析と日次履歴、拡張、機種カタログ、配置チェック、シナリオ、プロジェクト/保存、目標 |
| 運行 | マップ、運航表、常設カード、アラート、ターミナル・地上支援・手荷物・イベント・障害の詳細 |
| 設定メニュー | 新規ゲーム/サンドボックス/空港、難易度・ルール、JSON保存/読み込み、保存データ管理への導線 |

ページ切替はゲーム・シミュレーション状態を更新しない。運航中に建設へ移動してもシミュレーションは継続し、編集部品の操作は無効になる。画面モードそのものを終了する「建設モードに戻る」とは別の操作。

## 4. マップビュー

### 4.1 操作

| 操作 | 動作 |
|------|------|
| 右ドラッグ / 中ドラッグ / WASD・矢印 | パン |
| ホイール / Q・E | ズーム（5段階、タイル 8px〜64px） |
| 左クリック | 選択（航空機・施設・旅客グループ・スポット） |
| 建設ツール中の左ドラッグ | 配置（ペイント系は塗り、矩形系は範囲、滑走路は始点→終点） |
| R | 回転（配置前） |
| Esc / 右クリック（ツール中） | ツール解除 |
| Space | 一時停止切替 |
| 1〜4 | 速度 1x/2x/4x/8x |
| Ctrl+Z | 建設の取り消し（一時停止中、後続） |

### 4.2 建設時のフィードバック

- ゴースト表示: 配置可能=緑、不可=赤＋理由ツールチップ（「水域には建設できません」「滑走路クリアランス内です」等）。
- 費用プレビュー: カーソル付近に合計建設費と工期。
- 接続プレビュー: 誘導路を引いている間、接続されるノードを点で表示。滑走路に接するとホールディングポイントのアイコンが出る。
- 配置確定後、検証警告があれば黄色の警告アイコンを該当箇所に表示。

### 4.3 描画レイヤー（下から）

1. 地形
2. ペイント系（エプロン → 誘導路 → 道路）、滑走路
3. 建物・スポット・ゲート
4. 動的オブジェクト（GSE車両 → 航空機 → 旅客ドット）
5. オーバーレイ（ヒートマップ・経路線・予約ハイライト）
6. 選択枠・ゴースト・警告アイコン

### 4.4 オーバーレイ

| オーバーレイ | 表示内容 |
|-------------|---------|
| 混雑 | 施設の待ち行列長をヒートマップ、誘導路の待機機体を赤点 |
| 経路 | 選択した航空機の予定経路と予約済みノード |
| スポット | スポットごとの区分・割り当て状況（ガントへのリンク） |
| 稼働率 | 施設ごとの稼働率（緑/黄/赤 + 数値ラベル） |
| デバッグ | エアサイドグラフ（ノード・有向エッジ・maxSize）、予約、状態名、ID（開発ビルド/設定で有効化） |

### 4.5 航空機の表示

- 区分ごとにサイズの異なるトップダウンシルエット。航空会社色の尾翼。
- 状態アイコン: 待機中（⏸）、遅延（⏱）、経路なし（⚠）。
- 補間: シミュレーションのティック間は描画側で線形補間（シミュレーション状態は変更しない）。

## 5. パネル

### 5.1 運航表（フライトボード）

- 到着/出発タブ。列: 便名・航空会社・機種・予定・予想・実績・スポット/ゲート・状態・遅延理由。
- 行クリックで機体を選択しマップをフォーカス。
- フィルタ: 遅延のみ / 航空会社 / 時間帯。

### 5.2 スポット割り当てガント

- 縦軸スポット、横軸時刻（24時間）。ブッキングを帯で表示、遅延は帯の延長を斜線で。
- ドラッグで割り当て変更（検証に失敗すると戻る）。（S優先度）

### 5.3 航空会社・契約

- 提案一覧: 航空会社、路線、機材、週便数、時間帯、割引要求、**推定効果**（日次旅客増、日次収入増、ピーク負荷の変化）。承認/拒否ボタン。
- 契約中一覧: 満足度メーター（数値+バー）、満了日、主な不満要因トップ3。

### 5.4 財務

- 当日・昨日・過去30日の収支（カテゴリ別積み上げ棒グラフ）。
- 料金設定（スライダー + 数値入力。基準料金比と予想される需要影響を表示）。
- 融資（S優先度）。

### 5.5 職員

- 施設種別ごとに配置人数と必要人数の目安（ピーク需要から算出）、日次人件費。

### 5.6 KPI ダッシュボード

- [05_economy_spec.md](05_economy_spec.md) §10 の KPI を数値タイル + 過去30日の折れ線で表示。

### 5.7 詳細パネル（選択対象）

| 対象 | 表示 |
|------|------|
| 航空機 | 便名・機種・状態と経過時間・現在の待機理由・ターンアラウンド作業の進捗（作業ごとのバー） |
| スポット | 区分・紐付けゲート・今日のブッキング一覧 |
| 処理施設 | 窓口数・配置人数・待ち人数・平均待ち時間・稼働率、職員増減ボタン |
| 滑走路 | 運用モード・使用方向・直近1時間の運用回数・進入キュー |
| 旅客グループ | 便・人数・段階・待ち時間・満足度 |

### 5.8 通知・イベントログ

- 重要度: 情報 / 注意 / 警告。警告（経路なし、デッドロック、スポット不足、破産接近）はトースト表示 + クリックで該当箇所へ移動。
- ログはフィルタ可能。

## 6. 開港前のガイド

- 開港条件（[02](02_game_spec.md) §6）をチェックリスト表示し、満たしていない項目をクリックすると該当ツールを選択する。

## 7. 技術的な実装方針（UI）

- HUD・パネルは React。マップは PixiJS のキャンバスを React コンポーネント内にマウントし、描画ループは React の再レンダリングと独立させる。
- UI の状態購読は、ティックごとではなく **最大10Hz** にスロットルしたスナップショット（表示モデル）で行い、React の再描画コストを抑える。
- UI文字列は `src/ui/i18n/ja.json` に集約する。

## 8. 運航モードの画面（Phase 12B-1 実装）

建設モードの画面（§3）は従来のまま。運航モードだけ `src/ui/operate/` の `OperateLayout` に切り替わる（表示のみの変更で、シミュレーション・経済・保存は変えない）。

```
上部バー（時計・資金・評価・「建設モードに戻る」） + 2 行目 OpsNav（tab-* のボタン列）
┌ 左列(260〜300px) ──┬ 中央 ─────────────────────────────┬ 右列(260〜320px) ┐
│ ops-controls         │ マップ（2D/3D）                    │ ターミナル        │
│ 本日の KPI           │   左上: アラート（最大 3 件）      │ 地上支援・手荷物  │
│ 滑走路               │   右上: 運航表（案内板風）         │ アクセス          │
│ 天候・障害           ├───────────────────────────────────┤ 航空会社の評価    │
│ 工事                 │ 下部: 選択中の機体/施設の詳細      │ イベント(新しい順)│
└────────────────────┴───────────────────────────────────┴──────────────────┘
```

- **常設カード**（`cards/*.tsx`、testid `card-<名前>`、見出しで詳細オーバーレイ、▾ で折りたたみ。開閉は localStorage）。重い集計（KPI・ターミナル・イベント・航空会社評価）は実時間 1 秒ごと。`table.board` は運航表だけが使う。
- **運航表**（`FidsOverlay`、`flight-board`・`table.board.fids-table`）: 暗い盤面・琥珀色の等幅文字（表示のみの演出）。すべて/出発/到着、完了を隠す、折りたたみ。「運航表（全列）」（`tab-flights`）で従来の全列に切り替え。行クリックで機体を選択。行の ⋯ から遅延 +15/+30 分・スポット変更・優先・機体へ移動（`disruptionActions` を呼ぶだけ）。
- **アラート**（`alerts.ts` の純関数 `deriveAlerts`、`AlertStack`）: 滑走路閉鎖・ダイバート・競合・資金不足は重大、障害・10 分超の待機・保安検査の待ち 20 分超・積み残し・設備停止は注意。同じ種類・対象はまとめて ×n。クリックで対象へ移動、修理・遅延・スポット変更・詳細の各ボタン、× で閉じる（保存しない）。
- **大きなオーバーレイ**（`DetailOverlay`）: 運航表以外の `tab-*`（ターミナル・地上支援・手荷物・運航計画・経営・天候・障害・分析・シナリオ・アクセス・拡張計画・機種カタログ・プロジェクト・イベント・配置チェック・航空会社）。中央・右列・下部を覆い、上部バーと左列（時計・倍率）は覆わない。× / Esc / 同じボタンで閉じる。中身は従来のパネル部品そのもの。
- **下部の詳細**（`OpsDetail`）: 機体を選ぶと `AircraftPanel`、施設を選ぶと `PropertiesPanel` を横に流して表示。何も選んでいなければ細い帯に畳む。
- **航空会社の評価**（`core/economy/airlineScore.ts` の `airlineScorecard`、読み取り専用）: 定時性・折り返し・スポット/ゲート・料金・枠・機材の対応・旅客体験を 良好/注意/不足/判定不可 と 0〜100 で示し、悪い順に最大 2 つを「足りないもの」として出す。既存の記録・運航計画の分析・料金・機材だけから導出し、満足度の計算には使わない。
- 幅 1400〜1920px: 列幅 260/260（〜1599）・280/300（1600）・300/320（1760〜）。運航表は 420px（〜1599、遅延・機種列を省略）/ 約 470px / 最大 620px。1400px 未満は右列を隠す（未対応の調整は docs/10 §N）。
- 既存の testid は同じ部品・同じ名前で到達できる（`tab-*` は OpsNav、`flight-board` は運航表、`aircraft-panel` は下部）。新しい testid: `card-*`、`today-kpi-*`、`fids-*`、`alert-*`、`detail-overlay`・`overlay-close`、`airline-score-<id>`・`airline-lacking-<id>`。

## 9. 1 日のループの画面（Phase 12B-2 実装）

運航 → 振り返り →（次の日の準備＝建設モード | 続ける）→ 運航、の流れを画面で見えるようにする。コア（`settleDay`・`stepSimulation`）は変えない。

```
build ─start-ops→ operate ─0:00 の締め（自動で一時停止）→ review ─review-next→ operate（夜間を早送りして翌朝から）
  ▲                 │  ▲ skip-day（ヘッドレス。進捗バー）└─ review-build → build（締め済み。空の日報なし）
  └──── stop-ops ───┘  └── 重大な障害で停止 / 中止 → 一時停止の運航
```

- **自動一時停止と振り返り**（上部バーの「⚙ 日の設定」の `pref-pause-at-close`、既定 ON、localStorage `skyport.opsPrefs.v1`）: 0:00 の締めを行った tick の直後で一時停止し、上部バーを残した全画面の `day-review` を出す。切ると止まらずに日をまたぎ、「前日の振り返り」（`open-review`）から見られる。上部バーの「建設モードに戻る」（`stop-ops`）は従来どおり（途中締め）。**締めの直後は締め済みなので、`review-build` と `stop-ops` は `settleDay` を呼ばず、日は 1 だけ進む**。
- **振り返りの内容**（`core/analytics/review.ts` の `buildDayReview`。純関数・既存データのみ）: 収入と費用の内訳（`review-revenue`・`review-cost`、営業利益・資金）、定時率と主な遅延理由（`review-otp`・`review-causes`）、旅客・満足度（`review-pax`）、障害と対応（`review-disruptions`。対応の回数は UI が数える）、前日比（`review-compare`。改善・悪化・変化なしを ▲▼＝で表示。向きはシナリオ比較と同じ）、航空会社の評価の変化（`review-airlines`。日の初めと締めの満足度＋足りないもの）、明日の見通し（`review-tomorrow`。便数＝`planDay`、計画の問題、翌日完成する工事、天候予報は 12B-3a まで「予報なし」）。ボタン: `review-next`（次の日へ）・`review-build`（建設モードへ）・`review-history`。
- **1 日スキップ**（上部バー `skip-day`。ボタン群は建設モードの上部バーの高さを変えないよう小さく並べる。建設モードからは運航を始めてすぐ進める）: 残りの 1 日を、時間予算 12ms ごと（`setTimeout(0)`、1 チャンク最大 2,000 tick）に `stepTicks` で進める。描画は止め、`skip-overlay` に進捗バー（`skip-progress`）と `skip-cancel`。中止または重大な障害（滑走路の閉鎖・整備、ダイバート。設定 `pref-skip-autostop`、既定 ON）で、その時刻の一時停止の運航に戻る。締めに着いたら振り返り（設定に関わらず表示）。
- **次の日へ**: 締めの直後なら夜間（次の到着機が現れる 10 分前まで）を同じ方法で早送りしてから、元の倍率で再開する。
- **履歴**（`open-history`・`history-overlay`、プロジェクトのパネルの `project-history`、振り返りの `review-history`）: 行 `history-row-<日>`（日・資金・評価・営業利益・サイズ）、`history-view-<日>`（その日の振り返りを読み取り専用で開く）、`history-restore-<日>`（確認あり。建設モードのみ。検証に失敗したら何も変えない）、`history-delete-<日>`。保存の仕組みは [21](21_save_format.md) §日ごとの履歴。
- 運航中の速度操作（Space・倍率）は、スキップ中・振り返り中は無効。新しい testid: `skip-day`・`open-review`・`open-history`・`pref-*`・`skip-*`・`day-review`・`review-*`・`history-*`。

## ゲームのモデルの UI（Phase 12B-3a Part B）

上部バーに難易度・空港の格・天候の段階、左列に目標カード、天候カードに段階・24 時間の帯・明日の予報、航空会社カードに不満と要望、振り返りに予報・不満・達成した目標。建設モードの「新しいゲーム（設定）」「ゲーム設定」で難易度・気候・ルールを選ぶ。詳細は [docs/30](30_game_models.md)。
