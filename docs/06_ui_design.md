# 06. UI設計書

## 1. 原則

- UI はシミュレーション状態を **読み取り専用の表示モデル**（セレクタ経由）で参照し、変更はすべてコマンド送信で行う。
- 数値（収支・KPI・予測）はコアが計算し、UI は書式化（桁区切り・単位・色）のみを担当する。
- マップ表示（Canvas/WebGL）と HUD・パネル（DOM）を分離する。
- 状態は色だけでなくアイコン・パターンでも示す（色覚多様性対応）。

### 4.1.1 キーボードショートカット（仕様）

キーボード操作の正本は本節とする（§4.1 のキー行と食い違う場合は本節が優先）。実装は `src/editor/input.ts`（状態変更）と `src/editor/shortcuts.ts`（純粋な対応表）に分かれ、対応は `tests/unit/keyboardShortcuts.test.ts` で固定している。2026-11-21 に PO 依頼で階・サイズの2系統を追加し、あわせて切り替え系の操作にも拡張した（[実装計画](implementation/active/keyboard_shortcuts_plan.md)）。

#### 一般原則

- **入力中は無効**: テキスト入力・セレクト等のフォーム要素（input / select / textarea / summary）にフォーカスがある間は、すべてのエディタ系ショートカットを発動しない（`src/ui/App.tsx` の配線で担保）。
- **Ctrl / Cmd 併用は対象外**: Ctrl 系は既存の Undo / Redo / 複製とブラウザ操作を優先し、単独キーだけがショートカットになる。
- **モード別の割当て**: 同じキーでも建設モードと運航モードで意味が変わることがある（数字キー: 建設 = 表示階、運航 = 時間倍率。P: 建設 = スポットツール、運航 = バスの人数）。各モードで使わないキーは発動しない。
- **管制官（ATC）モードでは無効**: ATC は専用のキー処理を持ち、経営側のショートカットは届かない。
- **フィードバック**: 階・サイズ・レイヤの変更はトーストで結果を表示する。ツール切替と階はツールボックス・階ボタンのハイライト、サイズは配置オプションのセレクト、レイヤはレイヤーポップオーバーのチェック（キー表示つき）に即時反映される。
- **保存への影響なし**: いずれも UI 状態（ツール・オプション・表示階・表示レイヤ）の切り替えであり、セーブデータとシミュレーション結果には影響しない。

#### 表示階（数字キー、建設モードのみ）

数字段に B3〜4F を連続配置する。階ボタンと同じ `setInteriorLevel` を使うため、地図階層・ターミナル内部の表示階・配置先の階（roadLevel）が同期し、内部表示も有効になる（PR #62 の相互同期と同じ経路）。

| キー | 階 | 地図階層 |
|------|-----|---------|
| 8 | B3F | −3 |
| 9 | B2F | −2 |
| 0 | B1F | −1 |
| 1 | 1F | 0 |
| 2 | 2F | +1 |
| 3 | 3F | +2 |
| 4 | 4F | +3 |

- 5〜7 は割り当てない（階ボタンの範囲 B3〜4F に対応するキーは上記で揃っている）。
- `A` キー: 表示階を「全レイヤ」にする（`setMapLevel('all')`。配置先の階は最後に選んだ階のまま維持される）。数字キーでいつでも特定の階へ戻れる。
- 運航モードの数字キーは従来どおり時間倍率（1〜5）であり、階の割当ては置かない。

#### サイズ（S / M / L / F、建設モードのみ）

現在のツールのサイズ段階をキーで切り替える。対象はツールボックスにサイズのセレクトが出るツールだけであり、対象外のツールではキーは素通りする。加えて、選択ツールで誘導路の区間を選択中の場合は、その区間を含む経路全体の幅を変更する（「選択中の誘導路への適用」参照）。

| ツール | 変わるオプション | 段階 |
|--------|----------------|------|
| 誘導路 | 誘導路幅（taxiWidth） | S / M / L / F（2026-CF で F 区分を追加。4段階なので各キーが 1 対 1 に対応する） |
| 駐機スポット | サイズ（standSize） | S / M / L |
| 滑走路 | 舗装幅（runwayWidth） | 30m / 45m / 60m（S / M / L 級に対応） |

**一般規則**（段階リストが昇順に n 個ある場合）: S は最小の段階、F は最大の段階、M / L はその間を 1/3・2/3 の位置で選ぶ（切り上げ）。

| 段階数 | S | M | L | F |
|--------|---|---|---|---|
| 2 | 1番目 | 2番目 | 2番目 | 2番目 |
| 3 | 1番目 | 2番目 | 3番目 | 3番目 |
| 4 | 1番目 | 2番目 | 3番目 | 4番目 |
| 5 | 1番目 | 3番目 | 4番目 | 5番目 |

- 現行の3段階では S/M/L が 1 対 1 に対応し、**F は最大段階（Full）の別名**になる（ゲーム内のサイズ区分は S/M/L の3段階で、ICAO の D/E/F は L に含まれる。機能C の sizeClassOf と同じ整理）。
- **例外（2026-CF）**: 誘導路幅は4段階（S/M/L/F）になり、F キーは別名ではなく **F 区分そのもの**（コード F 機が通れる最上位の幅）を選ぶ。スポット・滑走路は3段階のままで、F は従来どおり最大段階の別名。プロパティパネルの誘導路幅も4段階のセレクトになり、旧「コード F 対応」チェックボックスは廃止（スポットのコード F 対応は存続）。
- エプロンはドラッグ範囲で大きさが決まり段階を持たないため対象外。PBB の型式はサイズではないため対象外（将来の候補として計画書に記録）。

**選択中の誘導路への適用**（ツール選択中の「これから置く幅」と対になる動き）:

- 選択ツールで誘導路の区間を選んでいるときに S / M / L / F を押すと、その区間を含む**経路全体**の幅が変わる。誘導路以外を選んでいるとき・何も選んでいないときは従来どおり素通りする。
- 「経路」は、選んだ区間から両方向へ、接する区間がちょうど2本の地点だけを通過してたどれる範囲（分岐・合流＝3本以上と端点＝1本で止まる。次数は誘導路区間の中だけで数える）であり、1回で引いた経路が単位になる。算出は `taxiwayRouteEdges`（`src/core/layout/network.ts`）。
- 変更は編集操作 `setTaxiwayRouteWidth` による1回の原子的な操作（Undo 1回で戻る）で、変更後のトーストに対象区間数を出す。プロパティパネルの「この幅を経路全体（N区間）に適用」ボタン（経路が2区間以上のとき表示）も同じ操作。
- 変えるのは widthClass だけで、codeF には触らない（単一区間の変更と同じ。L から下げても codeF の保存値は残る）。

#### 見送った切り替え（理由つき）

- **建設 / 運航の開始・終了とページ（レンズ）切替**: 運航の開始・終了はトップバーの専用フロー（状態遷移と確認を伴う）で、ページ状態も `App.tsx` 側にあり、エディタのキー処理からは安全に呼べないため割り当てない。
- **モード切替以外の確認を伴う操作**（全施設の着工・完成、日を進める等）: 誤爆防止のためキーには置かない。

### 4.2 建設時のフィードバック

- ゴースト表示: 配置可能=緑、不可=赤＋理由ツールチップ（「水域には建設できません」「滑走路クリアランス内です」等）。
- 費用プレビュー: カーソル付近に合計建設費と工期。
- 接続プレビュー: 誘導路を引いている間、接続されるノードを点で表示。滑走路に接するとホールディングポイントのアイコンが出る。
- 配置確定後、検証警告があれば黄色の警告アイコンを該当箇所に表示。

1. 地形

## 5. パネル

### 5.1 運航表（フライトボード）

- 到着/出発タブ。列: 便名・航空会社・機種・予定・予想・実績・スポット/ゲート・状態・遅延理由。
- 行クリックで機体を選択しマップをフォーカス。
- フィルタ: 遅延のみ / 航空会社 / 時間帯。

### 5.2 スポット割り当てガント

- 縦軸スポット、横軸時刻（24時間）。ブッキングを帯で表示、遅延は帯の延長を斜線で。
- ドラッグで割り当て変更（検証に失敗すると戻る）。（S優先度）

### 5.3 航空会社・契約

- 提案一覧: 航空会社、路線、機材、週便数、時間帯、割引要求、**推定効果**（日次旅客増、日次収入増、ピーク負荷の変化）。承認/拒否ボタン。
- 契約中一覧: 満足度メーター（数値+バー）、満了日、主な不満要因トップ3。

### 5.4 財務

- 当日・昨日・過去30日の収支（カテゴリ別積み上げ棒グラフ）。
- 料金設定（スライダー + 数値入力。基準料金比と予想される需要影響を表示）。
- 融資（S優先度）。

### 5.5 職員

- 施設種別ごとに配置人数と必要人数の目安（ピーク需要から算出）、日次人件費。

### 5.6 KPI ダッシュボード

- [05_economy_spec.md](05_economy_spec.md) §10 の KPI を数値タイル + 過去30日の折れ線で表示。

### 5.7 詳細パネル（選択対象）

| 対象 | 表示 |
|------|------|
| 航空機 | 便名・機種・状態と経過時間・現在の待機理由・ターンアラウンド作業の進捗（作業ごとのバー） |
| スポット | 区分・紐付けゲート・今日のブッキング一覧 |
| 処理施設 | 窓口数・配置人数・待ち人数・平均待ち時間・稼働率、職員増減ボタン |
| 滑走路 | 運用モード・使用方向・直近1時間の運用回数・進入キュー |
| 旅客グループ | 便・人数・段階・待ち時間・満足度 |

### 5.8 通知・イベントログ

- 重要度: 情報 / 注意 / 警告。警告（経路なし、デッドロック、スポット不足、破産接近）はトースト表示 + クリックで該当箇所へ移動。
- ログはフィルタ可能。

## 7. 技術的な実装方針（UI）

## 9. 1 日のループの画面（Phase 12B-2 実装）

運航 → 振り返り →（次の日の準備＝建設モード | 続ける）→ 運航、の流れを画面で見えるようにする。コア（`settleDay`・`stepSimulation`）は変えない。

```
build ─start-ops→ operate ─0:00 の締め（自動で一時停止）→ review ─review-next→ operate（夜間を早送りして翌朝から）
  ▲                 │  ▲ skip-day（ヘッドレス。進捗バー）└─ review-build → build（締め済み。空の日報なし）
  └──── stop-ops ───┘  └── 重大な障害で停止 / 中止 → 一時停止の運航
```

- **自動一時停止と振り返り**（上部バーの「⚙ 日の設定」の `pref-pause-at-close`、既定 ON、localStorage `skyport.opsPrefs.v1`）: 0:00 の締めを行った tick の直後で一時停止し、上部バーを残した全画面の `day-review` を出す。切ると止まらずに日をまたぎ、「前日の振り返り」（`open-review`）から見られる。上部バーの「建設モードに戻る」（`stop-ops`）は従来どおり（途中締め）。**締めの直後は締め済みなので、`review-build` と `stop-ops` は `settleDay` を呼ばず、日は 1 だけ進む**。
- **振り返りの内容**（`core/analytics/review.ts` の `buildDayReview`。純関数・既存データのみ）: 収入と費用の内訳（`review-revenue`・`review-cost`、営業利益・資金）、定時率と主な遅延理由（`review-otp`・`review-causes`）、旅客・満足度（`review-pax`）、障害と対応（`review-disruptions`。対応の回数は UI が数える）、前日比（`review-compare`。改善・悪化・変化なしを ▲▼＝で表示。向きはシナリオ比較と同じ）、航空会社の評価の変化（`review-airlines`。日の初めと締めの満足度＋足りないもの）、明日の見通し（`review-tomorrow`。便数＝`planDay`、計画の問題、翌日完成する工事、天候予報は 12B-3a まで「予報なし」）。ボタン: `review-next`（次の日へ）・`review-build`（建設モードへ）・`review-history`。
- **1 日スキップ**（上部バー `skip-day`。ボタン群は建設モードの上部バーの高さを変えないよう小さく並べる。建設モードからは運航を始めてすぐ進める）: 残りの 1 日を、時間予算 12ms ごと（`setTimeout(0)`、1 チャンク最大 2,000 tick）に `stepTicks` で進める。描画は止め、`skip-overlay` に進捗バー（`skip-progress`）と `skip-cancel`。中止または重大な障害（滑走路の閉鎖・整備、ダイバート。設定 `pref-skip-autostop`、既定 ON）で、その時刻の一時停止の運航に戻る。締めに着いたら振り返り（設定に関わらず表示）。
- **次の日へ**: 締めの直後なら夜間（次の到着機が現れる 10 分前まで）を同じ方法で早送りしてから、元の倍率で再開する。
- **履歴**（`open-history`・`history-overlay`、プロジェクトのパネルの `project-history`、振り返りの `review-history`）: 行 `history-row-<日>`（日・資金・評価・営業利益・サイズ）、`history-view-<日>`（その日の振り返りを読み取り専用で開く）、`history-restore-<日>`（確認あり。建設モードのみ。検証に失敗したら何も変えない）、`history-delete-<日>`。保存の仕組みは [21](21_save_format.md) §日ごとの履歴。
- 運航中の速度操作（Space・倍率）は、スキップ中・振り返り中は無効。新しい testid: `skip-day`・`open-review`・`open-history`・`pref-*`・`skip-*`・`day-review`・`review-*`・`history-*`。

### 10.3 経営ボード

従来の経営ページ12セクション＋ハブ（HubPanel）の13セクションを、右シート（幅 min(1280px, 86%)、z-25）に移した。Esc／背景クリックで閉じ、開いていたセクションとスクロール位置は保持される。地図は背後に薄く残る。

- **解放前表示**: ハブ（格5）・based（格2）を含む6機能の解放状況を、未解放でも要件と不足分（数値）つきで常時表示する。
- **ハブ**: 接続ペアごとの乗継見込み表（到着路線×出発路線、人数、接続品質、平均接続時間。`planConnections` の再計算による見込み）、ハブ設定エディタ（最大接続時間、バンク窓の追加・編集・削除。保存は会社データの既存経路）。CapacityPanel の「乗継・ハブ」欄は乗継0人でも消えず、未解放／オフ／なしの状態を表示する。
- **based**: 拠点契約の条件（滞泊能力・整備・人員）の充足内訳、常駐機一覧、滞泊スポット使用状況、翌朝出発の準備状況（morningReadiness）、撤退カウントダウン（3日）を表示する。条件内訳は読み取り専用ヘルパー `basedConditionDetails` による（sim の判定と集合一致をテストで担保）。
- **能力ビュー（CapacityPanel）**: 階層切替（施設別＝既定／ターミナル別／分野別／空港全体。単位の異なる能力は合算しない）、店舗粒度のプロファイル／詳細節（§10.7）、capability の状態表示（§10.8）。

### 10.4 運航レンズ

- 運航ナビの詳細オーバーレイ群は **運航ボード**（z-20）に集約した。開いている間は左側の運航コントロールが覆われる（速度のキーボードショートカットは有効なまま）。
- 運航表（FIDS）は **併用（決定C）**: ドラッグ可能な浮動パネルは要約表示（便名・行先・時刻・状態などの要約列）のみとし、全列表示は運航ボード側（`FidsBoard`）に置く。浮動パネルのヘッダーのボタンから全列ボードへ遷移できる。表示の出し分けは表示側のみで、運航の計算には影響しない。
- ライブアラートは **出し分け（決定C）**: 地図上の AlertStack には重大（critical）だけを出し、注意（warning）は要対応インボックスのみに出す（重複表示なし）。対応ボタンは重大側（スタック）に維持し、スタックには「注意はインボックスに出しています」の案内を出す。インボックス側の運航アラートは `buildAttentionItems` の `ops` 由来（mid 帯）として統合される。

### 10.5 日報ドロワー（`shell/ReviewDrawer.tsx`）

日次振り返りと履歴を右ドロワー（幅 min(720px, 96%)、z-30）のタブに同居させた。モーダルではないので背後の地図が見え、操作もできる。締め直後のライブ振り返りだけは「次の日へ／建設に戻る」の選択が必須のため × では閉じない（従来の導線を維持）。

- 行から地図への連動: プロセスピーク、ポータル・連絡設備の利用実績、最大のボトルネック、障害、便の行、ハブの乗り遅れ行は、対応する施設・機体へ地図フォーカスする。
- **ハブの実績**: 接続成功率、乗り遅れの内訳（場所名つき、地図ジャンプ可）、ゲート間所要時間に加え、OD別の計画配分表 `hubOd`（人数・ペア数・魅力・接続品質・平均接続時間）を表示する。これは「締め時に記録された計画配分」であり、HubPanel の便ペア見込み（再計算）とは別物として明示する。
- **ポータル通過実績**（`portalUsage`）: 連絡設備（linkUsage）の実績とは別節で、ポータル別の入／出／合計を表示する。

### 10.6 ATC レンズ

`.app-shell` の中に ATC 専用ヘッダーを上部バーとして置き、58px の AtcRail（GROUND＋TOWER のキュー件数バッジ）、左に要求キュー、右インスペクタに選択詳細と評価、下部スロットに通信ログを配置する。中央は専用 SVG の RadarMap のまま差し替える（**決定A で確定**: 専用 RadarMap を正式とし、MapRenderer への統合はしない）。開始画面と保存一覧はボード表示。ATC コア（`src/core/atc`）と専用セーブ形式（skyport-atc-session）は変更していない。

### 10.7 店舗粒度セレクト（ターミナル sim モード）

TopBar の ⚙設定メニュー内 `ServiceGranularitySelect` で、店舗シミュレーションの粒度（詳細／集約）を切り替える。値は localStorage `skyport.serviceGranularity.v1` に保存され、運航開始時に `createSimulation` へ渡る。未設定時の既定は **集約**。設定は次回の運航開始から効き、再開した sim やシナリオ実行には適用されない（その旨を UI に注記）。CapacityPanel のプロファイル節は両モードで同じ指標を表示し、実績は `serviceAggregateUsage` から読む（ラウンジ実績は詳細モードでも表示される。追随実装 §10.11）。

| capability 状態 | CapacityPanel・PropertiesPanel・要対応 | 運航中の閉鎖→ `closed`、故障・障害対象→ `failed` を表示専用に導出（理論能力は保持し有効は0、推定では埋めない）。正本はバックエンドの `operationalStateReadings`（追随実装 §10.11）。`supplyShortage` は施設単位のデータ源が無いため未生成（ラベルと帯割当は生成待ち） |
| 3D フットプリント描画 | 3D ビュー（Scene3D） | footprint のリングを押し出し形状で建物化。footprint が無ければ従来の矩形にフォールバック |
| 就航範囲の表示 | 航空会社スコア表の詳細 | `networkDestinations` で制限された会社は許可目的地を列挙し「範囲外の路線は提案されません」と表示。無制限の会社はその旨を表示 |

### 10.9 決定事項（2026-11-20 ユーザ決定・実装済み）

当初「未決定事項」だった5件はすべて決定され、追随実装（§10.11）で反映した。

1. **FIDS の置き場所 = C（併用）**: 浮動パネルは要約表示のみ、全列表示は運航ボード（§10.4）。
2. **ライブアラートと受信箱の関係 = C（出し分け）**: 重大のみ地図スタック、注意は要対応インボックスのみ（§10.4）。
3. **ATC レーダーの描画 = A（専用 RadarMap）**: 暫定を正式化し、描画統合はしない（§10.6）。作業なし。
4. **3D ビュー = B（観賞用）**: 3D は観賞用とし、編集は 2D で行う。3D 内の操作は視点操作（と運航中の選択・追従）のみで、編集手段は足さない。切替ボタンのツールチップと 3D ビュー内の注記（`view3d-note`）に明記した。
5. **空港の設定の分割 = B（設定モーダルへ分離）**: 右インスペクタ（未選択時）の空港設定のうち、編集中の操作に直結する項目（走行方式・ブロックタイル数）と参照情報（滑走路番号の一覧・注意書き）はインスペクタに残し、低頻度項目（磁偏角・判定ルールセット・アクセスモデル）を設定モーダル（「詳細設定（低頻度の項目）」ボタンから開く）へ分離した。設定の保存先・反映経路（`updateLayoutSettings`）は従来どおり。

### 10.10 互換性

再設計は表示と操作の置き場所の変更であり、sim の計算・判定・乱数は変更していない。SIM_MODEL_VERSION は `skyport-sim-10.8`、PROJECT_FORMAT の最大読込版は 8（形式8はラウンジを含むセーブのみ）のまま。形式7のセーブは形式7のまま往復し、ラウンジを含むセーブは形式8で往復する。

### 10.11 バックエンド追随の表示（追随実装 第1〜3弾）

バックエンド側の実装（PR #52 等）に UI を追随させた表示追加。いずれも表示専用で、sim の計算・判定・保存形式は変えていない。

- **能力状態の正本一本化**: 運航中の能力状態はバックエンドの `operationalStateReadings` を正本とし、UI 側の導出は廃止した（合成は `composeCapabilityReadings`）。人員不足（`resourceShortage`）が要対応（mid 帯）と能力ビューに出る。
- **日報の新形式**: 日報ドロワーはピーク開始時刻（peakStartMin）を正本表示とし、新プロセス（化粧室・バス・アクセス）は「能力は算出しない（実績のみ）」と明示する。Door-to-Door に区間別待ち（stepWaits）の内訳を追加した。旧形式の日報は従来表示にフォールバックする。
- **ラウンジ実績**: 店舗粒度の両モードで `serviceAggregateUsage` から読み、詳細モードではラウンジ専用表を出す。満足度換算の係数は暫定で、航空会社の満足度・空港評価には未反映である旨を注記する。実績は運航中のみ（日報には入らない）。
- **貨物**: アクセスパネルに貨物トラックの時間帯別計画（CargoTruckHourly。計画ベースの推定と明記し、実績は日報が正本）を追加。日報に積替量（transshipmentM3 > 0 のときのみ）を表示する。
- **ハブの採用率**: 接続ペア表と日報の OD 表に、直行便競合を前提とする採用率（`hubChoiceShare` の表示側計算）の列を追加した。係数は暫定で、文言に数値は入れない。
- **需要の根拠（docs/46）**: 経営ボード「路線の需要と供給（今日）」の各行に根拠の展開行を追加し、行き先の解決済み値（利用圏人口・出発側の航空市場人口・航空依存度・必須需要/観光の指数・需要指数・距離と距離減衰）を表示する。K・α・β は `BALANCE.market` から動的に読み、需要モデルが暫定校正中である旨と過大推計がありうる旨を一般形で注記する。季節性は季節プロファイル名と「今日の季節・曜日係数」（`seasonalWeekdayFactor` の合成値）までを表示する。**月係数だけを分離する純関数は demand.ts に無いため、月別の内訳表示はしていない**（月係数 helper の追加はバックエンドへの依頼事項）。
- **UI 数値リテラルの動的化**: 混雑凡例の帯境界（`HEAT_BAND_*`）、難易度ヒント（`DIFFICULTY`）、都市タイプの人口（`CITY_PROFILE`）、アクセス集計モデルの車線容量（`BALANCE.accessModel.roadPerEntrance` ／ `ROAD_LANE_CAPACITY_PER_HOUR`）、夜間帯・締切（`CITY_NIGHT_CURFEW` / `NIGHT_OPS_*`）、乗継上限（`DEFAULT_MAX_CONNECT_MIN`）、イベント混雑時の倍率（`CITY_EVENT_CONGESTED`）は、core の正本から動的に読む。式説明の文言（KPI の式など）は core の値と矛盾しないことを確認済みで、core 側の式が変わるときは同時改訂が必要。
