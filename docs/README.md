## 文書の優先関係

1. **要求・受入条件**: PO が承認した要求と `docs/42`、個別要求の `docs/40`・`docs/41` を参照する。
2. **現行仕様**: 機能別仕様書と実装コード・テストを照合する。文書とコードが食い違う場合、どちらかを独断で正とせず、差分と影響を整理する。
3. **実装状態**: フェーズ全体は `docs/42`、タスク単位は `docs/implementation/`、監査時点の証拠は `docs/39` を参照する。
4. **履歴資料**: `docs/00〜10` や `docs/design/` に残る初期案・過去の監査・引継ぎ記録は、現行の要求・実装状態と異なる場合がある。日付・対象コミットを確認する。

### 機能別仕様

- **基本・運航・旅客・経営・アクセス**: `docs/11〜19`
- **3D・保存・幾何・滑走路・検証・移行**: `docs/20〜27`
- **リモートスポット・ゲームモデル・都市・航空会社ホーム・能力・多層交通・複数ターミナル・日次振り返り・ナビゲーション**: `docs/29〜37`

## 更新ルール

- 新機能・複数ファイル変更・データ／シミュレーション変更では、コーディング前に実装計画書を作成または更新します。
- 実装計画書は `planned/` → `active/` → `completed/` で管理します。詳細は [implementation/README.md](implementation/README.md) を参照してください。
- 仕様書には実装・検証で確認した挙動だけを書き、未実装は未実装として記録します。
