# 37. 経営画面・ナビゲーション構成仕様（2026-11-14）

## 1. 目的

建設、経営、運航の作業領域を分け、既存の機能パネルを目的別に再配置する。画面遷移はシミュレーションの進行状態と独立させる。

## 2. 上部ナビゲーション

トップレベルの主要ナビゲーションは次の3領域とする。

| 領域 | 責務 |
|---|---|
| 建設 | 空港レイアウト、施設配置、ネットワーク、検証、建設編集 |
| 経営 | 運航計画、契約・航空会社、空港能力、アクセス、財務、分析・履歴、拡張、保存・プロジェクト、目標 |
| 運行 | マップ、運航表、運航状態、常設カード、アラート、選択中の機体・施設の詳細 |

新規ゲーム、ゲームモード、難易度、ルール、JSON入出力、保存データ管理への入口はトップレベルから分離し「メニュー」に集約する。

## 3. 状態・遷移ルール

- トップレベルのページ切替は `editorStore.mode`（建設/運航のシミュレーションモード）を変更しない。
- 運航中に経営ページまたは建設ページへ移動してもシミュレーションは継続する。
- 運航中の建設ページは読み取り専用とし、施設・道路・接続など構造変更を禁止する。
- 構造編集を行うには運航を終了し、建設モードへ戻る。
- 建設と経営の相互移動を許可する。
- 運行ページには運航モードのマップ、便一覧、アラート、常設カードを維持する。

画面を切り替えただけで一時停止・再開・日次締め・便の再生成を行ってはならない。

## 4. 経営ページの機能群

経営ページは既存パネルを再利用し、少なくとも次の機能群へ到達できるようにする。

- 運航計画・需要
- 航空会社・契約
- 空港能力
- 空港アクセス
- 財務
- 分析・履歴
- 拡張計画・工事
- 配置・構造チェック
- 機種カタログ・適合性
- シナリオ比較
- 保存・プロジェクト
- 目標・空港評価

能力ダッシュボードの算式・閾値・未算出条件は [docs/33](33_capacity_dashboard.md) を正とする。画面の表示値を別ロジックで再計算しない。

### 4.1 契約と航空会社の分離（2026-11-20、PR #61）

- 経営画面では「契約」と「航空会社」を独立セクションに分離した。契約側に契約中の便・契約提案・終了分・拠点契約の条件を集約し、航空会社側に一覧・評価表・使用ターミナル指定を集約する。従来の `contracts` 丸ごと再描画による二重表示は廃止した。
- 契約中の便はテキスト検索（会社名・就航先名）と並び替え（終了日順・機材順を含む）に対応する。
- 使用ターミナルの指定（航空会社ごとに使うターミナルを限定する既存機能）の選択 UI には、ターミナル別のスポット数と保安検査の処理能力/使用率を表示する（2026-11-20、PR #63。集計は `terminalCapacitySummaries` を正とし、指定ターミナルのスポット飽和が契約受諾時の能力チェック（TERMINAL_RESTRICTED）で拒否理由になることもここから辿れる）。
- あわせて、運航中に実際には遷移・編集できないボタンは配置しないか、理由（title）付きでグレーアウトする監査・修正を行った（運航中の建設ボタンは「建設（閲覧）」に改名、左レールは 58px → 84px、経営のセクション帯は折返し表示）。

## 5. 空港能力の表示・判定

能力ダッシュボードは運航計画と計画分析を再利用する。仮想契約・増便チェックは会社状態を複製して試算し、現在のセーブ・運航・契約を変更しない。

- 使用率 80%以上: 注意。
- 使用率 100%超: 能力不足。
- 需要0: 使用率0%。
- 容量モデルがない: 「未算出」。ゼロ能力・無限能力として扱わない。
- 滑走路30回/時/本は計画用基準であり、実際の滑走路性能保証ではない。
- ターミナル能力はチェックインと保安検査のボトルネックをターミナル別に算出する。
- 誘導路・ゲート・プッシュバック・ランプバスなど時間レートがモデル化されていない設備は未算出とする。

- 「空港全体」の先頭に、離発着能力のカード（`capacity-overall`）と制約になっている要素の名前（`capacity-overall-limit`: 滑走路 / スポットの回転数 / 折り返し能力 / 未算出）を表示する。値と根拠は `AirportCapacitySnapshot.overall`（誘導路は未算出のため含めない）。
- 運航中は、閉鎖中の滑走路（`runwayConfig[*].mode === 'closed'`）とスポット（`closures.stands`）を `live` 引数で渡し、滑走路・スポットの数から除く（根拠に「運航中の閉鎖を反映」と出る）。建設・経営モードでは渡さない（計画上の値）。

詳細な式と対象施設は [docs/33](33_capacity_dashboard.md) を参照。

## 6. テスト要件

- 各領域の表示・パネル遷移。
- 経営ページ表示中も運航時刻・便状態が進行する。
- 運航中の建設ページが読み取り専用である。
- ページ切替だけではモード・一時停止状態・日付・旅客数が変化しない。
- 仮想契約チェック前後で会社・レイアウト・セーブが同一である。
- 未算出能力が数値の0や無限大として表示されない。
- 80%・100%の境界で注意/不足判定が正しい。
