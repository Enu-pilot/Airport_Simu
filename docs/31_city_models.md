# 31. 都市規模と空港需要（Phase 12B-3b、一部実装）

この文書はゲーム内の抽象モデルを定める。人口・所要時間・需要上限は実都市の予測や交通計画の基準値ではない。

## 実装範囲

- `CompanyState.city` があるときだけ都市需要・都市成長・都市距離によるアクセス時間を使う。設定がない既存セーブでは従来の `planDay` とアクセス手段選択を維持する。
- 新規ゲーム設定は地方都市を初期値にし、都市モデルを無効にすることもできる。既存会社の設定画面から有効化・無効化・都市タイプ変更ができる。
- 都市鉄道サービスの各停/快速/特急、騒音ポイント、住民満足度への影響、夜間運航制限は実装済み。都市側の鉄道投資とイベントは未実装。

## 保存データ

```ts
interface CityConfig {
  version: 1;
  type: 'regional' | 'core' | 'metropolitan';
  population: number;
  distanceKm: number;
  roadQuality: 1 | 2 | 3 | 4 | 5;
  railQuality: 0 | 1 | 2 | 3 | 4 | 5;
  residents: number; // 0〜100。騒音導入時に使う
}
```

初期プロファイル: 地方都市 = 30万人/25km/道路2/鉄道0、中核都市 = 120万人/18km/道路3/鉄道2、大都市 = 600万人/30km/道路4/鉄道4。住民満足度は70。

`city` のない旧データは変更しない。`city` のあるファイルは既存の `formatVersion: 2` に含める。`importCompany` は不正な `city` を捨て、`validateProject` は不正な保存を拒否する。

## 需要上限と運航計画

- 旅行率（人/日/人口）: 地方 0.004、中核 0.006、大都市 0.009。
- `accessFactorNorm = clamp((factor - 0.3) / 0.8, 0, 1)`。
- `ceiling = population × tripRate × exp(-max(0, distanceKm - 15) / 60) × (0.7 + 0.3 × accessFactorNorm)`。単位は出発＋到着の旅客/日。
- `expected = Σ(active contract perDay × aircraft seats × airline base load factor × 2)`。都市設定がある計画のみ、`cityFactor = min(1.1, ceiling / max(1, expected))` を既存のアクセス係数に乗じる。実スケジュール・計画プレビュー・明日の見通しは同じ `planDayWithDemand` を使う。
- 都市設定がない場合は `planDayWithDemand` が既存の `planDay` の結果をそのまま返す。

## アクセス時間

距離を `d` km とする。都市設定がある場合だけ外部所要時間を置き換える。

- 車・送迎・タクシー: `d / (20 + 8 × roadQuality) × 60` 分
- バス: 上記の1.3倍
- 鉄道駅ごとに各停/快速/特急を選ぶ。各停は品質1以上・45km/h、快速は品質2以上・65km/h、特急は品質3以上・90km/h。品質0では都市鉄道アクセスを利用できない。複数駅は列車本数で重み付けした平均速度・運賃加算を使う。

駅までの徒歩、列車頻度、容量、待ち時間、既存の接続判定は Phase 6 のアクセスモデルを維持する。快速の運営費は駅標準費の1.4倍、特急は2.2倍。特急運賃は旅客1人あたり500cr加算する。各停・快速は運賃加算なし。これらはゲーム内の仮定値。

## 日次人口成長

完全な日次締めでのみ更新し、途中停止の部分締めでは更新しない。

`population *= 1 + base[type] + 0.0005 × min(1, paxDay / (0.8 × ceiling)) × min(1, residents / 70)`

`base` は地方0.0002、中核0.0003、大都市0.0002。人口が初期人口の1.5倍・2倍を越えたとき、それぞれ都市道路品質を1段階上げ（上限5）、運航イベントログに通知する。鉄道品質は自動成長させず、将来の投資・マイルストーンで更新する。

## 騒音・夜間制限

- 騒音は実測dBではなく日次のゲーム内ポイント。1移動あたり `sizePoints(S/M/L=1/2/3) + engines × 0.5` とする。実際の着陸・離陸時刻と保存済み機種データを使い、騒音ポイントと夜間移動数を日報へ記録する。
- 夜間は22:00以上または06:00未満。都市設定がある便計画は営業時間を06:00〜22:00に制限し、遅延で夜間にかかった着陸は次の06:00まで待機する。離陸も滑走路上の予測時刻が夜間なら滑走路手前で待機する。
- 日次住民満足度の変化は `clamp(0.03 - noisePoints × 0.0004 - nightMovements × 0.15, -1, 0.05)`。0〜100に収め、成長計算へ反映する。すべてゲーム用の仮定値で、現実の騒音評価・法規制を表さない。

### 検証結果と拡張案（2026-11-16）

夜間制限の検証結果（再現した不具合 2 件、上空・滑走路手前での長時間の待機、遅延の指標に反映されない点）は [docs/39](39_comprehensive_test_audit_and_handover.md) §11.4 を参照。再現した 2 件はフェーズ 1 で修正済み。

- 夜間待機（`noiseCurfew`）で待った到着機は、待機の理由が別に変わった時点で待ち始めの時刻を取り直す。06:00 より前の夜間待機の時間は 45 分のダイバート条件（`HOLD_DIVERT_SEC`）に数えず、夜明けに複数機がダイバートすることはない（`setHold`）。
- 離陸の夜間判定に使う離陸滑走時間は、実際の加速の積分と同じ tick 単位で求める（`takeoffRollSec`）。予測と実際の離陸時刻が一致し、06:00:00 より前に離陸しない。離着陸時刻に加えて出発時刻にも制限を設け、最終便の遅れによる翌朝への持ち越しを抑える仕様案は [docs/40](40_departure_time_limit.md)（未実装）。
