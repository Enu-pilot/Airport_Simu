# 34. 多層交通・ターミナル間連絡設備（Phase U 部分実装）

## データとルール

- 道路グラフは `RoadNode.level` / `elevationM` で階層を持つ。階層範囲は -5〜10、0 が地上、負数が地下、正数が高架。旧データで欠落する値は地上として扱う。2D/3D 表示の高さ間隔は 6 m/階で、これはゲーム表示・経路計算用の規約であり、実測標高ではない。
- `RoadEdge.roadClass` は一般道路・構内道路・鉄道・歩行路・燃料管。階層差のある端点は種別に対応した明示コネクタを必要とする。一般道路/構内道路ランプは標高差 12:1 以上、鉄道ランプは 20:1 以上、エレベーター/階段/エスカレーター/配管立上りは平面距離 25 m 以内とする。これは初期ゲームルールで、道路設計基準の適合を表すものではない。
- 道路の `capacityPerHour` は利用者が入力した任意値で、欠落時は未算出。現行モデルで実際の車両・列車移動や道路容量の予約を行うのは未実装のため、設定値を稼働率・実需要として表示しない。
- ターミナル内 AreaLink と `GateConnector` は従来の責務を維持する。別ターミナル間の徒歩通路/動く歩道は `AirportLayout.terminalLinks` に独立保存し、接続エリア、距離、所要時間、方向、建設状態、旅客区域、任意能力を持つ。ターミナル内部グラフへ暗黙に混ぜない。
- `findTerminalTransferRoute` は既存のターミナル内エリアグラフと運用中リンクを組み合わせ、区域を越えるリンクを除外して経路・所要時間・連絡リンク能力を返す。旅客グループを作成・変更しない計画 API である。
- 施設は `mapLevel` で地図階層を、建物内部設備は `parentFacilityId` / `floorIndex` で親建物と内部階を保持する。旧セーブで階層がない施設は地上扱い。内部設備は親の範囲・階数を検証し、内部階ごとに別の占有空間を使う。
- ターミナル内エリアの階は、既定では地下 3 階（-3）から、ターミナルの階数（最大 4）− 1 まで（2026-11-18 拡張）。建物ごとにターミナルの任意項目 `floorRangeMin` / `floorRangeMax`（相対階）で上書きできる（機能G。欠落 = 既定のまま）。建物生成では最下階・最上階を絶対階で選び、基底階（mapLevel）= 絶対最下階、階数 = 最上階 − 最下階 + 1、`floorRange = [0, 階数 − 1]` として保存する（基底より下のエリアを持たない建物として表現する）。地下のエリアも地上と同じく、共有辺（同じ階）または平面が重なる上下移動エリア（隣の階）でつながる。ツールボックスの「ターミナル内部の階」は B3〜4F、エリアの「階」プロパティは地下 N 階〜N F を選べる。
- 配置衝突はタイルと物理的な高さ区間で判定する。内部設備の高さは階の間隔内に制限し、異なる階の同一平面位置を許容する。同じ階や実際に高さが交差する配置は従来どおり衝突扱いとする。

## シミュレーションへの接続状況

- 地下/高架レール駅が地上ターミナルへ到達するには、同階層の `walkway` エッジと、階層間の対応する歩行コネクタが必要。実経路がなければアクセス鉄道を利用可能と判定しない。所要時間はアクセス選択に反映する。通路容量が明示され、経路上すべての容量が既知の場合のみ、その最小値を駅からターミナルまでの接続能力として返す。
- 運用中燃料管の接続成分を給油施設からスポットまで探索する。到達スポットの給油作業は給油車を要求せず、既存給油作業時間の 0.6 倍となる。人員要件は既存ルールのまま。
- 通常の旅客需要は引き続き便の所属ターミナル内で生成する。スポット変更で出発ゲートのターミナルが変わった場合に限り、明示された旅客連絡設備を使って既存 `PaxGroup` を実際に歩かせる。生成数、発生時刻、予約人数、ID は変更しない。
- ターミナル内部の階段・エスカレーター・エレベーターは、重なる上下階エリア間の実旅客経路として動作する。上下移動設備とターミナル間リンクは時間帯別能力を有限の人数/時で予約し、能力超過グループを次の時間帯まで待機させる。上下移動設備の `capacityPerHour` は、旧データや未指定値に対して階段 1,800、エスカレーター 2,400、エレベーター 600 人/時を適用する。待ち行列の詳細な実績/KPI集計と到着・乗り継ぎ旅客への適用は未実装。
- `PaxGroup.stepFree` を持つ旅客は階段を経路候補から除外する。通常生成では seed とグループ ID から独立に決まる約 5% のグループへ属性を付与し、運航用乱数列を変えない。エレベーター等の段差のない経路がなければ到達不能になり得る。個人単位の属性・専用案内/KPI は未実装。
- 建物内の GSE・手荷物・燃料などの施設は配置と保存に対応するが、設備から地上サービス網への内部接続ネットワークは未実装。そのため親建物内に置いた設備は、接続モデルがない間は車両・人員・処理能力・燃料容量に加算しない。
- 個別道路車両と列車の位置・走行経路・占有・混雑・遅延は未実装。駅の列車頻度は既存の集約アクセスモデルの設定値で、車両運行を表さない。道路グラフの階層コネクタは駅アクセス経路の計画に使うが、旅客グループの階層移動には未接続。

## 編集・表示・費用

- 選択（V-3・V-4、フェーズ 1）: クリックでの選択は描画と同じ条件で絞る（`pickCandidatesAt`、`core/layout/pick.ts`）。内部表示がオンのときは、表示中の階の建物内設備 → その階のターミナルエリア → 通常の候補の順。道路のノード・辺と独立施設は表示中の階（`mapLevel`）のもの、滑走路・誘導路・スポットは常に候補。内部表示がオフのときは建物内設備を候補にせず、親のプロパティの「建物内の設備」一覧（`interior-children`）から選ぶ。重なった候補が 2 つ以上あるときは、プロパティの先頭の選択欄（`pick-candidates`）で切り替える（クリックの循環はドラッグの移動と衝突するので採らない）。
- 置けない階（V-5・V-6）: 配置に失敗したとき、エディタは理由を表示する（階が建物の範囲外 / 建物の範囲の外）。階の選択肢は残し、親の階数を超える階には「（この建物にはありません）」と注記する。コアの失敗コード（`INVALID_VALUE`）は変えず、理由は `core/layout/levelRules.ts` の純粋関数で導く。建物内設備の階は、プロパティの `prop-floorIndex` で後から変更できる。階数を減らすとき、範囲外の階にエリアや設備があれば変更前に理由を表示する。
- 表示（W-1・W-2・W-8）: 施設名ラベルは表示中の階の施設だけ。建物内設備は親の種類を問わず、内部表示の階（`floorIndex`）のものを 1 度だけ描く（`render/labels.ts`）。階層接続設備は、名前が空か内部名のとき和名（階段・エスカレーター・エレベーター・スロープ・鉄道の勾配区間・燃料管の立ち上がり）と番号で表示する。保存データの `name` は変えない。
- 階層接続設備の端点（V-2）: 接続設備と、同じノードを共有する道路の辺は、そのノードのタイルでは重なりとして報告しない（docs/26 §2）。
- 内部設備の接続警告（W-3、フェーズ 5 の 5-09 で確定）: 建物内の設備には接地（エプロン等への隣接）の警告を出さない（親の接し方で判定する）。建物内の GSE 基地・手荷物仕分け場・燃料施設・整備施設は、接続モデルがない間は能力に数えないことを情報レベルの検証項目（INTERIOR_FACILITY_UNLINKED）で知らせる。
- 地下に置ける種類（W-7、5-09 で確定、機能G で変更）: 単独施設を地下（mapLevel < 0）に置けるのは駐車場・従業員駐車場・鉄道駅・ターミナルとする（`UNDERGROUND_FACILITY_KINDS`）。ターミナルの追加は CDG 型の地下コンコース／サテライト再現のため（機能G）。配置と階の変更は operations で止め、既存データには検証の警告（FACILITY_UNDERGROUND_KIND）を出す。建物内の内部設備は対象外。地上階のエリアを持たず、他のターミナル複合体にも属さず、ランドサイド入口も無い地下ターミナルは、配置禁止ではなく検証の警告（TERMINAL_UNDERGROUND_ISOLATED）で到達不能を知らせる。地下の搭乗口はバスゲート扱いが原則で、ブリッジ有効時は警告（GATE_UNDERGROUND_BRIDGE）を出す。
- 全レイヤ表示中の配置先（W-11、5-09 で確定）: 「全レイヤ」は表示だけの切り替えとし、配置先の階は最後に選んだ単一階層のままにする。ツールボックスに配置先の階を表示する。
- 階層接続の候補（W-9、5-09）: 接続先ノードの候補には距離（m）を示し、選択中の設備の条件（近接・勾配）を満たさない候補は選べないようにする。ランプ類では勾配区間の長さと必要な倍率を表示する。接続設備の種別名は和名で表示する。

- 建設画面は現在階層の選択、道路種別・明示容量の作図、異階層ノードの明示接続に対応する。ターミナル内部エリアを選択すると、異なるターミナルの同じ旅客区域に徒歩通路または動く歩道を追加・撤去できる。施設配置では地図階層と建物内の親施設・階を指定できる。
- ターミナル間連絡設備の建設状態と旅客接続の3状態（接続済み／完成待ち／未接続）の確定仕様は docs/35 §7-9 を参照。キャリアモードで新設した連絡設備は建設中として建設プロジェクトに登録され、完成するまで旅客経路に入らない。
- 2D は選択階層の交通エッジを表示し、3D は選択階層以外の地形を透過表示する。3D は高架連絡通路と建物内設備を表示するが、内部設備は簡易マーカーであり、階層ごとの詳細な建物形状・混雑表示は未実装。
- 建設費はゲーム値: トンネル道路は地上道路の 10 倍、高架道路は 2 倍、燃料管 1,500 cr/タイル、通常歩行通路 4,500 cr/25 m、動く歩道 12,000 cr/25 m。既存の資産額連動維持費へ含める。
- 「空港能力」施設一覧は多層道路/通路・駅・ターミナル連絡設備を表示する。需要が記録されないものは使用率を未算出とする。

## 階層表示の統一（2026-11-20、PR #62）

- 地図階層（`mapLevel`: 地上 0・地下負数・高架正数）と建物内階（`interiorLevel`）は別状態だったため、外の地図で選んだ階と建物内の表示階が食い違い、初期値も内側だけ 1 ずれていた。表示階の相互同期（外で変えると内も同じ階になり、内の階ボタンを押すと外も連動する。「全レイヤ」表示のときだけ内側の階を保持する）に統一し、初期値は内外とも地上（0）に揃えた。
- 建物内の描画・クリック選択・配置判定は、親施設の階層を加えた実効階層で判定する。階ボタンは建設・運航で共通の B3〜4F とした。

## 保存互換性

`SCHEMA_VERSION = 3` を維持し、階層・標高・コネクタ・能力・連絡設備を任意項目として保存する。`terminalLinks` 欠落は空として扱う。読み込み時に範囲・列挙値・参照先・区域の整合性を検査する。通常旅客への段差なし需要割当と、能力より大きい旅客グループの複数時間帯にわたる通路利用を反映するため `SIM_MODEL_VERSION` は `skyport-sim-10.3`。10.2 以前の進行中シミュレーションは復元せず、レイアウト・会社・日報は保持する。新しい交通項目を含むプロジェクトは外側形式 v3 を使う。

## 次に必要な実装

1. 到着旅客・乗継旅客のターミナル間移動を、需要の生成・割当ルールを決めたうえで既存 ID・人数のまま実行する。**（フェーズ 4 で乗継旅客については実装済み**: 需要は契約の乗継率、割当は MCT と空席で決まり、連絡設備の利用人数は運航状態の `hubStats.byLink` に蓄積される。到着旅客の移動と、利用率の画面表示は未実装。仕様は [docs/44](44_hub_and_international.md) §4。）
2. 通路の実利用人数・待ち時間・閉鎖履歴をシミュレーションへ記録し、能力実績と日次分析へ渡す。
3. 道路車両/列車のエンティティ、経路、占有、停留所/ホーム処理を追加し、設定した道路・線路容量を実運行に結び付ける。
4. 建物階・上下移動施設・駅ホームの詳細な階層形状、コネクタ接続・設備能力による内部施設の運用可否、階層ごとの混雑描画を拡張する。
