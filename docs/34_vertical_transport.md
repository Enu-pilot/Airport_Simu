# 34. 多層交通・ターミナル間連絡設備（Phase U 部分実装）

## データとルール

- 道路グラフは `RoadNode.level` / `elevationM` で階層を持つ。階層範囲は -5〜10、0 が地上、負数が地下、正数が高架。旧データで欠落する値は地上として扱う。2D/3D 表示の高さ間隔は 6 m/階で、これはゲーム表示・経路計算用の規約であり、実測標高ではない。
- `RoadEdge.roadClass` は一般道路・構内道路・鉄道・歩行路・燃料管。階層差のある端点は種別に対応した明示コネクタを必要とする。一般道路/構内道路ランプは標高差 12:1 以上、鉄道ランプは 20:1 以上、エレベーター/階段/エスカレーター/配管立上りは平面距離 25 m 以内とする。これは初期ゲームルールで、道路設計基準の適合を表すものではない。
- 道路の `capacityPerHour` は利用者が入力した任意値で、欠落時は未算出。現行モデルで実際の車両・列車移動や道路容量の予約を行うのは未実装のため、設定値を稼働率・実需要として表示しない。
- ターミナル内 AreaLink と `GateConnector` は従来の責務を維持する。別ターミナル間の徒歩通路/動く歩道は `AirportLayout.terminalLinks` に独立保存し、接続エリア、距離、所要時間、方向、建設状態、旅客区域、任意能力を持つ。ターミナル内部グラフへ暗黙に混ぜない。
- `findTerminalTransferRoute` は既存のターミナル内エリアグラフと運用中リンクを組み合わせ、区域を越えるリンクを除外して経路・所要時間・連絡リンク能力を返す。旅客グループを作成・変更しない計画 API である。
- 施設は `mapLevel` で地図階層を、建物内部設備は `parentFacilityId` / `floorIndex` で親建物と内部階を保持する。旧セーブで階層がない施設は地上扱い。内部設備は親の範囲・階数を検証し、内部階ごとに別の占有空間を使う。
- 配置衝突はタイルと物理的な高さ区間で判定する。内部設備の高さは階の間隔内に制限し、異なる階の同一平面位置を許容する。同じ階や実際に高さが交差する配置は従来どおり衝突扱いとする。

## シミュレーションへの接続状況

- 地下/高架レール駅が地上ターミナルへ到達するには、同階層の `walkway` エッジと、階層間の対応する歩行コネクタが必要。実経路がなければアクセス鉄道を利用可能と判定しない。所要時間はアクセス選択に反映する。通路容量が明示され、経路上すべての容量が既知の場合のみ、その最小値を駅からターミナルまでの接続能力として返す。
- 運用中燃料管の接続成分を給油施設からスポットまで探索する。到達スポットの給油作業は給油車を要求せず、既存給油作業時間の 0.6 倍となる。人員要件は既存ルールのまま。
- 通常の旅客需要は引き続き便の所属ターミナル内で生成する。スポット変更で出発ゲートのターミナルが変わった場合に限り、明示された旅客連絡設備を使って既存 `PaxGroup` を実際に歩かせる。生成数、発生時刻、予約人数、ID、搭乗/降機/乗り遅れ判定は変更しない。
- ターミナル内部の階段・エスカレーター・エレベーターは、重なる上下階エリア間の実旅客経路として動作する。ターミナル間リンクの時間帯別能力を有限の人数/時で予約し、満員時は旅客グループを待機させる。待ち行列の詳細な実績/KPI集計と到着・乗り継ぎ旅客への適用は未実装。
- 建物内の GSE・手荷物・燃料などの施設は配置と保存に対応するが、設備から地上サービス網への内部接続ネットワークは未実装。そのため親建物内に置いた設備は、接続モデルがない間は車両・人員・処理能力・燃料容量に加算しない。
- 個別道路車両と列車の位置・走行経路・占有・混雑・遅延は未実装。駅の列車頻度は既存の集約アクセスモデルの設定値で、車両運行を表さない。道路グラフの階層コネクタは駅アクセス経路の計画に使うが、旅客グループの階層移動には未接続。

## 編集・表示・費用

- 建設画面は現在階層の選択、道路種別・明示容量の作図、異階層ノードの明示接続に対応する。ターミナル内部エリアを選択すると、異なるターミナルの同じ旅客区域に徒歩通路または動く歩道を追加・撤去できる。施設配置では地図階層と建物内の親施設・階を指定できる。
- 2D は選択階層の交通エッジを表示し、3D は選択階層以外の地形を透過表示する。3D は高架連絡通路と建物内設備を表示するが、内部設備は簡易マーカーであり、階層ごとの詳細な建物形状・混雑表示は未実装。
- 建設費はゲーム値: トンネル道路は地上道路の 10 倍、高架道路は 2 倍、燃料管 1,500 cr/タイル、通常歩行通路 4,500 cr/25 m、動く歩道 12,000 cr/25 m。既存の資産額連動維持費へ含める。
- 「空港能力」施設一覧は多層道路/通路・駅・ターミナル連絡設備を表示する。需要が記録されないものは使用率を未算出とする。

## 保存互換性

`SCHEMA_VERSION = 3` を維持し、階層・標高・コネクタ・能力・連絡設備を任意項目として保存する。`terminalLinks` 欠落は空として扱う。読み込み時に範囲・列挙値・参照先・区域の整合性を検査する。運航計算に差が出る地下スポット給油以外は既存の地上空港の挙動を変えず、`SIM_MODEL_VERSION` は変更しない。新しい交通項目を含むプロジェクトは外側形式 v3 を使う。

## 次に必要な実装

1. 到着旅客・乗継旅客のターミナル間移動を、需要の生成・割当ルールを決めたうえで既存 ID・人数のまま実行する。
2. 通路の実利用人数・待ち時間・閉鎖履歴をシミュレーションへ記録し、能力実績と日次分析へ渡す。
3. 道路車両/列車のエンティティ、経路、占有、停留所/ホーム処理を追加し、設定した道路・線路容量を実運行に結び付ける。
4. 建物階・上下移動施設・駅ホームの詳細な階層形状、コネクタ接続・設備能力による内部施設の運用可否、階層ごとの混雑描画を拡張する。
