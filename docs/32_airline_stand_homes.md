# 32. 航空会社別ホームスポットとリモートバスゲート接続

## 1. 運用上のホームスポット

航空会社ごとに、現在の運航日で使用したスポットをホーム候補として記録する。初回の割当では既存のスポット割当基準（計画スポット、機材適合、スポット寸法、コンタクト優先、ID順）を使い、割当が成功したスポットをホームに加える。

次便では、空き・機材適合・閉鎖・運航経路条件を満たすホーム候補を優先する。複数機が同時に到着し1つのホームが埋まっている場合は同社の別ホームを利用する。ホームが足りなければ近接性を優先しながら新しい候補を追加する。他社のホームは未所有スポットより後に評価するが、実際に使用可能か、他機に占有されていないか、機材と経路に適合するかの判定は既存の割当処理が必ず行う。

一時閉鎖・サイズ不適合・到達経路不足などで全ホームが利用できない場合は、適合する代替スポットを割り当て、その航空会社の優先リスト先頭へ追加する。これにより、元のスポットが再開しても同じ便群が頻繁に行き来しない。候補選定と代替理由は運航イベント（`standAssigned`、時刻・航空会社・機体・スポット・理由）へ記録する。理由は初回、既存ホーム、同時処理用の追加、ホーム利用不能による代替を区別する。

この一覧は優先順位だけを示す。機体を駐機させる排他予約の唯一の情報源は引き続き `state.standAssignments` であり、ホーム一覧が物理的な占有を作ることはない。

## 2. 日次リセット

`SimState.airlineStandHomes` は `{ day, byAirline }` の任意フィールド。day はシミュレーション秒から算出した日番号、`byAirline` は航空会社 ID からスポット ID 配列への対応である。日番号が変わると一覧を空にする。古い保存にフィールドがない場合は、ロード時に当日の空一覧を初期化する。保存形式 v2 の運航状態に含まれ、スポット ID の存在、一覧内重複、日番号を検証する。

航空会社がないテスト便や会社便には airline ID がない場合、ホーム記録を作らず従来のスポット優先を使う。

## 3. バスゲートの接続と選択

- リモートスポットは航空機の駐機位置、バスゲートは旅客のバス乗降位置、ターミナルはチェックイン・保安検査・待合・手荷物受取・出口の施設群。
- `remoteBoarding: 'bus'` と `busGateId` が明示されている場合は、そのゲートだけを使う。閉鎖・建設中・非バス方式・未接続・片方向のみのゲートから別ターミナルへフォールバックしない。
- 自動割当（`auto` または旧データ）は運用中かつ未閉鎖で、同一ターミナルに搭乗口と降機口の双方が接続するバスゲートから、スポットに最も近いゲートを選ぶ。距離が同じ場合はゲート ID 順。運用計画と運航で同じ選択器を使う。
- 旅客のターミナルは選択したバスゲートの所属ターミナルで決める。出発・到着とも同じスポット接続規則を使い、ゲートの端末接続変更は次の未生成旅客の割当から反映される。
- 同じバスゲートを複数リモートスポットが共有してよい。個別指定は混雑分散より優先される。バス車両・配車不足はゲート選択とは別の運用能力問題として扱う。

構造検証は指定先ゲートの存在・方式・建設状態・ターミナル・搭乗口・降機口、ランプバス、各ターミナル内の既存旅客経路検証を組み合わせる。運航時の閉鎖は実際の候補から除外し、利用不能時は便イベントの理由を記録する。設定画面には選択先ターミナル、出発/到着能力、運用状態、ランプバス数を表示する。

## 4. 保存・互換性

ホーム一覧はレイアウトには保存しない。現在の運航状態へ保存するため `formatVersion` 2 の対象とし、`airlineStandHomes` が欠落した旧運航状態は空で復元する。航空会社別スポット優先とバスゲート選択統一で同じレイアウトの運航結果が変わるため、`SIM_MODEL_VERSION` は `skyport-sim-10.1`。10.0 の進行中運航状態は既存の版方針に従って復元せず、プロジェクトのレイアウト・会社・日報を保ったまま建設モードで開く。

既存のスポット形状・`remoteBoarding`・`busGateId` は変更しない。セーブ済み空港に新しい構造移行は不要。
