- 関連: [31. 都市規模と空港需要](31_city_models.md)、[43. データ追加ガイド](43_data_extension_guide.md)、[Phase 6 実装計画](implementation/planned/phase6_airport_facility_expansion_plan.md)

## 1. 目的と決定事項

日本各地と羽田を結ぶ航空需要を再現するため、都市人口だけでなく、空港利用圏人口、鉄道競合を含む航空依存度、必須移動と観光の構成、季節性を都市別に与える。

この文書のPO指定は次のとおり。

1. **広域拠点性はパラメータ化しない。**
2. **競合空港の強さ・競合空港補正は設けない。**
3. **需給調整・座席供給による需要補正はこのモデルの対象外。** 潜在需要を算出するモデルとし、便数・座席数で潜在需要自体を縮めない。
4. **鉄道競合は独立変数にせず、航空依存度へ統合する。** 新幹線・特急・高速バス等が強い地域ほど航空依存度を下げる。海峡・山地・離島等で航空が有利/必要な地域は高くする。
5. **ビジネス需要と生活需要を「必須需要」に統合する。** 出張、通勤的な業務移動、行政、医療、教育、帰省・親族訪問などを同じ需要区分で扱う。ビジネス需要と生活需要の個別シェアは持たない。
6. 必須需要と観光需要の2区分を使用する。季節プロファイルは原則として観光側に適用し、必須需要は年間を通じて安定させる。
7. 仙台・首都圏・名古屋の航空需要校正では、羽田との実績だけを使わず、新千歳との路線旅客数を比較用代理指標とする。新千歳路線の数値を羽田路線の実績値と誤認しない。

### 対象外の変数

以下は追加しない。

- `regionalHubStrength` / 広域拠点性
- `airportCompetition` / 競合空港補正
- 座席供給・座席利用率による需要抑制や需給均衡係数

既存コードのアクセス交通能力や空港設備能力の計算を否定するものではない。ここでは都市間旅客の潜在需要パラメータの対象に含めない。

## 2. 調査データと読み方

### 2.1 航空旅客数

年次で路線を比較できる国土交通省・e-Statの2024年暦年データ（1〜12月）から、羽田主要路線の両方向旅客数を参照する。

| 路線 | 2024年暦年旅客数 | 用途 |
|---|---:|---|
| 羽田―新千歳 | 951.3万人 | 北海道の大規模航空需要の基準 |
| 羽田―福岡 | 891.3万人 | 大都市・ビジネス混合型の基準 |
| 羽田―那覇 | 663.6万人 | 観光・島嶼型の基準 |
| 羽田―大阪 | 492.3万人 | 新幹線競合を含む大都市路線の参考 |
| 羽田―鹿児島 | 246.4万人 | 地方中核・観光混合型の参考 |

これらは空港の全旅客数ではなく、**羽田との特定路線の旅客数（両方向合計）**である。空港利用者全体や地域住民だけの移動量とは異なる。路線旅客数には観光客・出張客・帰省客等が含まれる。

2025年度の国内定期航空輸送旅客数は全体1億1,250万人（前年度比3.4%増）であり、基準年以降も市場規模は変動している。都市別初期値の比較は、月別とそろう2024年暦年データを基本にし、2025年度値は市場全体の更新状況を確認する参考とする。

### 2.2 新千歳路線を代理指標にする都市

羽田との路線旅客数には新幹線競合による抑制が含まれるため、仙台・首都圏・名古屋の比較では、2024年暦年の新千歳路線を次のように使う。

| 対象都市・地域 | 代理に使う路線 | 2024年暦年旅客数 | 使い方 |
|---|---|---:|---|
| 仙台 | 仙台―新千歳 | 約87.7万人 | 仙台の航空移動市場を表す参考値 |
| 首都圏 | 羽田―新千歳 | 約951.3万人 | 首都圏の長距離航空市場の規模を表す参考値 |
| 名古屋圏 | 中部―新千歳 | 約136.4万人 | 名古屋圏の長距離航空市場の規模を表す参考値 |

**代替値の意味:** これらは「羽田―仙台」「羽田―名古屋」の実績旅客数ではない。新幹線に需要を奪われにくい長距離航空路線を使って、当該地域に存在する航空需要の規模を比較・校正するための代理指標である。首都圏の参照は羽田―新千歳そのもの、中部は中部―新千歳、仙台は仙台―新千歳を使う。

### 2.3 人口データの扱い

総務省統計局の2024年10月1日人口推計を、県単位・都市圏単位の基礎資料とする。例として、北海道504.3万人、宮城県224.8万人、青森県116.5万人、愛知県746.0万人、東京都1,417.8万人、大阪府875.7万人である。

ただし、都道府県人口をそのまま空港利用圏人口とはみなさない。空港の利用圏は県境を越える場合や、県内の一部にとどまる場合がある。以下の初期値は、都道府県人口または複数県の合算を錨にした**ゲーム用の推定値**であり、空港アクセス時間から厳密に積み上げた実測の商圏ではない。東京圏・名古屋圏・関西圏の値は、機能的都市圏の公式定義値ではなく、対象県の人口を基にした広域近似値である。空港間で利用圏が重なることがあり、これらの値を合計して日本の人口を求めてはならない。

## 3. パラメータ定義

| パラメータ | 単位・範囲 | 意味 |
|---|---|---|
| `catchmentPopulation` | 人、1,000以上 | 空港が主に旅客を集める地域の推定人口。現行 `population` とは別項目 |
| `aviationDependency` | 0.50〜1.00 | 航空依存度。新幹線・鉄道競合・道路移動の代替可能性を織り込んだ需要倍率。高いほど航空を利用する構造 |
| `demand.essential` | 0.1〜3.0 | 必須需要指数。従来の `demand.business` を移行元とし、ビジネス・生活上必要な移動を一つにまとめる |
| `demand.leisure` | 0.1〜3.0 | 観光・レジャー需要指数。既存値を初期値として引き継ぐ |
| `seasonalityProfile` | 列挙値 | 観光需要に適用する12か月の季節プロファイル |

### 3.1 現行データとの互換方針

現状の `DestinationInput.population` はゲーム内の都市規模値であり、実人口や空港利用圏人口とは異なる。これを `catchmentPopulation` と読み替えたり、一括上書きしたりしない。

現行コードは `demand.business` と `demand.leisure` を参照している。本仕様の実装時には、既存の `business` を必須需要の初期値として読み取る。移行期は `essential ?? business ?? 1` 相当の互換読み込みを行い、legacy ID・順序・旧セーブの挙動を保つ。カタログの先頭21件のID・順序・legacy属性は変更しない。

`essential` は「ビジネス需要のみに適用する係数」ではない。ビジネスと生活・必要移動を統合した需要区分の係数である。別の `businessShare`、`livingShare`、`essentialShare` は作らない。

### 3.2 需要式（設計案）

```
essentialLeisureIndex = 0.55 * essential + 0.45 * leisure

monthlyFactor =
  (0.55 * essential * essentialMonth[m]
   + 0.45 * leisure * leisureMonth[seasonalityProfile][m])
  / essentialLeisureIndex

routeDemand =
  K
  * (originPopulation / 1_000_000)^alpha
  * (catchmentPopulation / 1_000_000)^beta
  * essentialLeisureIndex
  * aviationDependency
  * distanceFactor
  * accessFactor
  * monthlyFactor
```

- 既存の `K`、`alpha`、`beta`、距離減衰、アクセス・評価・料金の式は、この調査だけを理由に変更しない。係数の再推定は別の検証タスクとする。
- `aviationDependency` は旅客構成比ではなく、航空需要の構造的な強さを表すゲーム用倍率。
- 需給調整、便数・座席数による潜在需要の切り下げ、供給不足による補正はこの式に含めない。
- `catchmentPopulation` を導入するまでは既存式の `dest.population` を使用し、この新式が実装済みであるかのように扱わない。

## 4. 季節性の実測例とプロファイル

### 4.1 2024年の主要路線・月別指数

国交省・e-Statの路線別月別輸送実績を基に、各路線の月間旅客数を平均月=100に正規化した観測例を示す。数値は月別の**路線全体旅客数**であり、必須需要と観光需要を分離した統計ではない。

| 羽田―神戸 | 89 | 90 | 100 | 97 | 105 | 101 | 103 | 104 | 104 | 107 | 100 | 100 |

読み取り:
- 新千歳は4月が低く、夏から秋（7〜10月）に強い。北海道の需要は夏だけでなく秋にも山がある。
- 福岡は年間変動が比較的小さいが、3月・10〜12月に強い月がある。
- 那覇は7〜8月および3月・10月に強い。夏休みだけの単峰型ではない。
- 八丈島は6月が弱く、7〜8月が強い。観光依存の高い小規模離島の季節変動例。
- 神戸は比較的安定し、大都市・ビジネス混合型の参考になる。

## 5. 国内就航先83件の初期パラメータ

### 5.1 数値の読み方

- 利用圏人口は「万人」表示。実装値は表示値 × 10,000 人とする。
- 必須需要指数は、現行 `demand.business` の値を初期値として転用する。意味を「ビジネス単独」から「ビジネス＋生活上必要な移動」に拡張する。
- 観光需要指数は現行 `demand.leisure` を初期値として維持する。
- 航空依存度は、鉄道競合を含めたゲーム用指数。実際に航空を使う住民割合や、鉄道競合率の実測値ではない。
- 根拠 A/B/C は人口値の根拠の確からしさを示す。航空依存度・需要指数も同じ確度で実測されたという意味ではない。

| 根拠 | 内容 |
|---|---|
| A | 2024年の都道府県人口を使用、または明記した複数県人口の合算で近似 |
| B | 県内の一部地域・複数市町村・空港利用圏を推定。人口の範囲が県全体と一致しないため、類似空港/地域の値も参照 |
| C | 架空の旧来都市。地理・都市規模・需要傾向が近い実在地域の値を流用したゲーム用設定 |

### 5.3 類似空港・地域からの流用ルール

| 都市・地域 | 流用元・考え方 |

| 架空都市 KTA / TWN / MSK / YKH / KRG / AOS / NSH / HSM | 実在する北海道・首都圏・沖縄・地方中核・新幹線沿線都市の人口規模/季節性を参照。実在統計ではなくゲーム用の類似設定（根拠C） |
| 札幌・旭川・釧路・帯広・女満別・稚内・中標津・紋別・利尻・函館 | 新千歳の広域需要・道東/道北の地域人口を基準に分割。月別は新千歳路線の傾向を基本とし、離島はISLANDへ |
| 仙台・青森・花巻・三沢・大館能代・山形・庄内・福島 | 仙台―新千歳の旅客数を東北側の航空需要の比較錨にし、東北各県人口・空港利用圏を分配。新幹線の強い都市ほど航空依存度を下げる |
| 東京・名古屋・大阪・神戸 | 東京は東京都・神奈川県・埼玉県・千葉県、名古屋は愛知県・岐阜県・三重県の人口を合算した広域近似。大阪・神戸は関西都市圏の概算（根拠B）。羽田―新千歳、中部―新千歳を代理指標とし、東海道新幹線競合を航空依存度に反映 |
| 広島・岡山・小松・新潟・富山・秋田・山形・静岡・茨城 | 新幹線/特急の競合がある地方都市グループ。羽田路線や近い都市の実績を参考にし、航空依存度を低〜中に設定 |
| 鹿児島・熊本・宮崎・大分・長崎・松山・高知・徳島・高松・山口宇部・鳥取・出雲・米子・石見 | 九州・四国・山陰の地方中核/地方路線の特性を流用。個別旅客実績を十分確認できない都市は、人口規模と類似地域の路線傾向を基に設定 |
| 那覇・石垣・宮古島・下地島・奄美 | 羽田―那覇/八丈島等の島嶼・観光路線の月別傾向を流用。島ごとの人口は小さくても観光需要指数を高める |
| 八丈島・南紀白浜・屋久島 | 羽田―八丈島の夏季集中をSUMMERの基準にする。八丈島の月別実績をそのまま他空港の実績値とはみなさない |

値の確度が低い空港は、数値を実績として固定せず、同系統の類似空港の初期値からスタートする。実装後の校正では、公式の空港別利用者数・路線別旅客数を確認できた都市から順次置き換える。

## 6. 空港類型と値の考え方

本仕様では空港を排他的なタイプに分けず、航空依存度と季節プロファイルの組み合わせで表現する。

| 類型 | 代表的な対象 | 航空依存度の目安 | 観光指数/季節性の考え方 |
|---|---|---:|---|
| 大都市・ビジネス混合 | 東京・大阪・名古屋・福岡・神戸 | 0.50〜0.93 | 必須需要を基礎に、観光変動は小〜中 |
| 新幹線競合 | 仙台・広島・岡山・小松・富山・新潟 | 0.55〜0.75 | 需要を消さず、航空依存度の倍率で抑える |
| 地方中核 | 鹿児島・熊本・長崎・松山・宮崎・高知 | 0.80〜0.93 | 必須需要と地域観光の混合 |
| 北海道広域・自然観光 | 新千歳・旭川・函館・道東各地 | 0.82〜0.99 | 夏〜秋、冬季観光はSNOWで補足 |
| 島嶼観光 | 那覇・石垣・宮古・奄美 | 0.98〜0.99 | 観光指数が高く、春・夏・秋に山 |
| 離島・生活路線 | 八丈島・隠岐・対馬・五島・沖縄離島 | 0.97〜0.99 | 必須需要は年間安定、観光は島ごとのプロファイル |

航空依存度は、例えば0.60なら「航空需要を60%にする」という意味ではなく、基本需要の相対補正である。モデル全体のKと人口弾力性と一緒に調整する。

## 7. 実装時の注意・受入条件

### 7.1 実装時に変更する対象

この文書作成時点ではコード変更していない。実装時に最低限確認する対象:

- `src/core/data/types.ts`: DestinationInput / DestinationDef に新パラメータを追加
- `src/core/data/destinations.ts`: 国内83都市の初期パラメータを登録。既存ID、順序、legacy属性を保持
- `src/core/data/index.ts` またはカタログ検証: 値域とseasonalityProfileの検証
- `src/core/economy/demand.ts`: 需要指数と月別プロファイルの計算
- `src/core/economy/balance.ts`: profile定義を置く場合の共通プロファイル管理
- 関連テスト: カタログ検証、legacy互換、月別係数の平均、都市別需要比較、既存会社・旧セーブ回帰

### 7.2 受入条件

1. 国内就航先の登録件数83件とID集合が変更前後で一致する。
2. 先頭21件のlegacy ID・順序・legacy指定は不変。
3. 旧 `demand.business` だけを持つカタログも必須需要として読み込める。
4. `catchmentPopulation` と `aviationDependency` の範囲外値、未定義の `seasonalityProfile` はカタログ検証で検出する。
5. 必須需要・観光需要の月別係数は、各プロファイルごとに年間平均が1.0になる。
6. 必須需要と観光需要を一度だけ合成し、季節係数・航空依存度を二重に掛けない。
7. 仙台・首都圏・名古屋は新千歳路線の代理指標を使ったことがデータコメントとDocsに残る。
8. 旅客需要の計算で、座席数・便数・座席利用率による潜在需要の上限調整を追加しない。
9. 新パラメータを導入するまでは現行シミュレーションは変更されない。SIM_MODEL_VERSIONや保存形式は、コード実装時に影響を確認し、必要な場合のみPO判断を得る。
